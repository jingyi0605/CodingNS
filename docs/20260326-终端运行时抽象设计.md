# 终端运行时抽象设计

## 【核心判断】

✅ 值得做：当前终端模型把 `process_id` 当成了“可恢复会话”的替身，这个数据结构从根上就是错的。  
真正需要持久化的是“运行时类型 + 会话句柄 + 附着目标”，不是某次 Host 进程内存里的 PTY 对象。

## 【关键洞察】

- 数据结构：终端实例不应该直接等于 PTY 进程；终端实例应该绑定一个可恢复的 runtime session。
- 复杂度：前端连接状态与终端运行状态必须彻底分离，否则“断开连接”和“终端结束”会永远混在一起。
- 风险点：如果继续依赖 Host 进程内存持有 PTY，Host 重启时终端一定丢；这和“后台常驻”需求天然冲突。

## 设计目标

1. 统一支持以下 runtime：
   - `tmux`
   - `conpty-powershell`
   - `conpty-cmd`
   - `conpty-git-bash`
2. Host 重启后可以恢复 `running` 终端的可见状态。
3. 前端断开只影响 attach，不影响后台会话。
4. 运行中终端与已关闭终端的语义清晰分离。
5. 允许未来新增其他 runtime，不改上层终端接口。

## 一、统一领域模型

### 1. 终端实例 `terminal_instances`

保留“用户视角下的终端标签”。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT | 终端实例 ID |
| `workspace_id` | TEXT | 工作区 ID |
| `name` | TEXT | 标签名 |
| `cwd` | TEXT | 初始工作目录 |
| `shell` | TEXT | 展示/兼容字段，保留 |
| `runtime_type` | TEXT | `tmux` / `conpty-powershell` / `conpty-cmd` / `conpty-git-bash` |
| `runtime_session_id` | TEXT | 运行时会话 ID，业务主键 |
| `attach_target` | TEXT | attach 目标，按 runtime 解释 |
| `status` | TEXT | `creating` / `running` / `closed` / `error` |
| `process_id` | INTEGER NULL | 辅助健康检查字段，不再作为恢复主键 |
| `status_detail` | TEXT NULL | 关闭或错误详情 |
| `created_by_user_id` | TEXT | 创建人 |
| `created_at` | TEXT | 创建时间 |
| `last_active_at` | TEXT | 最近活跃时间 |
| `closed_at` | TEXT NULL | 关闭时间 |
| `exit_code` | INTEGER NULL | 退出码 |

### 2. 运行时会话 `terminal_runtime_sessions`

保留“后台真实运行体”。

建议新增表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT | runtime session ID |
| `terminal_id` | TEXT | 所属终端实例 |
| `runtime_type` | TEXT | 运行时类型 |
| `session_key` | TEXT | 外部会话标识，例如 tmux session name 或 agent session key |
| `attach_target` | TEXT | attach 所需目标，例如 socket/sessionName/agent endpoint |
| `host_instance_id` | TEXT NULL | 当前托管该会话的 Host 实例 ID |
| `agent_pid` | INTEGER NULL | runtime agent 自身 PID，辅助诊断 |
| `shell_pid` | INTEGER NULL | 壳进程 PID，辅助诊断 |
| `state` | TEXT | `starting` / `running` / `lost` / `closed` / `error` |
| `last_heartbeat_at` | TEXT NULL | agent 心跳时间 |
| `last_checked_at` | TEXT NULL | 最近健康检查时间 |
| `last_error_detail` | TEXT NULL | 最近检查错误 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

### 3. 前端连接 `terminal_connections`

只描述“谁正在看这个终端”，不描述终端是否存活。

建议保留现有概念，但明确它不是运行时生命周期的来源。

## 二、runtime 抽象接口

Host 上层不要直接操作 `node-pty`，统一走适配器接口。

```ts
type TerminalRuntimeType =
  | "tmux"
  | "conpty-powershell"
  | "conpty-cmd"
  | "conpty-git-bash";

interface RuntimeSessionDescriptor {
  runtimeType: TerminalRuntimeType;
  sessionId: string;
  sessionKey: string;
  attachTarget: string;
  processId: number | null;
  metadata: Record<string, string>;
}

interface RuntimeHealth {
  alive: boolean;
  processId: number | null;
  detail: string | null;
}

interface TerminalRuntimeAdapter {
  readonly type: TerminalRuntimeType;

  createSession(input: {
    terminalId: string;
    workspaceId: string;
    cwd: string;
    env: Record<string, string>;
  }): Promise<RuntimeSessionDescriptor>;

  attach(input: {
    session: RuntimeSessionDescriptor;
    lastCursor: string | null;
    onOutput: (chunk: string) => void;
    onExit: (event: { exitCode: number | null; detail: string | null }) => void;
  }): Promise<{ detach(): Promise<void> }>;

  write(input: {
    session: RuntimeSessionDescriptor;
    content: string;
  }): Promise<void>;

  resize(input: {
    session: RuntimeSessionDescriptor;
    cols: number;
    rows: number;
  }): Promise<void>;

  inspect(input: {
    session: RuntimeSessionDescriptor;
  }): Promise<RuntimeHealth>;

  terminate(input: {
    session: RuntimeSessionDescriptor;
    reason: "user_closed" | "host_shutdown" | "delete";
  }): Promise<void>;
}
```

## 三、四种 runtime 的落地映射

### 1. `tmux`

- `session_key`：tmux session name
- `attach_target`：`tmux:<socketPath>:<sessionName>`
- `process_id`：可记录 tmux server pid 或 pane pid，辅助诊断
- `attach`：通过 `tmux attach` 或 `tmux pipe-pane/capture-pane` 配合桥接程序
- `inspect`：`tmux has-session`
- `terminate`：`tmux kill-session`

适用平台：

- macOS
- Linux

### 2. `conpty-powershell`

- `session_key`：agent 生成的 session key
- `attach_target`：`conpty-agent://<agentId>/<sessionKey>`
- `process_id`：PowerShell 主进程 PID
- `attach`：连接独立 session agent，再由 agent 把 ConPTY 流桥接给 Host
- `inspect`：agent 查询会话是否仍存活
- `terminate`：agent 杀掉 PowerShell 会话

### 3. `conpty-cmd`

与 `conpty-powershell` 相同，只是默认 shell 不同。

- 默认命令：`cmd.exe`

### 4. `conpty-git-bash`

与 `conpty-powershell` 相同，只是默认 shell 不同。

- 默认命令：`C:\Program Files\Git\bin\bash.exe --login -i`
- 不绑定 `git-bash.exe` / `mintty`
- 绑定的是 `bash.exe` 进程本身

## 四、状态机

### 1. 终端实例状态 `terminal_instances.status`

```text
creating -> running -> closed
creating -> error
running  -> error
running  -> closed
```

规则：

- `creating`：runtime session 已申请，尚未完成首轮健康确认
- `running`：runtime session 可 attach，可写入
- `closed`：用户主动结束，或 shell 正常退出
- `error`：session 丢失、agent 不可达、shell 异常退出、恢复失败

### 2. runtime session 状态 `terminal_runtime_sessions.state`

```text
starting -> running -> closed
starting -> error
running  -> lost
running  -> closed
running  -> error
lost     -> running
lost     -> error
```

规则：

- `starting`：刚创建，还没通过健康检查
- `running`：agent 或外部会话可访问
- `lost`：数据库说它该活着，但当前 Host 临时无法确认
- `closed`：确认已正常结束
- `error`：确认已异常丢失或无法恢复

### 3. 前端连接状态

前端连接状态单独存在：

```text
connected / reconnecting / disconnected
```

注意：

- 前端 `disconnected` 不得修改终端实例为 `closed`
- 前端 `disconnected` 只表示当前没有 attach

## 五、核心流程

### 1. 创建终端

1. 前端请求创建终端，指定 runtime type。
2. Host 选择对应 adapter 创建 runtime session。
3. 将 `runtime_type/runtime_session_id/session_key/attach_target` 写入数据库。
4. 首轮 `inspect` 成功后，将终端标记为 `running`。
5. 前端 attach 到该 session。

### 2. 前端断开

1. Host 仅移除当前连接订阅。
2. 不调用 `terminate`。
3. 终端实例仍保持 `running`。
4. 标签状态显示为“未连接但仍在运行”。

### 3. 用户关闭终端

1. Host 调用 adapter `terminate(reason="user_closed")`。
2. runtime session 状态更新为 `closed`。
3. terminal instance 状态更新为 `closed`。
4. 保留记录，供用户查看历史。

### 4. 用户删除终端

1. 如果仍在运行，先 `terminate(reason="delete")`。
2. 删除 `terminal_instances`。
3. 删除 `terminal_runtime_sessions`。
4. 删除缓存输出和前端恢复快照。

### 5. Host 重启恢复

1. Host 启动后扫描 `terminal_instances.status = running`。
2. 逐条加载其 `runtime_session_id/runtime_type/attach_target`。
3. 调用 adapter `inspect()`：
   - 如果 alive，保持 `running`
   - 如果临时不可达，先标记 `lost`
   - 如果确认已结束，标记 `error`
4. 前端后续点击标签时重新 attach。

### 6. Host 关闭

规则必须改：

- Host 关闭时不得默认结束所有终端 session。
- 只能关闭当前 Host 自己的 WebSocket 连接与内存订阅。
- 只有在“嵌入式 runtime 无法脱离 Host 存活”的旧模型下，才允许 kill。

## 六、恢复策略

### 1. `tmux`

- 通过 `tmux has-session` 判断会话是否还在
- 会话在：终端保持 `running`
- 会话不在：终端改为 `error`

### 2. `conpty-*`

- 通过独立 session agent 查询 session key
- session 在：保持 `running`
- agent 活着但 session 不在：标记 `error`
- agent 不可达：先 `lost`，经过重试窗口后再 `error`

## 七、错误归类

建议统一错误码：

- `RUNTIME_NOT_FOUND`
- `RUNTIME_ATTACH_FAILED`
- `RUNTIME_HEALTHCHECK_FAILED`
- `RUNTIME_SESSION_LOST`
- `RUNTIME_TERMINATE_FAILED`
- `RUNTIME_UNSUPPORTED_PLATFORM`

## 八、平台策略

### 1. macOS / Linux

默认 runtime：

- 优先 `tmux`

### 2. Windows

默认 runtime：

- `conpty-powershell`
- `conpty-cmd`
- `conpty-git-bash`

注意：

- `conpty-git-bash` 绑定的是 `bash.exe`
- 不绑定 `mintty` 外壳窗口

## 九、向后兼容迁移

### 第一阶段：补字段，不切行为

1. 给 `terminal_instances` 增加：
   - `runtime_type`
   - `runtime_session_id`
   - `attach_target`
2. 旧数据默认：
   - `runtime_type = embedded-pty`
3. Host 启动时如果看到 `embedded-pty + running`，直接标记为 `error`

### 第二阶段：引入 adapter

1. 保留旧 `embedded-pty` adapter
2. 新增 `tmux` adapter
3. 新增 `conpty-*` adapter
4. 创建逻辑全部走 adapter 工厂

### 第三阶段：去掉 Host 直接持有 PTY 的唯一实现

1. 仅把 `embedded-pty` 保留为开发兼容模式
2. 默认创建改为持久 runtime

## 十、推荐的最小可落地顺序

1. 先补数据库字段和领域模型
2. 抽 `TerminalRuntimeAdapter` 接口
3. 落 `tmux` adapter
4. 改 Host 启停逻辑，去掉 `dispose() -> closeAll()`
5. 落 Host 重启恢复扫描
6. 最后补 Windows 的 `conpty-*` session agent

## 【Linus式方案】

1. 先把“终端实例”和“运行时会话”拆开，这是第一性原理，不拆就全是补丁。
2. `process_id` 降级成辅助字段，别再让它承担会话恢复职责。
3. 前端连接状态独立建模，彻底切开“断开连接”和“终端结束”。
4. macOS/Linux 先上 `tmux`，把可恢复链路跑通。
5. Windows 再补 `ConPTY + agent`，但接口层不要再改。
