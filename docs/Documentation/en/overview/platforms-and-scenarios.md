# Platforms & Scenarios

## Supported client forms

These docs currently describe three main access styles:

- Desktop: best for long work sessions and dense project views
- Mobile: best for checking progress, handling quick actions, and light edits
- Browser: best for temporary access and device-independent entry

## Common usage scenarios

### A main development machine plus a phone

Keep the Host on your main machine, then use your phone to check session progress, approve actions, and inspect the project when away from the desk.

### An always-on machine plus outside access

If your projects stay on a home or office machine, CodingNS lets you keep using the same environment from outside the local network.

### Multiple machines for different work

You can keep separate Hosts for different machines and switch between them from one client experience.

## When CodingNS makes the most sense

- You work with AI coding tools regularly.
- You switch devices often.
- You want the project, conversation, Git state, and terminal access to stay connected.

## When you may not need it yet

If you only use one machine and rarely continue work remotely, local tools may already be enough. CodingNS becomes most useful once continuity across devices matters.
