# Workspaces & Sessions

In CodingNS, a workspace is not a side list item. It is the base unit for project browsing, conversations, files, Git, and terminal access.

## Most workspaces start in one of these ways

### Import an existing directory

If the project already exists on the Host machine, importing it is the fastest path.

### Clone from a repository

If the project is not on that machine yet, clone it and turn it into a workspace.

### Keep multiple projects separate

If you maintain several projects, store them as separate workspaces and switch by project.

## A session is not just a chat log

A session is the ongoing AI coding context tied to the workspace. The main idea is to continue useful context instead of restarting it.

## In day-to-day use, session flow usually looks like this

- continue an existing session when the task is still the same;
- start a new one when the goal changes;
- archive inactive sessions so the active list stays clear.

## The easiest cross-device rule is simple

Keep the workspace stable and avoid unnecessary new sessions. That makes desktop and mobile switching much easier.
