# 工作区与会话

## 为什么工作区是一切的入口

在 CodingNS 里，工作区不是一个可有可无的列表项，它是你查看项目、继续会话、打开文件、使用 Git 和终端的基础单位。

## 工作区常见来源

### 导入已有目录

如果你的项目已经在这台 Host 所在设备上，直接导入目录最省事。

### 从仓库克隆

如果项目还没放到这台设备上，可以从仓库地址直接克隆，再把它作为工作区接入。

### 管理多个项目

如果你同时维护多个项目，可以把每个项目作为独立工作区保存，后续再按项目切换。

## 会话是什么

会话是你和 AI 编程工具持续协作的一条上下文。它通常和某个工作区关联，因此你看到的消息、上下文文件、Git 变化和终端操作，会更容易保持一致。

## 日常使用中的会话流转

### 继续已有会话

如果你之前已经在这个工作区里工作过，优先继续原来的会话，避免重新解释项目背景。

### 创建新会话

当你准备开始一项新的开发任务、修复或实验时，可以在当前工作区里新开一条会话。

### 归档不再活跃的会话

当某条会话已经结束或暂时不需要关注时，可以把它从主列表中收起来，让当前工作区更干净。

## 多设备切换时怎么用

最简单的原则就是：工作区不变，会话尽量不断。这样你在桌面端和移动端之间来回切换时，理解成本最低。

## 新用户建议

- 一个工作区先只维护少量活跃会话。
- 不要把完全无关的项目混进同一个工作区。
- 想临时看状态时，优先继续已有会话，不要习惯性新开。
