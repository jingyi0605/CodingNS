# 核心能力

## 会话续接

CodingNS 的核心不是“重新开一个新聊天框”，而是尽量把你已经在原设备上进行中的 AI 编程会话带过来。这样你在桌面端、手机端和浏览器里看到的是同一条工作上下文。

## 工作区管理

工作区是所有操作的入口。你可以围绕工作区组织项目目录、会话、文件、Git、终端和辅助工具，避免在不同页面之间来回找项目状态。

## 对话工作台

对话页不仅用于发消息，还能承接常见的开发协作动作：

- 查看消息流和运行状态。
- 处理权限请求。
- 补充文件上下文。
- 跟踪排队中的消息。
- 在需要时从历史节点继续分叉。

## 工作区助手与办公能力

从 `v0.8.0` 开始，普通工作区会话不只是“看聊天”和“发下一句”。它们已经能走受控助手入口去调用一部分正式能力，比如：

- 文档相关入口
- 浏览器任务入口
- 当前工作区终端入口
- 部分运维和工作树入口

重点不是“什么都放开”，而是把该开放的能力正式开放，把不该越界的能力挡住。

## 浏览器任务与真实浏览器桥接

`office.browser` 现在有两条路：

- 默认还是平台自管的无头链路，适合稳定自动化
- 需要复用真实 Chrome / Edge 登录态时，可以显式切到桥接链路

这让“读 DOM、截图、点页面、提交表单、下载文件”这类任务不再只能靠一条死板路径处理。

## 文件、Git 与终端

这些能力都围绕当前工作区展开：

- 文件面板帮助你浏览、搜索、预览和编辑文件。
- Git 面板帮助你查看改动、提交、同步远端。
- 终端页帮助你打开和管理真实终端实例。

## 静态 HTML 演示编辑

如果你的项目里有演示稿式 HTML 文件，现在不只是“能打开看看”。它已经能直接进入演示视图，继续改文本、调布局，并尽量把导出结果和当前视图对齐。

## 多 Host 与多端访问

如果你不止有一台 Host，CodingNS 可以把它们区分开管理。你可以在不同 Host 之间切换，再进入对应的工作区继续工作。

## 远程访问

当你不在内网里时，可以通过 Tailscale 或 CodingNS Connect 继续连接 Host。两种方式适合不同的网络条件，官方文档会在远程访问部分单独说明。

## 账户偏好与设置

主题、语言、默认权限模式、部分模型选择、浏览器 Profile / 任务面板和更新入口都放在设置页里，方便你把日常偏好收口到同一个地方。

## 安装与运行时稳定性

这轮除了加功能，也补了不少容易影响实际使用的坑：

- Windows 安装链路更稳
- `codingns` npm 包运行时依赖发现更完整
- 工作区会话 runtime scope 更严格
- 文件树和刷新链路更不容易抖
