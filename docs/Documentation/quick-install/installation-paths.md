# 安装路径选择

想用 CodingNS，通常至少要准备两样东西：

- 一台运行 Host 的设备
- 一个用来连接它的客户端

Host 负责保管真实工作区、会话、文件、Git 和终端；客户端负责让你从不同设备继续进入它。

所以“安装 CodingNS”这件事，真正的第一步不是下命令，而是先决定：

- 你准备把 Host 放在哪台机器上
- 你想用哪种方式把它装起来

## 先从最像你现在情况的组合看起

### 组合一：一台开发机 + 桌面客户端

这是第一次上手最省心的方式。  
你可以先把 Host 装在平时写代码的电脑上，再直接用本机或另一台电脑连接它。

### 组合二：一台常驻机器 + 手机客户端

适合平时不一定坐在电脑前，但又想随时看进度、接着回复的人。  
你可以把 Host 放在家里或办公室那台经常在线的机器上，再用手机继续进入。

### 组合三：一台 Host + 浏览器访问

适合临时接入，或者当前不方便装客户端的时候。  
只要这台 Host 已经能被访问到，浏览器也可以先进入。

## 装 Host 这件事，其实只有两种思路

### 方式一：CURL 快速安装

适合这类情况：

- 你希望尽快装好
- 你不想记一堆命令
- 你更希望安装过程自动帮你把 `PM2` 和开机自启一起处理掉

这条路的特点是：

- 只需要先执行一条命令
- 后面跟着提示填端口、数据目录就行
- 脚本会自动处理依赖检查、npm 源切换、`PM2` 托管和开机启动

如果你现在的目标只是“今天先跑起来”，优先选这条。

### 方式二：手动 NPM + PM2 安装

适合这类情况：

- 你想自己确认每一步
- 你希望先手工启动看看，再决定要不要托管
- 你更习惯按自己的节奏装服务

这条路的特点是：

- 先用 `npm` 安装
- 先手工启动一次确认没问题
- 再决定是否交给 `PM2`
- 如果你在 Linux 上安装，先准备 `build-essential` 和 `python3`

如果你更希望逐步确认安装过程，可以选择这条方式。

## 选择建议

- 第一次安装：优先选 `CURL 快速安装`
- 准备长期放在常驻机器上：也可以直接选 `CURL 快速安装`
- 想慢慢确认每一步：选 `手动 NPM + PM2 安装`

## 开装前，机器上先准备好这些

开始前，先确认你准备运行 Host 的那台设备已经有：

- Node.js `22` 或更高版本
- npm `10` 或更高版本
- 如果你准备在 Linux 上手动安装，再提前装好 `build-essential` 和 `python3`
- 一个你之后愿意长期保留项目和数据的目录环境

如果你准备从外面访问这台 Host，后面还需要继续配置远程访问；不过第一次上手时，完全可以先在本机或同一局域网里跑通。
