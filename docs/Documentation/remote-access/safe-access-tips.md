# 安全与稳定建议

远程访问只是入口，不会替你解决 Host 自己没运行、项目目录不可用或客户端地址填错的问题。所以第一条原则很简单：先把本地使用跑通，再谈外部访问。

## 账号和设备，别图一时省事

- 给管理员账号设置足够稳妥的密码。
- 不在不受信任的公共设备上长期保存登录状态。
- 只有你真正需要的设备，才加入远程访问链路。

## 网络路线越简单，越不容易把自己绕进去

- 远程访问前，先确认当前 Host 所在设备网络稳定。
- 关键工作会话尽量在稳定网络下继续，移动网络更适合查看和轻量回复。
- 如果你有多种远程访问方式，先固定一条主路线，避免自己把入口搞乱。

## 真正长期使用时，顺手维护这些地方

- 定期关注客户端和服务更新。
- 长期不用的远程访问入口及时停用或解绑。
- 更换 Host 设备时，顺手更新对应的远程访问标识和说明。

## 最后记住这一条就够了

越是日常高频使用，越应该让路径更简单。对大多数人来说，最好的远程访问方案不是“功能最多”，而是“你下次打开还能立刻知道该连哪个地址”。
