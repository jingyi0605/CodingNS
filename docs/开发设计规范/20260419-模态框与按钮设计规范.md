# 20260419-模态框与按钮设计规范

这份规范只管两件事：

1. 模态框和移动端 sheet 应该怎么长
2. 模态框里的按钮和通用操作按钮应该怎么统一

如果你后续还在业务代码里手写 `portal + backdrop + card + footer`，那就是没按规范做。

## 1. 适用范围

下面这些改动必须先看这份文档：

- 新增桌面端模态框
- 新增移动端 sheet
- 修改已有模态框尺寸、结构、按钮样式
- 修改模态框里的列表、表单、记录块、空态、底部动作区
- 修改项目里的标准操作按钮基线

## 2. 壳层规则

### 2.1 桌面端

- 默认必须使用 `DesktopModal`
- 不允许直接手写 `workbench-modal-layer`
- 不允许自己再拼一套 backdrop、header、body、footer

### 2.2 移动端

- 默认必须使用 `MobileSheet`
- 不允许直接手写 `ios-action-sheet-overlay`
- 不允许自己再造“看起来差不多”的移动弹层壳

## 3. 尺寸规则

### 3.1 桌面端宽度

- 标准桌面模态框统一按“约 60% 浏览器宽度，低分辨率自动放大占比”处理
- `narrow / compact / regular / wide / xwide` 现在保留语义名，但不再鼓励各自再长出不同皮肤
- `full` 只留给查看器、大型 diff、重内容工作面板

### 3.2 移动端高度

- 只能从 `auto / half / three-quarter / full` 里选
- 不允许写这次先临时 `72vh`
- 如果现有高度档位不够，先补基础件，再改业务

## 4. 内容结构规则

- 字段区优先用 `ModalField`
- 分组区优先用 `ModalSection`
- 动作区优先用 `ModalActions`
- 列表区优先用 `ModalList / ModalListItem`
- 空态优先用 `ModalEmptyState`
- 标签优先用 `ModalTag`

一句人话：
先复用现有结构原子，别每个弹窗自己调 padding、gap、圆角和说明区。

## 5. 视觉规则

### 5.1 模态框内部信息块

- 记录信息优先平铺
- 分类和记录之间优先用细分割线
- 不要默认再叠白底卡片
- 只有 diff、图片预览、媒体内容、强交互编辑器这种内容，才允许保留专用内容容器

### 5.2 按钮统一规则

- 模态框按钮必须与设置页按钮保持同一套风格
- 模态框不允许再有“专用按钮皮肤”
- 普通按钮统一使用浅底、细边框、轻 hover 强调
- 危险按钮统一使用浅红底、浅红边框、红色文字

### 5.3 按钮语义规则

- `primary-button` 表示当前主动作
- `secondary-button` 表示次要动作
- `ghost-button` 只在确实需要弱化时用，但视觉仍要走同一套基线
- `workbench-danger-button` 和 `settings-button-danger` 都属于同一类危险语义，不允许分叉成两套长相

## 6. 什么时候允许特例

只有下面这些情况可以偏离：

1. 文件查看器、图片预览、diff 预览这类重内容弹层
2. 业务必须保留旧 DOM，否则会直接破坏现有交互或测试
3. 第三方组件强绑定 DOM 结构，暂时拆不掉

但就算允许特例，也只能偏离内容结构，不能偏离壳层和按钮基线。

## 7. 开发流程规则

新增或修改弹窗时，按这个顺序做：

1. 先选 `DesktopModal` 或 `MobileSheet`
2. 再选尺寸/高度档位
3. 再用 `ModalAtoms` 拼内容结构
4. 最后才补业务特例样式

不允许反过来：

1. 先写业务 DOM
2. 再用一堆 class 把它修成像弹窗
3. 最后说“以后再收口”

这种路线最后一定变垃圾。

## 8. 提交前自查

至少检查这几项：

1. 有没有新增手写 modal / sheet 壳层
2. 有没有继续给模态框单独发明按钮皮肤
3. 有没有把模态框内容做成一层套一层白底卡片
4. 有没有写临时宽度、高度而不是走档位
5. 有没有把例外原因写清楚

这五条里只要有一条不成立，就说明这次改动还没收口。
