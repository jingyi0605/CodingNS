# 助手命令矩阵与 Skill 自动同步说明

## 1. 这份文档管什么

这份文档只回答三件事：

1. `codingns assistant` 现在到底开放了哪些正式能力
2. 每条命令怎么写，参数怎么传
3. `codingns-assistant` 这个内置 Skill 现在怎么自动同步到 Codex

如果你只想快速看当前命令树，直接跑：

```bash
codingns assistant --help
codingns assistant help debug-targets
codingns assistant help workspaces
codingns assistant help sessions
```

## 2. 公共参数和约定

### 2.1 所有 `codingns assistant` 命令的公共参数

| 参数 | 含义 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--base-url <url>` | Host 地址 | `http://127.0.0.1:3002` | 不传时优先读取环境变量 |
| `--token <token>` | Bearer token | 无 | 不传时优先读取环境变量或认证文件 |

### 2.2 公共环境变量

| 环境变量 | 含义 |
| --- | --- |
| `CODINGNS_BASE_URL` | 默认 Host 地址 |
| `CODINGNS_ACCESS_TOKEN` | 默认 Bearer token |
| `CODINGNS_AUTH_FILE` | 可选认证文件，支持读取 `apiBaseUrl/accessToken` |

### 2.3 公共约定

- `workspaces`、`projects`、`debug-targets` 这类命令，优先按对象查事实，再决定要不要执行。
- `sessions send`、`terminals send`、`debug-targets run` 这类命令会真正推进动作，不是只读查询。
- 调试进程当前没有单独的 `debug-runtimes stop` 命令。
  现在的正式停止路径是：先查运行态拿到 `terminalId`，再执行 `codingns assistant terminals close <terminalId>`。

#### `--port-request` 语法

CLI 用重复参数表达：

```bash
codingns assistant debug-targets launch-plan target-123 \
  --port-request role=frontend,cwd=apps/web,port=43001 \
  --port-request role=backend,cwd=apps/api,port=44001 \
  --token <token>
```

支持的键：

| 键 | 是否必填 | 说明 |
| --- | --- | --- |
| `port` | 必填 | 目标端口，`1-65535` |
| `service-id` | 可选 | 直接按服务 ID 匹配 |
| `role` | 可选 | `frontend|backend|worker|mock|custom` |
| `cwd` | 可选 | 服务工作目录。可以传相对 `targetRootPath` 的路径，也可以传绝对路径 |
| `name` | 可选 | 服务名 |
| `command` | 可选 | 服务启动命令 |

规则：

- 一条 `--port-request` 至少要提供 `service-id/role/cwd/name/command` 里的一个选择条件。
- 如果请求没匹配到服务，会报 `DEBUG_TARGET_PORT_REQUEST_UNMATCHED`。
- 如果请求匹配到多个服务，会报 `DEBUG_TARGET_PORT_REQUEST_AMBIGUOUS`。
- 如果多个服务请求同一个端口，或者端口已被占用，会报 `DEBUG_TARGET_PORT_REQUEST_CONFLICT` 或 `DEBUG_TARGET_PORT_NOT_AVAILABLE`。
- 没传 `--port-request` 时，仍然走平台原有的自动端口租约分配。

#### 原始 API 里的 `portRequests` JSON 结构

如果不是走 CLI，而是直接调 Host API，请求体结构是：

```json
{
  "portRequests": [
    {
      "role": "frontend",
      "cwd": "apps/web",
      "port": 43001
    },
    {
      "role": "backend",
      "cwd": "apps/api",
      "command": "node",
      "port": 44001
    }
  ]
}
```

## 5. 推荐工作流

### 5.1 并行工作区里的调试进程

1. 先分析调试目标

```bash
codingns assistant debug-targets analyze \
  --workspace-id workspace-123 \
  --root-path /repo/demo \
  --token <token>
```

2. 再显式请求端口生成计划

```bash
codingns assistant debug-targets launch-plan target-123 \
  --port-request role=frontend,cwd=apps/web,port=43001 \
  --port-request role=backend,cwd=apps/api,port=44001 \
  --token <token>
```

3. 最后真正启动

```bash
codingns assistant debug-targets run target-123 \
  --port-request role=frontend,cwd=apps/web,port=43001 \
  --port-request role=backend,cwd=apps/api,port=44001 \
  --token <token>
```

4. 需要停掉某个进程时

```bash
codingns assistant terminals close <terminalId> --token <token>
```

### 5.2 会话和终端仍然是两条线

- 要继续 AI 开发上下文：优先 `sessions send`
- 要读脚本输出、补 shell 命令、停掉受控终端：走 `terminals *`
- 要做并行工作区的调试进程编排和显式端口控制：走 `debug-targets *` / `debug-runtimes *`

## 6. Skill 自动同步现状

| 场景 | 当前行为 |
| --- | --- |
| npm 包安装 | 包内置的 `codingns-assistant` 会自动同步到 `CODINGNS_CODEX_HOME` 或默认 `~/.codex/skills/codingns-assistant` |
| Host 服务启动 | Host 会把仓库内置 `codingns-assistant` 当成 SSOT，同步到目标 Codex skill 目录 |
| Skill 真源 | 仓库内置资源 `apps/host/src/modules/skills/builtin-skills/codingns-assistant` |

## 7. 当前结论

- `assistant` 现在已经正式覆盖：项目、会话、终端、调试目标、调试运行时、工作区、工作树。
- 并行工作区开发需要的“分析调试目标 + 显式请求端口 + 启动 + 查运行态 + 关闭进程”已经有正式 assistant 入口。
- `codingns-assistant` 已按项目内置 Skill 管理，npm 安装和 Host 启动都会自动同步最新版本到 Codex。
