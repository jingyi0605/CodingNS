# CodingNS 通用桌面文件能力说明

## 这次加了什么

这次给 CodingNS 桌面端补了 4 个通用宿主能力，目标是让运行在桌面容器里的任意 HTML 页面都能统一调用：

1. 打开本地文件
2. 在 Finder / 资源管理器中显示指定文件
3. 选择本地目录
4. 获取宿主平台信息

这些能力只负责宿主侧动作，不保存任何文档库、镜像根路径、相对路径映射之类的业务配置。

## 新增的桌面命令

桌面 Rust / Tauri 侧新增：

- `open_local_file(path: String)`
- `reveal_in_file_manager(path: String)`
- `get_platform_info()`

继续复用已有：

- `pick_directory()`

### 基本校验

`open_local_file` 和 `reveal_in_file_manager` 都会先做最基本校验：

- 路径非空
- 必须是绝对路径
- 不能是 URL / scheme
- 目标必须存在

失败时统一返回 `错误码: 详情`，前端会拆成标准结构。

## HTML 页面怎么调用

桌面端现在会暴露稳定全局对象：

```js
window.CodingNSDesktop
```

结构如下：

```js
window.CodingNSDesktop = {
  runtime: {
    isAvailable(),
    getPlatformInfo(),
  },
  fs: {
    openFile(path),
    revealInFileManager(path),
    pickDirectory(),
  },
}
```

如果 HTML 页面是通过 `iframe` 跑在 CodingNS 里，子页面也可以直接用同一个 `window.CodingNSDesktop`。

- 宿主页自己有桌面能力时，直接调用
- `iframe` 子页没有直接 Tauri 权限时，会自动走 `postMessage` 转发到宿主页

业务页面不需要自己碰 `window.__TAURI_INTERNALS__`，也不需要自己写消息转发。

### 调用示例

```js
const desktop = window.CodingNSDesktop;

if (!desktop?.runtime?.isAvailable()) {
  console.warn("当前不是 CodingNS 桌面端");
} else {
  const platform = await desktop.runtime.getPlatformInfo();
  const openResult = await desktop.fs.openFile("/Users/jackson/Documents/中文 空格 文件.pdf");
  const revealResult = await desktop.fs.revealInFileManager("/Users/jackson/Documents/中文 空格 文件.pdf");
  const pickResult = await desktop.fs.pickDirectory();
}
```

## 返回结构

所有接口都走统一结果结构：

```ts
interface DesktopBridgeResult<T = void> {
  ok: boolean;
  value?: T;
  errorCode?: string;
  detail?: string;
}
```

### 成功示例

```json
{ "ok": true }
```

```json
{
  "ok": true,
  "value": {
    "platform": "macos",
    "isDesktop": true,
    "fileManager": "finder"
  }
}
```

### 失败示例

```json
{
  "ok": false,
  "errorCode": "FILE_NOT_FOUND",
  "detail": "目标路径不存在：/Users/demo/missing.pdf"
}
```

## 当前平台支持情况

### macOS

- 打开文件：`open <path>`
- Finder 定位：`open -R <path>`

### Windows

- 打开文件：系统默认关联
- 资源管理器定位：`explorer /select,<path>`

### Linux

- 打开文件：`xdg-open <path>`
- 定位文件：退化为打开父目录

### 非桌面环境

`window.CodingNSDesktop` 仍然会存在，但调用会优雅失败：

- `ok: false`
- `errorCode: "PLATFORM_NOT_SUPPORTED"`

这样业务页面可以先检测能力，再决定给用户什么提示。

## 明确不做的事

这套接口**不做**下面这些事：

- 不保存镜像根路径
- 不保存相对路径映射规则
- 不实现文档浏览器业务逻辑
- 不实现索引、检索、标签之类业务能力

这些都应该由外部 HTML 页面自己处理，通常自己放进 `localStorage`。
