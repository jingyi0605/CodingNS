# macOS 证书申请与导入说明

## 目的

这份说明只解决一件事：把 `CodingNS` 的 macOS 发布链路补到可用状态。

最终目标是让下面这条命令可以真正用于对外发布：

```bash
./scripts/build-desktop.sh release-macos
```

## 当前本地已生成的材料

本地安全目录：

```text
/Users/jackson/Documents/Code/CodingNS/.local-secrets/macos-signing
```

目录中的关键文件：

- `developer-id-signing.key.pem`：本地私钥，只能留在当前机器
- `developer-id-signing.csr.pem`：提交给 Apple Developer 的 CSR
- `release-macos.env`：本地发布配置模板，不进 Git

## 第一步：去 Apple Developer 申请证书

你需要的证书类型是：

```text
Developer ID Application
```

操作顺序：

1. 登录 Apple Developer 证书后台。
2. 选择创建新证书。
3. 证书类型选择 `Developer ID Application`。
4. 上传本地生成的 `developer-id-signing.csr.pem`。
5. 下载 Apple 返回的证书文件，通常是 `.cer`。

注意：

- 不要选错成 `Apple Development` 或 `Mac Development`，那不是对外分发用的。
- 不要重新生成一套别的私钥再配这个项目。现在仓库里已经有一套本地私钥和 CSR，继续沿用它，别把数据结构搞乱。

## 第二步：把 Apple 证书导回本机

拿到 `.cer` 之后，执行：

```bash
./scripts/import-macos-signing-certificate.sh /path/to/DeveloperIDApplication.cer
```

这个脚本会做这些事：

1. 把 Apple 返回的证书复制到本地安全目录。
2. 将证书和本地私钥组装成 `.p12`。
3. 导入到登录钥匙串。
4. 生成本地配置文件 `release-macos.env`。

如果你希望减少 `codesign` 时的钥匙串弹窗，可以先设置：

```bash
export MACOS_KEYCHAIN_PASSWORD='你的登录钥匙串密码'
```

然后再运行导入脚本。

## 第三步：补齐 notarization 配置

导入脚本会生成这个本地配置文件：

```text
/Users/jackson/Documents/Code/CodingNS/.local-secrets/macos-signing/release-macos.env
```

推荐方案是使用 `notarytool` 的 keychain profile。

先执行一次：

```bash
xcrun notarytool store-credentials "codingns-notary" \
  --apple-id "你的 Apple ID" \
  --team-id "你的 Team ID" \
  --password "你的 app-specific password"
```

然后在 `release-macos.env` 中取消注释并填写：

```bash
export APPLE_NOTARY_PROFILE='codingns-notary'
```

如果你懒得配 profile，也可以直接在 `release-macos.env` 中填写：

- `APPLE_ID`
- `APPLE_APP_SPECIFIC_PASSWORD`
- `APPLE_TEAM_ID`

能用，但不够干净。

## 第四步：执行构建和发布

先构建：

```bash
./scripts/build-desktop.sh build macos
```

再发布：

```bash
./scripts/build-desktop.sh release-macos
```

## 脚本当前行为

`release-macos` 现在已经支持：

- 自动读取 `.local-secrets/macos-signing/release-macos.env`
- 在未拿到 Apple 证书前，明确停在“等待 Apple 证书”阶段
- 对 `.app` 做签名
- 对 `.app` ZIP 做 notarization 并回写票据
- 重建 DMG、签名 DMG、notarize DMG、校验 Gatekeeper

## 常见问题

### 1. 为什么不能直接本地生成一个可用证书？

因为 Gatekeeper 信任的是 Apple 签发链，不是你自己手搓的自签名证书。

### 2. 为什么私钥不能提交到 Git？

因为这是发布身份的根。你把它扔进仓库，就等于给别人发了一把能伪装你发布应用的钥匙。

### 3. 为什么 `release-macos` 还会停住？

常见原因只有这几个：

- Apple 证书还没导入钥匙串
- `release-macos.env` 里缺少 `APPLE_SIGN_IDENTITY`
- notarization 凭据还没配置

## 你下一步该做什么

最短路径如下：

1. 把 `.local-secrets/macos-signing/developer-id-signing.csr.pem` 上传到 Apple Developer。
2. 下载 `Developer ID Application` 证书。
3. 运行 `./scripts/import-macos-signing-certificate.sh /path/to/DeveloperIDApplication.cer`。
4. 配置 `release-macos.env` 的 notarization 参数。
5. 执行 `build macos` 和 `release-macos`。
