# Android 应用打包说明

## 这套流程现在稳不稳定

### 【核心判断】

✅ 值得用：当前仓库里用于打 Android 包的**稳定入口**已经明确，就是项目根目录下的 `scripts/build-android.sh`。

但要把话说清楚：

- 稳定的是“**按脚本走**”这条路
- 不稳定的是“**手工直接敲 `tauri android build`**”这条路

原因很直接。前者会统一处理 `JAVA_HOME`、Android SDK / NDK、签名密钥、`key.properties` 和产物输出；后者很容易因为环境变量或签名配置缺失直接失败。

### 【关键洞察】

- 数据结构：Android release 打包依赖四个核心输入，分别是 `JDK`、`Android SDK/NDK`、`Rust Android target`、`release keystore`
- 复杂度：真正该记住的命令只有一条，不应该每次都手工拼 `tauri android build`
- 风险点：最大的破坏性风险不是代码本身，而是误用 `debug` 包、`unsigned` 包，或者绕开脚本直接打 release

## 以后统一怎么打

### 推荐命令

在仓库根目录执行：

```bash
bash scripts/build-android.sh release
```

如果只是打调试包：

```bash
bash scripts/build-android.sh debug
```

## 常见坑

### 1. 直接执行 `pnpm --filter user-app tauri:android:build`

这条命令不是不能用，而是它太依赖当前 shell 环境。

常见死法：

- `JAVA_HOME` 没配
- release 签名配置没准备好
- `key.properties` 缺失

结论：

- **不要把它当成日常稳定入口**
- 日常打包统一走脚本

### 2. 把 debug 包当成 release 包

最容易混的是这几种文件：

- `app-universal-release.apk`
- `app-universal-debug.apk`
- `app-universal-release-unsigned.apk`

这里面只有 `app-universal-release.apk` 是正式发布包。

### 3. 误以为有两套签名

当前仓库里确认到的 release keystore 只有一份：

- [codingns-release.jks](/Users/jackson/Code/CodingNS/apps/user-app/src-tauri/target/codingns-release.jks)

如果你觉得“签名不一致”，优先检查：

1. 你对比的是不是 debug 包
2. 你对比的是不是 unsigned 包
3. 你拿到的 APK 是否来自当前仓库这条脚本流程

## 怎么验证打出来的是正式包

推荐使用 `apksigner` 查看证书：

```bash

PATH="$(brew --prefix openjdk@21)/bin:$PATH" \
"$HOME/Library/Android/sdk/build-tools/36.0.0/apksigner" verify --print-certs \
/Users/jackson/Code/CodingNS/apps/user-app/src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
```

如果输出的 `SHA-256` 是下面这个值，就说明签名对上了：

```text

```
