# OpenCLI 与浏览器运维能力下线说明

## 背景

本次清理把历史上为 OpenCLI、办公浏览器和运维任务临时接入的能力面下线。它们已经没有业务使用方，继续保留只会增加会话启动、能力注册、前端设置页、SQLite schema 和测试维护成本。

真实浏览器任务和远程运维任务以后由 Codex / Claude Code 自带的浏览器、终端能力承担。

## 保留内容

- 工作区会话里的普通 `SKILL` 能力。
- 文档相关能力，包括现有文档创建、更新、导出和任务查询链路。
- `ONLYOFFICE` 独立设置入口和对应弹窗。
- Teable 等仍在使用的能力设置入口。
- Codex app-server 基础 turn 和运行时必要注入。

## 删除内容

- OpenCLI 前端设置面板、API 封装、浏览器桥和运行时构建链路。
- `browser.opencli_bridge`、`browser.playwright`、`office.browser.*`、`office.ops.*`。
- `/api/opencli/*`、`/api/office/browser/*`、`/api/office/ops/*` 相关后端路由与服务。
- 会话启动时的 OpenCLI 环境变量注入，包括 `PATH` 和 `CODINGNS_OPENCLI_*`。
- 会话 prompt / overlay 中的 OpenCLI 浏览器临时规则注入。
- runtime home / 共享 Codex home 的 OpenCLI skill 同步。
- `browser_profiles`、`ops_targets` 以及 OpenCLI 相关 SQLite 表和兼容补列逻辑。

## 替代方案

- 本地页面、localhost 调试和 UI 冒烟：使用 Codex 内置 Browser。
- 真实网站操作：使用 Codex / Claude Code 自带浏览器能力。
- SSH、控制台和运维类任务：使用 Codex / Claude Code 自带终端能力。
- 文档任务：继续使用现有 office document 链路。

## 验证口径

- 类型检查：`pnpm --dir apps/host exec tsc --noEmit`、`pnpm --dir apps/user-app exec tsc --noEmit`。
- SQLite 检查：`pnpm check:sqlite-runtime`。
- 残留清点：对 OpenCLI、`office.browser`、`office.ops`、`browser.opencli_bridge`、`browser.playwright`、旧 API 路由和旧表名做模块级 `rg`。
- 定向测试：优先跑 host 会话注入、能力路由、SQLite bootstrap 和设置页相关测试。
