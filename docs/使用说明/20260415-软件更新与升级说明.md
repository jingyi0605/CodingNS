# 软件更新与升级说明

## 这份说明是干什么的

这份说明写的是现在项目里三条更新链路怎么用：

- 桌面客户端更新
- Android `APK` 直装更新
- 服务端全局 npm 包升级

别再把这三件事混成一个“更新按钮”。它们底层根本不是同一种东西。

## 1. 在哪里操作

统一入口都在用户端设置页的“软件更新”分组里。

你会看到三类内容：

1. 发布通道
2. 服务端更新
3. 客户端更新

不同平台显示会有差异：

- 桌面端：显示服务端更新 + 桌面客户端更新
- Android：显示服务端更新 + Android `APK` 更新
- iOS：显示服务端更新 + “当前不支持安装更新”
- Web/H5：只显示服务端更新

## 2. 桌面客户端怎么更新

桌面端现在走的是 Tauri 官方 updater。

用户侧动作只有两步：

1. 点击“检查客户端”
2. 有新版本时点击“安装更新”

如果你打开了“自动检查客户端更新”：

- 桌面客户端启动后会自动检查一次
- 检测到新版本时会发系统通知

发布侧要保证下面这些东西同时存在：

- `latest.json`
- macOS `.app.tar.gz + .sig`
- Windows `NSIS .exe + .sig`
- 构建时注入 `TAURI_SIGNING_PUBLIC_KEY`

如果少了公钥，客户端虽然能编出来，但 updater 安装链路不会工作。

## 3. Android 怎么更新

Android 现在明确走 `APK` 直装，不走商店更新。

用户侧动作：

1. 点击“检查客户端”
2. 看到新版本后点击“安装更新”
3. 应用下载并校验 APK
4. 系统安装器接管，用户自己确认安装

要注意：

- 如果没开“允许此来源安装应用”，系统会先跳权限页
- 如果用户从系统安装器回到应用，但版本还没变，页面会提示“安装已取消或未完成，可重新触发安装”
- 应用不会假装自己能静默安装

发布侧要保证 Android 清单和 APK 一起可访问：

- `android-apk.json`
- `app-universal-release.apk`

## 4. 服务端怎么升级

服务端更新不是“下载客户端”，而是让 Host 执行全局 npm 升级。

用户侧动作：

1. 点击“检查服务端”
2. 有新版本时点击“安装更新”

系统侧动作：

- Host 创建后台任务
- 后台任务执行 `npm install -g <package>@<tag or version>`
- 前端轮询任务状态
- 安装成功后明确提示“新版本已安装，重启 Host 后生效”

这里最重要的一条是：

- “包已经升级”不等于“当前进程已经切到新版本”

所以看到“需要重启”不是 bug，这是系统在说真话。

## 5. 现在的发布责任分别是什么

桌面端发布责任：

- GitHub Actions 生成安装包、updater 资产和 `latest.json`

Android 发布责任：

- GitHub Actions 在 tag 发布时自动构建 `app-universal-release.apk`
- 发布阶段自动生成对应的 `android-apk.json`
- 两个文件都会上传到 GitHub Release，并通过 `latest/download` 暴露稳定地址
- Host 启动时会把远端 `android-apk.json` 同步到本地 `releaseManifestRoot/stable/android-apk.json`

服务端发布责任：

- 正常发布 npm 包
- 确保受管包版本能被 registry 查询到

## 6. 现在还没做的事

下面这些能力现在没有，不要误判：

- Android 静默安装
- iOS 客户端自更新
- 服务端自动重启切换到新版本
- Windows 商业代码签名整套流程

第一版的目标不是把所有安装器生态一锅炖，而是把现有三条链路做成“能用、能解释、不撒谎”。
