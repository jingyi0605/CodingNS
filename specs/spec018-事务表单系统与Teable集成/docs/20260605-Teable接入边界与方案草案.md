# 20260605-Teable接入边界与方案草案

## 这份补充文档记录什么

这份文档只记录当前已经确认下来的接入边界，避免后面重新把方向走歪。

## 已确认结论

### 1. 第一阶段只用 `Teable` 的表、视图、表单和基础权限

不接：

- `Teable AI`
- `Teable Automation` 主链路
- `Teable App Builder`

### 2. `Teable` 不当 `CodingNS` 真源

真源继续在 `CodingNS`：

- 标签
- 会话
- 代办

`Teable` 只拿镜像表做引用，业务表收表单结果。

### 3. 不做“`Teable` 直接读 `CodingNS` 内部数据库”

第一阶段只允许：

- `CodingNS -> Teable` 镜像同步
- `Teable -> CodingNS` 结果回流

不允许：

- `Teable` 直接挂 `CodingNS` 私有 SQLite 或内存数据
- 直接把 `CodingNS` 私有数据库当成 `Teable` 原生表

### 4. `Teable` 实例走事务工作台全局绑定，不跟单个工作区走

- `Teable` 站点、空间、认证引用是事务工作台级全局配置
- 不为每个 `workspace` 各存一套实例配置
- 但“推什么到 `Teable`”“哪些表单引用哪些镜像表”“怎么回流”继续在工作台里配

### 5. 镜像表默认只读

策略目标：

- 只有 `CodingNS` 同步账号可写镜像表
- 普通 `Teable` 用户只能把镜像表当引用数据源
- 真正可编辑的内容必须落在业务表

### 6. 表单入口优先放事务工作台

首阶段不改代码视图主骨架，不把 `Teable` 误做成代码模式里的 provider 或聊天入口。

## 当前推荐表结构

### 镜像表

- `cn_tags`
- `cn_sessions`
- `cn_todos`

### 业务表

按场景创建，例如：

- 需求收集表
- 跟进申请表
- 资料补充表
- 标签申请表

## 当前推荐主链路

1. 事务工作台全局绑定 `Teable`
2. 在工作台里配置要推哪些标签 / 会话 / 代办
3. 初始化镜像表
4. 同步标签 / 会话 / 代办到镜像表
5. 从 `CodingNS` 发起新建业务表 + Form View
6. 用户填写表单
7. `CodingNS` 拉回业务表结果
8. 结果转成本地代办、会话补充或标签动作
