# spec018-事务表单系统与Teable集成

## 这份 Spec 现在只解决什么

这份 Spec 只解决一件事：

**把 `Teable` 作为 `CodingNS` 的内置表单系统接进事务工作台，同时把 `CodingNS` 里的标签、会话、代办等真实数据安全地喂给 `Teable` 表单使用。**

一句人话：

- 不是把 `Teable` 当外链挂出去就算完事
- 也不是把 `CodingNS` 内部数据库直接裸给 `Teable`
- 而是要让用户在 `CodingNS` 里能创建和使用 `Teable` 表单，并且这些表单能选到 `CodingNS` 的标签、会话、代办，提交结果还能再回到 `CodingNS`

## 这次要交付什么

### 1. `Teable` 作为内置表单能力正式接进工作台

- 事务工作台里出现正式的 `Teable` / 表单入口
- 用户可以在 `CodingNS` 里看到当前事务工作台全局绑定的 `Teable` 站点、目标空间、目标表单
- 用户可以从 `CodingNS` 打开已有 `Teable` 表单，也可以发起“新建表单应用”流程

### 2. `CodingNS` 真源数据镜像到 `Teable`

首阶段只覆盖三类真源：

- 标签
- 会话摘要
- 代办

这三类数据不会让 `Teable` 直接读 `CodingNS` 内存或本地库，而是由 `CodingNS Host` 同步成 `Teable` 里的镜像表。

### 3. 工作台里可以配置“推什么数据到 `Teable`”

- `Teable` 实例本身全局绑定在事务工作台，不跟单个 `workspace` 走
- 但哪些标签、哪些会话、哪些代办要推，仍然在事务工作台里显式配置
- 后续不同表单用哪些镜像数据、回流到哪里，也继续在工作台里配，不藏进底层常量

### 4. 基于镜像表创建可引用的业务表单

- 业务表单所在表可以通过 `Link / Lookup` 引用镜像表
- 表单填写时可以选 `CodingNS` 的标签、会话、代办
- 镜像表默认只读，只允许 `CodingNS` 同步账号写入

### 5. 表单提交结果能回到 `CodingNS`

- `Teable` 业务表新增或变更后，`CodingNS` 能拉回结果
- 首阶段优先支持把表单结果转成：
  - 新代办
  - 现有代办补充信息
  - 会话上下文补充
  - 标签分配请求
- 这条回流链路继续由 `CodingNS` 控，不依赖 `Teable AI` 或 `Teable Automation`

## 这次明确不做什么

- 不接 `Teable` 的 AI 能力
- 不接 `Teable` 的自动化能力当主链路
- 不把 `Teable App Builder` 当第一阶段交付目标
- 不让 `Teable` 直接读取 `CodingNS` 内存、SQLite 或私有数据库
- 不在第一阶段做双向强一致同步
- 不深改 `Teable` 源码再把它揉进 `CodingNS` 主仓

## 为什么这轮必须先走“镜像表”

这点先写死，不然后面一定会走歪。

原因很简单：

1. `Teable` 当前正式能力适合“用 API 管它自己的表”，不适合“把外部系统直接挂成原生数据源”
2. `CodingNS` 里的标签、会话、代办都有自己的权限、状态和生命周期，不能把真源让给 `Teable`
3. 如果第一阶段就追求双向强一致、实时跨系统 join，只会把同步、冲突和排障复杂度炸开

所以第一阶段的原则是：

**`CodingNS` 继续是真源，`Teable` 拿镜像表做引用，业务表单回流时再由 `CodingNS` 显式接收和处理。**

## 这次的硬边界

### 边界 1：`CodingNS` 继续是真源

- 标签真源在 `CodingNS`
- 会话真源在 `CodingNS`
- 代办真源在 `CodingNS`
- `Teable` 只承接表单、结构化录入、引用和协作展示

### 边界 2：镜像表和业务表分开

- 镜像表只负责给表单引用
- 业务表才负责接表单提交
- 不能把“镜像表”和“表单结果表”混成一张

### 边界 3：镜像表默认只读

- 普通 `Teable` 用户不能直接改镜像表记录
- 只有 `CodingNS` 专用同步账号能写镜像表
- 用户真正可编辑的数据必须落在业务表里

### 边界 4：`Teable` 实例是工作台级全局绑定，不是工作区级绑定

- `Teable` 实例配置不跟单个 `workspaceId` 走
- 不为每个工作区各存一套 `Teable baseUrl/token/spaceId`
- 同一个事务工作台先只认一套全局 `Teable` 实例
- 具体推送哪些数据、哪些表单引用哪些数据，再在工作台里单独配置

### 边界 5：表单系统先服务事务工作台

- 第一阶段入口优先放在事务视图
- 不先把 `Teable` 塞进代码视图左侧会话树或 provider 体系
- 不把“表单系统”误做成另一个聊天入口

### 边界 6：首阶段只做 Form View，不做 App Builder

- 先把“表单采集 + 引用镜像表 + 回流 `CodingNS`”跑通
- 多步应用、品牌化页面、复杂布局编辑以后再说
