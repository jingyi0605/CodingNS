# spec001.9.2-公共隧道管理员只读后台与权限通路

## 当前定位

这是 `spec001.9` 下的新子 Spec，也是接在 `spec001.9.1` 后面的运营侧补口。

它只解决一件事：

- 给 `apps/codingns-proxy` 这套公共隧道服务补一条真正独立的管理员权限通路，让管理员能看全局数据，而不是继续拿用户控制台硬凑后台。

一句人话：
当前只有“用户控制台”，没有“管理员后台”。这次不是往用户 `Dashboard` 里多塞几张卡片，而是把角色模型、管理员鉴权、管理员 API、管理员路由这四样真东西补出来。

## 2026-04-20 二期补记

一期只读后台已经落地。二期继续沿用同一条管理员通路，但只补最小写操作，不扩成什么都能改的脏后台。

这次新增三件事：

- 管理员可以解绑任意设备绑定
- 管理员可以停用或重新启用未兑换激活码
- 管理员可以在后台在线批量生成激活码，并一次性拿到完整码结果

一句人话：
先把最容易出运营事故、又最容易定义边界的动作补上。生成激活码也只补最小闭环：后台生成、当前页一次性回显完整码、列表继续只展示掩码。手工加量、封禁账号、复杂 RBAC 继续不做。

## 计划覆盖

- `accounts.role` 角色模型
- 管理员鉴权与独立 `/api/admin/*` 命名空间
- 管理员只读数据查询：
  - 用户列表与详情摘要
  - 设备绑定列表
  - 激活码列表
  - 支付事件日志
  - relay usage 日志
- 管理员最小写操作：
  - 解绑任意设备绑定
  - 停用未兑换激活码
  - 重新启用未兑换激活码
  - 在线批量生成激活码
- `console-web` 的管理员路由壳与只读后台页面
- 旧用户会话兼容、现有用户接口零破坏

## 本阶段明确不做

- 不做复杂 RBAC
- 不做管理员注册
- 不做细粒度权限树
- 不把管理员能力塞回用户 `Dashboard`
- 不做手工加量、封禁账号、角色审批流
- 不把后台写操作扩成运营大盘
- 不把完整激活码长期明文回显到列表里
