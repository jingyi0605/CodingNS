# spec015 最小闭环验收草案

状态：Draft

## 1. 目标

这份草案只解决一件事：

定义 `spec015` 第一阶段到底怎样才算“真的能用”，而不是文档写完就当成功。

一句话版本：

**没有最小闭环验收，前面那些设计最后都会变成自我感动。**

## 2. 验收原则

### 2.1 先验四条主线

第一阶段只验四条主线：

- 浏览器任务
- 模板文档
- SSH / 浏览器运维
- 自动化工作流

### 2.2 每条主线都要回到统一任务模型

验收时不只看“功能有没有跑起来”，还要看：

- 有没有 `OfficeTask`
- 有没有 `OfficeTaskStep`
- 有没有产物或回执
- 该审批的有没有审批

### 2.3 先追最小闭环，不追全量生态

第一阶段不验证：

- 所有 SaaS 平台
- 所有浏览器站点
- 所有文档模板
- 所有运维系统

先把最小主链路跑通。

## 3. 浏览器主线验收

### 3.1 目标

证明平台能在真实浏览器里完成一次正式浏览器任务，并留下截图证据。

### 3.2 前置条件

- 已注册 `browser.playwright`
- 可用真实 `Chrome` 或 `Edge`
- 已创建浏览器 `Profile`

### 3.3 验收步骤

1. 创建一个浏览器任务
2. 打开目标页面
3. 执行至少一组页面动作
4. 读取 DOM 或文本结果
5. 产出截图
6. 完成任务并写回回执

### 3.4 通过条件

- 生成正式 `OfficeTask`
- 至少有一条 `OfficeTaskStep`
- 至少有一个 `screenshot` 产物
- 任务状态进入成功终态

## 4. 文档主线验收

### 4.1 目标

证明平台能从结构化文档对象正式导出指定模板文档。

### 4.2 前置条件

- 已注册 `document.doct`
- 至少有一个可用 `doct` 模板
- 已创建文档对象和修订

### 4.3 验收步骤

1. 创建文档对象
2. 写入大纲和正文块
3. 绑定模板
4. 触发正式导出
5. 导出 `docx` 或 `pdf`
6. 记录模板版本和导出产物

### 4.4 通过条件

- 文档对象存在正式修订
- 模板字段校验通过
- 产出正式导出件
- 导出件挂到 `OfficeArtifact(kind="document_export")`
- 回执里能追到模板和模板版本

## 5. 运维主线验收

### 5.1 目标

证明平台能完成一次受控运维动作，并留下正式记录。

### 5.2 分两条

- `SSH` 运维
- 浏览器控制台运维

### 5.3 SSH 运维前置条件

- 已注册 `ops.ssh`
- 已创建 `OpsTarget(kind="ssh_host")`
- 已配置 `credentialRef`

### 5.4 SSH 运维步骤

1. 创建 SSH 运维任务
2. 校验风险和权限
3. 执行一条安全命令
4. 记录输出摘要和日志
5. 完成任务

### 5.5 SSH 运维通过条件

- 命中正式 `OpsTarget`
- 任务和步骤记录齐全
- 留下 `command_log` 或等价产物
- 回执里能看到退出状态

### 5.6 浏览器运维前置条件

- 已注册 `ops.browser_console`
- 已创建 `OpsTarget(kind="web_console")`
- 已绑定可用浏览器 `Profile`

### 5.7 浏览器运维步骤

1. 创建浏览器运维任务
2. 打开控制台
3. 完成一次登录后操作
4. 记录截图和页面证据
5. 完成任务

### 5.8 浏览器运维通过条件

- 任务和步骤记录齐全
- 至少有一张页面截图
- 至少有一次控制台动作记录
- 失败时能看到失败摘要

## 6. 工作流主线验收

### 6.1 目标

证明平台能通过正式工作流对象触发并编排至少一次办公任务。

### 6.2 前置条件

- 已注册一个可用工作流
- 工作流至少有两个步骤
- 至少一步会创建 `OfficeTask`

### 6.3 验收步骤

1. 创建工作流定义
2. 配一个 `manual` 或 `once` 触发器
3. 启动一次 `WorkflowRun`
4. 执行第一个步骤
5. 创建并等待关联 `OfficeTask`
6. 根据结果完成、分支或补偿

### 6.4 通过条件

- 生成正式 `WorkflowRun`
- 至少有一条 `WorkflowRunStep`
- 至少创建一个关联 `OfficeTask`
- 失败时能看到重试或补偿记录

## 7. 平台级通过条件

四条主线之外，还必须满足：

- 高风险动作能进入审批
- 失败动作有审计或回滚记录
- 所有任务都能按连接器追踪
- 不使用新能力时，不影响原有编码主链路

## 8. 第一阶段明确不验什么

第一阶段不要求：

- 所有连接器都实装
- 所有站点都稳定适配
- 组织级复杂权限体系
- 大规模并发压测

这些后面真要做，再单独立验收项。
