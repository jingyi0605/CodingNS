# spec015 审批审计回滚权限草案

状态：Draft

## 1. 目标

这份草案只解决一件事：

把 `spec015` 里“哪些动作要人批、做完怎么记、出错怎么撤、谁能做什么”说清楚。

一句话版本：

**没有审批、审计、回滚和权限分级，办公平台就只是危险脚本堆。**

## 2. 核心原则

### 2.1 审批不是聊天里的口头同意

要审批，就必须生成正式审批对象。  
不能只在界面里弹一句“你确认吗”，然后系统自己当作批准。

### 2.2 审计不是日志替身

审计事件必须记录：

- 发生了什么
- 谁触发的
- 关联哪个任务或步骤
- 结果如何

不能拿普通 debug log 冒充审计。

### 2.3 回滚不是一句“失败了”

如果动作可以回滚，就必须有正式回滚记录。  
如果动作不能回滚，也必须明确写成“不可回滚”，不能装作没事。

### 2.4 权限分级先按风险走

第一阶段不先搞复杂组织体系，而是先按下面这组逻辑：

- 低风险：直接执行
- 中风险：受控执行
- 高风险：必须审批

## 3. 审批模型

### 3.1 审批对象

平台里已经有 `OfficeApproval`，这一节补的是它的实际使用方式。

审批对象最少回答这些问题：

- 是哪一个任务要批
- 是哪一个步骤要批
- 为啥要批
- 谁批的
- 批成什么结果

### 3.2 什么时候创建审批

以下场景建议默认进入审批：

- 高风险 SSH 命令
- 运行中的浏览器接管
- 破坏性系统变更
- 需要修改正式文档模板样式
- 任何被策略显式标成高风险的步骤

### 3.3 审批记录要保留什么

至少保留：

- `policyId`
- 任务 ID
- 步骤 ID
- 审批人
- 决策结果
- 决策说明
- 决策时间

## 4. 审计模型

### 4.1 审计事件对象

建议使用 `OfficeAuditEvent`。

审计事件只负责一件事：

**把平台动作变成可查证的事实记录。**

### 4.2 必须记审计的事件

建议至少覆盖：

- 任务创建
- 任务修改
- 任务开始
- 任务完成
- 任务取消
- 任务审批通过或拒绝
- 任务回滚
- 关键产物创建
- 外部资源动作
- 权限拒绝

### 4.3 审计事件不要记什么

不要往审计里塞：

- 巨长的调试输出
- 全量页面 HTML
- 无意义的临时变量

这些东西应该去日志或产物，不该污染审计主表。

## 5. 回滚模型

### 5.1 回滚对象

建议使用 `OfficeRollbackRecord`。

回滚对象要回答：

- 为什么回滚
- 回滚做了什么
- 回滚成功没有
- 能不能继续补偿

### 5.2 哪些动作必须准备回滚语义

建议默认包括：

- SSH 变更
- 浏览器里的破坏性运维动作
- 文档正式发布前的不可逆导出
- 自动化工作流里的高风险步骤

### 5.3 回滚记录要保留什么

至少保留：

- 任务 ID
- 步骤 ID
- 回滚原因
- 补偿内容
- 开始时间
- 结束时间
- 最终状态

## 6. 权限分级模型

### 6.1 第一阶段只做最小角色语义

先别把组织级 RBAC 搞得太复杂。  
第一阶段够用的角色语义建议是：

- `owner`
- `operator`
- `reviewer`
- `admin`

### 6.2 权限判断顺序

建议按这个顺序判断：

1. 这个动作是不是被系统判定为高风险
2. 调用者有没有这个能力的执行权限
3. 调用者是不是有审批或复核权限
4. 目标对象是不是归属于当前工作区或账号

### 6.3 先不做什么

第一阶段先不做：

- 复杂组织层级继承
- 多租户交叉授权
- 细粒度条件表达式权限策略

这些东西后面真需要，再补。

## 7. 服务边界

### 7.1 `office-approval-service`

职责：

- 创建审批
- 查询待审批列表
- 处理审批回复

### 7.2 `office-audit-service`

职责：

- 记录审计事件
- 查询审计事件
- 给任务和步骤提供追溯入口

### 7.3 `office-rollback-service`

职责：

- 创建回滚记录
- 推进回滚状态
- 保存补偿摘要

### 7.4 `office-permission-service`

职责：

- 计算动作是否需要审批
- 判断执行者是否有权限
- 把高风险操作拦到正确的入口

## 8. 关键流程

### 8.1 高风险任务执行流程

1. 用户发起任务
2. 系统识别风险等级
3. 系统创建审批对象
4. 审批通过后才允许继续
5. 每个关键动作写审计
6. 如果失败且支持补偿，则写回滚记录

### 8.2 权限拒绝流程

1. 调用者发起动作
2. 系统判断权限不足
3. 动作被拒绝
4. 系统写审计事件
5. 系统返回明确错误

## 9. 最容易做烂的地方

1. 把审批做成一个布尔值
2. 把审计做成普通日志
3. 把回滚做成一句说明
4. 把权限分级做成前端按钮禁用
5. 高风险动作没有明确终态
