# spec015 doct 模板字段映射草案

状态：Draft

## 1. 目标

这份草案只解决一件事：

把 `doct` 模板怎么接、怎么校验、怎么导出说清楚。

一句话版本：

**文档内容可以由 AI 写，最终样式必须由指定 `doct` 模板决定。**

## 2. 核心原则

### 2.1 模板是样式真相源

不能让前端样式、模型提示词、导出脚本各说各话。

最终交付样式只认模板。

### 2.2 字段映射必须显式

每个模板都要说清楚：

- 需要哪些字段
- 哪些字段必填
- 哪些字段可选
- 哪些字段只用于导出，不允许改正文

### 2.3 导出前先校验，校验不过就别装作成功

如果模板字段不齐、类型不对、引用缺失，就直接失败。

不能“先导了再说”，那是垃圾流程。

## 3. 模板对象

### 3.1 `DocumentTemplate`

建议最少字段：

- `id`
- `templateKey`
- `displayName`
- `engine`
- `templateVersion`
- `schemaJson`
- `mappingJson`
- `outputFormatsJson`
- `status`
- `createdAt`
- `updatedAt`

### 3.2 `DocumentTemplateSchema`

模板 schema 最少要表达：

- 文档标题
- 文档摘要
- 章节结构
- 正文块
- 引用来源
- 批注锚点
- 导出格式限制

### 3.3 `DocumentTemplateMapping`

映射层要能把结构化文档对象转成模板需要的数据。

至少要支持：

- `document.title -> template.title`
- `document.outline -> template.sections`
- `document.revisions.latest -> template.body`
- `document.citations -> template.references`
- `document.comments -> template.annotations`

## 4. 导出流程

### 4.1 正式导出顺序

1. 读取文档对象
2. 读取当前修订
3. 读取大纲、引用和批注
4. 校验模板字段
5. 生成模板输入
6. 渲染 `doct`
7. 输出 `docx/pdf/md`
8. 记录导出产物和模板版本

### 4.2 校验规则

至少要校验：

- 必填字段是否存在
- 字段类型是否正确
- 引用是否能回溯
- 批注锚点是否有效
- 导出格式是否被模板支持

### 4.3 失败规则

以下情况必须直接失败：

- 模板缺字段
- 文档结构和模板不匹配
- 引用来源找不到
- 模板版本不可用
- 输出格式不在模板支持列表里

## 5. 服务边界

### 5.1 `document-template-service`

职责：

- 注册模板
- 读取模板版本
- 管字段映射
- 管模板状态

### 5.2 `document-export-service`

职责：

- 校验导出输入
- 调用 `doct`
- 生成正式产物
- 记录模板版本和导出结果

### 5.3 `document-template-validator`

职责：

- 校验模板 schema
- 校验文档内容
- 拒绝不兼容导出

## 6. 最容易做烂的地方

1. 把模板当成普通配置文件
2. 不校验字段就导出
3. 前端自己拼样式冒充正式文档
4. 导出失败时只吐一条模糊错误
