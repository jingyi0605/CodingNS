# spec015 浏览器运维目标与控制台操作链路草案

状态：Draft

## 1. 目标

这份草案只解决一件事：

把“通过浏览器做运维”从普通网页自动化里拆出来，变成正式的运维动作。

一句话版本：

**浏览器运维不是点网页，而是在受控目标上完成可审计操作。**

## 2. 核心原则

### 2.1 运维目标不是普通网页

浏览器运维的目标是：

- 控制台
- 后台管理页
- 登录后站点
- 需要人工身份和状态的管理界面

它不是随便一个网页自动化任务。

### 2.2 运维动作必须可追踪

每一步都要知道：

- 在哪台机器上执行
- 用哪个浏览器 Profile
- 登录到哪个站点
- 做了什么操作
- 结果是什么

### 2.3 不允许静默操作生产控制台

只要目标是正式控制台，就必须把权限、审批和审计放在前面。

## 3. 运维目标对象

### 3.1 `OpsTarget(kind="web_console")`

浏览器运维目标应该单独作为一种正式对象。

它至少要回答：

- 目标站点是什么
- 控制台地址是什么
- 用哪个浏览器 Profile
- 需要哪些身份信息
- 是否允许自动化操作

建议最少字段：

- `id`
- `userId`
- `kind`
- `displayName`
- `consoleUrl`
- `loginHint`
- `browserProfileId`
- `configJson`
- `credentialRef`
- `status`
- `createdAt`
- `updatedAt`

## 4. 浏览器运维执行模型

### 4.1 `BrowserOpsRunRequest`

建议最少字段：

- `targetId`
- `profileId`
- `entryUrl`
- `operationPlan`
- `riskLevel`
- `approvalPolicyId`
- `timeoutMs`

### 4.2 `BrowserOpsRunResult`

建议最少字段：

- `sessionId`
- `pageIds`
- `artifactIds`
- `summary`
- `startedAt`
- `finishedAt`
- `succeeded`

### 4.3 运行流程

1. 选择 `OpsTarget(kind="web_console")`
2. 选择或创建浏览器 `Profile`
3. 打开控制台地址
4. 完成登录或身份恢复
5. 执行控制台操作
6. 记录截图、DOM 快照和结果摘要
7. 必要时生成回执或回滚记录

## 5. 运维动作范围

第一阶段只做这几类：

- 登录控制台
- 切换页面
- 填写表单
- 点击确认
- 下载结果
- 截图留痕
- 读取页面状态

先不做复杂到离谱的专用站点适配器。

## 6. 留痕规则

### 6.1 必须留下什么

至少要留下：

- 控制台地址
- 浏览器引擎
- Profile 归属
- 操作步骤
- 截图
- 页面快照
- 失败原因

### 6.2 产物挂法

这些产物要挂回：

- `OfficeTask`
- `OfficeTaskStep`
- `OfficeArtifact`

不能只放在临时下载目录里。

## 7. 风险规则

### 7.1 默认高风险动作

以下动作默认应按高风险处理：

- 生产控制台登录
- 提交关键配置
- 删除资源
- 重启服务
- 修改权限

### 7.2 失败退回

如果控制台动作失败：

- 记录失败步骤
- 保留最后一张截图
- 保留页面状态摘要
- 不污染普通浏览器 Profile

## 8. 服务边界

### 8.1 `ops-browser-run-service`

职责：

- 绑定浏览器 Profile
- 打开控制台
- 执行控制台步骤
- 保存证据和结果

### 8.2 `ops-audit-service`

职责：

- 记录控制台运维审计
- 记录关键页面动作
- 记录失败和回退

## 9. 最容易做烂的地方

1. 把控制台运维当普通网页脚本
2. 不区分普通 Profile 和运维 Profile
3. 不留截图和页面证据
4. 失败后继续污染浏览器状态
5. 没有任务对象就直接操作正式控制台
