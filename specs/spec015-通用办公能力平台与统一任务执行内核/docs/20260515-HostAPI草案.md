# spec015 Host API 草案

状态：Draft

## 1. 目标

这份草案定义 `spec015` 在宿主端的第一版 API 轮廓。

要求只有一个：

**办公能力必须先经过统一平台对象，再下钻到浏览器、文档、运维和自动化模块。**

所以这里不允许一上来就变成：

- `/api/playwright/*`
- `/api/doct/*`
- `/api/ssh/*`

这种按底层技术直接开洞的做法。

## 2. 设计原则

### 2.1 任务是顶层资源

绝大多数动作最终都应该能回到：

- `/api/office/tasks`

上层入口先围绕任务展开，具体执行器只是任务后面的实现细节。

### 2.2 具体能力允许有分组入口，但不能绕开任务

可以有：

- `/api/office/browser/*`
- `/api/office/documents/*`
- `/api/office/ops/*`
- `/api/office/workflows/*`
- `/api/office/connectors/*`

但这些入口本质上仍然应该：

1. 创建或读取平台对象
2. 统一写任务、步骤、产物、审批

### 2.3 先把控制面 API 做稳，后面再补丰富动作

MVP 阶段优先保证：

- 能创建任务
- 能查看状态
- 能拿到产物
- 能审批
- 能重试和取消

不要一开始就把所有浏览器动作、模板动作、运维动作全塞成几十个散接口。

## 4. 详细接口

### 4.1 `GET /api/office/tasks`

用途：列出办公任务。

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `workspaceId` | `string` | 可选，按工作区过滤 |
| `taskType` | `string` | 可选，`browser/document/ops/workflow` |
| `status` | `string` | 可选，按状态过滤 |
| `riskLevel` | `string` | 可选，按风险等级过滤 |
| `limit` | `number` | 可选，限制返回条数 |

响应示例：

```json
{
  "items": [
    {
      "id": "task_001",
      "taskType": "browser",
      "title": "登录控制台并导出报表",
      "status": "running",
      "riskLevel": "medium",
      "workspaceId": "ws_001",
      "createdAt": "2026-05-15T10:00:00.000Z",
      "updatedAt": "2026-05-15T10:03:00.000Z"
    }
  ]
}
```

### 4.2 `POST /api/office/tasks`

用途：创建统一办公任务。

请求体：

```json
{
  "taskType": "document",
  "title": "生成周报",
  "workspaceId": "ws_001",
  "connectorId": "document.doct",
  "targetRefKind": "document_template",
  "targetRefId": "tpl_weekly_001",
  "riskLevel": "low",
  "input": {
    "templateKey": "weekly-report",
    "sourceRefs": ["note_01", "note_02"]
  }
}
```

响应示例：

```json
{
  "task": {
    "id": "task_001",
    "taskType": "document",
    "status": "ready"
  }
}
```

### 4.3 `GET /api/office/tasks/:taskId`

用途：读取任务详情。

响应字段建议：

- 任务基本信息
- 当前状态
- 当前步骤
- 审批状态
- 最近产物摘要

### 4.4 `POST /api/office/tasks/:taskId/cancel`

用途：取消任务。

说明：

- 只能取消 `draft / pending_approval / ready / running / paused / waiting_external`
- 终态任务不允许重复取消

### 4.5 `POST /api/office/tasks/:taskId/retry`

用途：重试失败任务或失败步骤。

请求体：

```json
{
  "fromStepId": "step_003"
}
```

### 4.6 `GET /api/office/tasks/:taskId/steps`

用途：查看任务步骤。

响应字段建议：

- `stepSeq`
- `stepType`
- `title`
- `status`
- `retryCount`
- `startedAt`
- `finishedAt`
- `errorMessage`

### 4.7 `GET /api/office/tasks/:taskId/artifacts`

用途：查看任务产物。

响应字段建议：

- `kind`
- `name`
- `storagePath`
- `contentType`
- `createdAt`

### 4.8 `GET /api/office/approvals`

用途：列出待审批事项。

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `string` | `pending/approved/rejected/...` |
| `taskId` | `string` | 可选，按任务过滤 |

### 4.9 `POST /api/office/approvals/:approvalId/reply`

用途：处理审批。

请求体：

```json
{
  "decision": "approved",
  "note": "允许继续执行"
}
```

### 4.10 `GET /api/office/browser/profiles`

用途：列出浏览器 Profile。

响应字段建议：

- `engine`
- `mode`
- `displayName`
- `ownershipScope`
- `status`

### 4.11 `POST /api/office/browser/profiles`

用途：创建独立持久化浏览器 Profile。

请求体：

```json
{
  "engine": "chrome",
  "displayName": "运营后台专用 Profile",
  "workspaceId": "ws_001",
  "ownershipScope": "workspace"
}
```

### 4.12 `POST /api/office/browser/tasks`

用途：创建浏览器任务。

请求体：

```json
{
  "title": "登录站点并截图",
  "workspaceId": "ws_001",
  "profileId": "bp_001",
  "input": {
    "startUrl": "https://example.com/login",
    "actions": [
      { "type": "goto", "url": "https://example.com/login" },
      { "type": "fill", "selector": "#username", "value": "demo" },
      { "type": "click", "selector": "button[type='submit']" },
      { "type": "screenshot", "fullPage": true }
    ]
  }
}
```

说明：

- 这里允许有浏览器动作数组
- 但最终仍应创建统一 `office_task`

### 4.13 `POST /api/office/browser/cdp/attach`

用途：接管运行中的真实浏览器。

请求体：

```json
{
  "engine": "edge",
  "displayName": "接管当前 Edge",
  "cdpEndpoint": "http://127.0.0.1:9222"
}
```

说明：

- 必须明确标记为高级模式
- 后端要单独记审计

### 4.14 `GET /api/office/documents`

用途：列出文档。

### 4.15 `POST /api/office/documents`

用途：创建文档对象。

请求体：

```json
{
  "title": "周报",
  "workspaceId": "ws_001",
  "templateId": "tpl_weekly_001"
}
```

### 4.16 `PATCH /api/office/documents/:documentId`

用途：更新文档内容或元信息。

允许字段：

- `title`
- `content`
- `summary`

说明：

- 真正更新时应创建新修订，而不是直接覆盖历史

### 4.17 `POST /api/office/documents/:documentId/export`

用途：导出正式文档。

请求体：

```json
{
  "format": "pdf"
}
```

响应示例：

```json
{
  "taskId": "task_export_001"
}
```

### 4.18 `GET /api/office/document-templates`

用途：列出可用 `doct` 模板。

### 4.19 `GET /api/office/ops/targets`

用途：列出运维目标。

### 4.20 `POST /api/office/ops/targets`

用途：创建运维目标。

请求体示例一：SSH

```json
{
  "kind": "ssh_host",
  "displayName": "生产机 01",
  "environment": "prod",
  "config": {
    "host": "10.0.0.1",
    "port": 22,
    "username": "deploy"
  },
  "credentialRef": "cred_ssh_prod_001"
}
```

请求体示例二：控制台

```json
{
  "kind": "web_console",
  "displayName": "云控制台",
  "environment": "prod",
  "config": {
    "baseUrl": "https://console.example.com"
  },
  "credentialRef": "cred_console_001"
}
```

### 4.21 `POST /api/office/ops/ssh/tasks`

用途：创建 SSH 运维任务。

请求体：

```json
{
  "title": "检查磁盘使用率",
  "targetId": "ops_ssh_001",
  "riskLevel": "medium",
  "input": {
    "command": "df -h",
    "timeoutSeconds": 30
  }
}
```

### 4.22 `POST /api/office/ops/browser/tasks`

用途：创建浏览器运维任务。

请求体：

```json
{
  "title": "登录控制台重启实例",
  "targetId": "ops_console_001",
  "riskLevel": "high",
  "profileId": "bp_001",
  "input": {
    "actions": [
      { "type": "goto", "url": "https://console.example.com" },
      { "type": "click", "selector": "[data-action='restart']" }
    ]
  }
}
```

### 4.23 `GET /api/office/workflows`

用途：列出自动化工作流。

### 4.24 `POST /api/office/workflows`

用途：创建工作流。

请求体：

```json
{
  "title": "每天汇总日报并导出 PDF",
  "trigger": {
    "type": "cron",
    "cronHour": 18,
    "cronMinute": 0
  },
  "steps": [
    { "type": "document.generate", "templateId": "tpl_daily_001" },
    { "type": "document.export", "format": "pdf" }
  ]
}
```

### 4.25 `GET /api/office/connectors`

用途：列出连接器能力。

响应字段建议：

- `connectorKey`
- `kind`
- `displayName`
- `capabilities`
- `status`

## 5. 错误响应约定

建议统一沿用宿主端现有错误风格，至少保留：

```json
{
  "detail": "当前任务需要审批后才能继续",
  "error_code": "OFFICE_TASK_APPROVAL_REQUIRED",
  "timestamp": "2026-05-15T12:00:00.000Z"
}
```

第一阶段建议新增的典型错误码：

- `OFFICE_TASK_NOT_FOUND`
- `OFFICE_TASK_INVALID_STATUS`
- `OFFICE_TASK_APPROVAL_REQUIRED`
- `OFFICE_BROWSER_PROFILE_NOT_FOUND`
- `OFFICE_BROWSER_CDP_ATTACH_NOT_ALLOWED`
- `OFFICE_DOCUMENT_TEMPLATE_INVALID`
- `OFFICE_DOCUMENT_EXPORT_FAILED`
- `OFFICE_OPS_TARGET_NOT_FOUND`
- `OFFICE_OPS_PERMISSION_DENIED`
- `OFFICE_CONNECTOR_DISABLED`
