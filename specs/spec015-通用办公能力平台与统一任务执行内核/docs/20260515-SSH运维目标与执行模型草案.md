# spec015 SSH 运维目标与执行模型草案

状态：Draft

## 1. 目标

这份草案只解决一件事：

把 SSH 运维从“直接执行一条命令”变成“有目标、有凭据、有审计、有回滚”的正式模型。

一句话版本：

**SSH 运维不是裸命令，它是一类受控任务。**

## 2. 核心原则

### 2.1 命令不是主对象

主对象应该是：

- 运维目标
- 凭据引用
- 执行任务
- 审计记录
- 回滚记录

命令只是任务输入，不是平台核心。

### 2.2 先参数化，再执行

SSH 命令不能靠一坨自由文本直接拼接。

至少要拆成：

- 主机目标
- 环境
- 执行用户
- 命令模板
- 参数
- 期望结果

### 2.3 高风险默认要审批

只要命令可能改配置、停服务、删文件、重启机器，就不要当普通命令跑。

## 3. 运维目标对象

### 3.1 `OpsTarget`

`OpsTarget` 是平台里正式的运维目标对象。

它回答的是：

- 连哪台机器
- 用什么环境
- 归谁管
- 能不能执行

建议最少字段：

- `id`
- `userId`
- `kind`
- `displayName`
- `environment`
- `host`
- `port`
- `username`
- `credentialRef`
- `configJson`
- `status`
- `createdAt`
- `updatedAt`

### 3.2 目标分类

第一阶段先只做两类：

- `ssh_host`
- `web_console`

SSH 这边先专心把主机、环境和凭据管理好，不要一开始就贪多。

## 4. 凭据模型

### 4.1 凭据不要明文散落

凭据必须用引用，不要直接把私钥或密码塞进任务输入里。

### 4.2 `credentialRef`

`credentialRef` 至少要能指向：

- SSH 私钥
- SSH 密码
- 跳板机凭据
- 只读账号

### 4.3 凭据访问规则

至少要支持：

- 只读查看引用
- 执行时临时取用
- 任务结束后不把明文继续挂在对象上

## 5. SSH 执行模型

### 5.1 `SSHRunRequest`

建议最少字段：

- `targetId`
- `commandTemplate`
- `args`
- `workingDirectory`
- `timeoutMs`
- `riskLevel`
- `dryRun`
- `approvalPolicyId`

### 5.2 `SSHRunResult`

建议最少字段：

- `exitCode`
- `stdoutSummary`
- `stderrSummary`
- `startedAt`
- `finishedAt`
- `artifactIds`
- `rolledBack`

### 5.3 运行流程

1. 选择 `OpsTarget`
2. 读取凭据引用
3. 判断风险等级
4. 需要的话先走审批
5. 创建统一任务和步骤
6. 执行 SSH 命令
7. 记录输出摘要和产物
8. 失败时记录审计和回滚信息

## 6. 输出和产物

SSH 执行后至少要留：

- 命令摘要
- 退出码
- 输出摘要
- 错误摘要
- 日志产物

不要把整个终端会话当审计主体。

## 7. 风险规则

### 7.1 默认高风险动作

以下动作默认应按高风险处理：

- 重启服务
- 修改配置
- 删除文件
- 改权限
- 改用户
- 影响外部可用性的命令

### 7.2 风险不足时不要硬跑

如果系统无法判断命令风险，宁可要求人工确认，也不要默认放行。

## 8. 服务边界

### 8.1 `ops-target-service`

职责：

- 创建和维护运维目标
- 读取目标元数据
- 管理目标状态

### 8.2 `ops-credential-service`

职责：

- 管理凭据引用
- 提供执行时取用接口
- 避免明文泄漏

### 8.3 `ssh-run-service`

职责：

- 执行参数化 SSH 命令
- 记录命令结果
- 生成任务产物

### 8.4 `ops-risk-policy-service`

职责：

- 判断命令风险
- 决定是否需要审批
- 给权限服务提供判定输入

## 9. 最容易做烂的地方

1. 把 SSH 运维做成裸 shell
2. 把密码直接塞进任务输入
3. 把命令执行当成日志打印
4. 没有任务对象就直接跑
5. 失败后没有回滚和审计
