# spec015 浏览器 Profile、标签页、产物和失败重试草案

状态：Draft

## 1. 目标

这份草案只解决一件事：

把浏览器运行时里的四个最容易做乱的东西说死：

1. Profile 怎么隔离
2. 标签页怎么管理
3. 产物怎么挂回任务
4. 失败怎么重试

一句话版本：

**浏览器任务不是一条脚本，而是一个可回放、可重试、可追踪的运行过程。**

## 2. Profile 规则

### 2.1 默认必须隔离

第一阶段默认规则：

- 每个用户或工作区都可以有自己的 Profile
- 每个浏览器任务优先复用所属 Profile
- 不允许默认落到用户日常浏览器目录

### 2.2 Profile 不是一次性临时参数

Profile 是正式对象，不是启动参数。

它要能回答：

- 谁拥有它
- 属于哪个工作区
- 用的是 Chrome 还是 Edge
- 是持久化还是 CDP 接管
- 当前是否可用

### 2.3 Profile 锁定

如果某个 Profile 正在被任务占用，平台应该能看到：

- 谁在用
- 什么时候开始
- 什么时候释放

不要让两个任务同时抢一个 Profile。

## 3. 标签页规则

### 3.1 标签页是正式对象

标签页不是临时变量。  
它应该至少能表示：

- 当前 URL
- 当前状态
- 最近一次动作
- 是否活动页

### 3.2 一个任务可以有多个标签页

允许：

- 多个页面并行打开
- 一个活动页
- 其他页面挂起

但所有页面都要能追到同一个运行时会话。

### 3.3 标签页生命周期

建议状态：

- `opening`
- `active`
- `idle`
- `blocked`
- `closed`

### 3.4 页面切换要留痕

如果任务切换了活动页，平台必须记录：

- 从哪个页面切到哪个页面
- 切换时间
- 切换原因

## 4. 产物规则

### 4.1 产物类型

第一阶段至少支持：

- `screenshot`
- `ocr_result`
- `downloaded_file`
- `dom_snapshot`
- `custom`

### 4.2 产物必须挂回步骤

产物不能只挂任务不挂步骤。  
因为后面排障时，最有用的是“哪一步产了什么”。

### 4.3 产物引用关系

建议规则：

- 截图可以引用对应 DOM 快照
- OCR 结果可以引用对应截图
- 下载文件可以引用触发下载的动作

## 5. 失败与重试规则

### 5.1 失败分类

建议先分成三类：

1. 可重试网络失败
2. 结构变化或权限失败
3. 人工介入失败

### 5.2 可重试的条件

可以重试的情况：

- 临时网络抖动
- 页面短暂未就绪
- 浏览器实例短暂失联

不该无限重试的情况：

- 登录态失效
- 权限拒绝
- 页面结构根本变了

### 5.3 重试要保存什么

每次重试必须保存：

- 重试前失败原因
- 重试次数
- 关联步骤
- 最终结果

### 5.4 失败重试不是重跑整个任务

默认不应该整任务无脑重跑。  
优先从失败步骤继续，除非该任务明确要求从头再来。

## 6. 与任务模型的关系

### 6.1 任务层

浏览器任务最终还是 `OfficeTask`。

### 6.2 步骤层

每个页面动作或关键操作尽量落成 `OfficeTaskStep`。

### 6.3 产物层

截图、OCR、下载和 DOM 快照都挂到 `OfficeArtifact`。

### 6.4 回执层

任务结束后，平台要给出明确回执：

- 成功
- 失败
- 需要人工介入

## 7. 最容易做烂的地方

1. 把 Profile 当普通字符串
2. 把标签页当数组项
3. 把截图和下载当临时文件不登记
4. 失败后整任务重跑
5. 重试时不保留失败上下文
