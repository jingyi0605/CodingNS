# spec016.5-事务工作台画布化与插件块布局

## 这份 Spec 现在解决什么问题

事务视图已经有文档库、对话、代办、自动化这些入口，但它还是“切页面”，不是“工作台”。

现在先把骨架定死，避免后面越做越乱：

- 左侧一级入口里，代办和自动化合并成一个正式“工作台”
- 左侧导航栏在任何情况下都默认显示
- 事务视图默认**没有右侧常驻边栏**
- 中间区域和原来的右侧区域并成一整块工作台画布
- 画布顶部固定是标签工具栏
- 左侧菜单下方固定保留一条“快捷应用栏”
- 快捷应用栏允许把工作区里的静态 HTML 文件挂进去，作为常用应用入口

一句人话：

这次不是再加一个页面，而是先把事务视图改成“左栏默认显示 + 左下固定应用栏 + 右侧按分区切换的主舞台”的正式骨架。

## 这次计划覆盖什么

- 把左侧“代办”“自动化”收口成“工作台”
- 明确事务视图默认不再常驻右侧详情/助手栏
- 把原本中间区和右侧区合成完整画布区
- 工作台顶部支持多个标签页切换
- 画布支持块式布局，后续把代办、自动化、HTML 插件都接进去
- 左侧固定快捷应用栏支持静态 HTML 应用入口
- 区分三类 HTML 能力：
  - 左侧固定快捷应用
  - 画布里的 HTML 块
  - 普通 HTML 文件预览

## 这次明确不做什么

- 不把事务视图拆成独立新应用
- 不在这一轮做多人协同布局
- 不把普通 HTML 预览页直接当高权限插件块
- 不在这一轮做万能低代码编排器
- 不把右侧详情/助手栏继续当默认常驻结构
  - 如果以后还需要详情或助手，应该单独定义成可打开的浮层、抽屉或临时面板

## 为什么现在要先锁骨架

因为骨架如果不先定死，后面一定会长成垃圾：

- 左侧文案虽然改成“工作台”，底层却还在跑 `todo | automation`
- 画布只占中间一小块，右边继续挂旧详情栏，布局永远拧巴
- 静态 HTML 快捷应用既想放画布里，又想塞侧栏里，最后状态模型一团乱
- 顶部标签页只是视觉切换，没有正式状态和持久化

## 这次的硬边界

### 1. 左侧导航默认显示

事务视图进入时，左侧导航应该直接可见，不需要先展开。

### 2. 右侧边栏按分区切换

- 文档视图：右侧详情栏默认显示，而且必须能看到对象详情
- 对话视图：默认不显示右侧栏
- 工作台视图：默认不显示右侧栏

### 3. 顶部标签栏属于整块画布，不属于中间某一列

标签栏是整张工作台的顶栏。后面不允许再把它缩回“中间主区标题栏”。

### 4. 左侧快捷应用栏是固定区，不是普通画布块

静态 HTML 快捷应用先作为左侧固定入口存在。它和画布里的 HTML 块不是一回事，别混。

### 5. 普通 HTML 文件预览不等于工作台插件

文件预览还是文件预览。只有被系统接纳为快捷应用或插件来源的 HTML，才能进固定应用栏或画布块。
