# 需求文档 - spec003.7 会话级模型与配置选择持久化

状态：In Progress

## 1. 背景

会话页的模型下拉框当前把选择写进账号级 `defaultModel`。因此用户在 A 会话改模型后，B 会话没有自己的选择时会读取这个新默认值，表现为 A 会话改动了 B 会话的下次对话。

`spec003.6` 已经让发送过消息的会话保存了 `cc-switch` preset 绑定，但“用户刚刚选了什么”仍然没有一条单独、可立即保存的会话级状态。刷新、切换会话或尚未发送下一条消息时，页面不能可靠恢复这次选择。

这不是下拉框显示问题。模型和配置文件的归属层级错了：账号默认值只能给新会话兜底，已经存在的会话必须有自己的选择。

## 2. 目标

1. 每个已有会话独立保存模型选择和配置文件选择。
2. 用户在 A 会话改模型或 preset 后，切换到 B 会话不会改变 B 的选择。
3. 页面刷新、应用重启、会话恢复后，选择器恢复该会话最后保存的值。
4. 发送、排队发送、继续会话仍使用该会话选择；显式发送参数优先级保持不变。
5. 新会话和历史会话没有会话级选择时，继续使用现有账号默认模型与全局配置文件，不破坏已有用户空间。

## 3. 非目标

- 不改设置页中“账号默认模型”的用途；它仍是新会话和未保存会话的兜底值。
- 不新增、编辑或删除 `cc-switch` preset。
- 不在正在执行的 run 中途替换模型或配置文件；新选择只用于后续消息。
- 不扩展 reasoning level、权限模式等其他 composer 选项的持久化范围。

## 4. 术语说明

- **会话级选择**：绑定到一个 `sessionId` 的模型与配置文件选择。
- **账号默认模型**：账号偏好中的 `defaultModel`，仅在会话没有显式选择时作为初始兜底。
- **配置文件选择**：当前为 `providerConfigMode` 和 `providerPresetId`，分别表示全局默认配置或一条 `cc-switch` preset。
- **未指定模型**：会话不强制传入模型，运行时沿用 provider 或 preset 的默认模型。

## 5. 功能需求

### 需求 1：会话必须独立保存模型选择

**用户故事：** 作为同时使用多个模型的用户，我希望每个会话记住自己的模型，以便 A 会话改模型不会影响 B 会话。

#### 验收标准

1. WHEN 用户在已存在的会话选择一个模型 THEN System SHALL 将该模型与该 `sessionId` 保存，并立即更新会话摘要。
2. WHEN 用户先后为 A、B 两个会话选择不同模型 THEN System SHALL 在重新打开任一会话时恢复它自己的模型。
3. WHEN 用户选择“使用默认模型” THEN System SHALL 保存空模型选择，后续运行由 provider 或 preset 默认值决定。
4. WHEN 历史会话没有模型选择 THEN System SHALL 保持账号默认模型的现有兜底行为。

### 需求 2：会话必须独立保存配置文件选择

**用户故事：** 作为需要并行使用多个配置文件的用户，我希望选择 preset 后立刻属于当前会话，以便未发送下一条消息时也不会丢失选择。

#### 验收标准

1. WHEN 用户在已存在的会话选择全局默认配置或一条 `cc-switch` preset THEN System SHALL 将合法选择保存到该会话。
2. WHEN 用户切换会话或刷新页面 THEN System SHALL 从会话摘要恢复对应的配置文件选择。
3. WHEN 用户选择 preset 后发送下一条消息 THEN System SHALL 使用该 preset 对应的会话运行上下文。
4. WHEN preset 已被删除或不再可用 THEN System SHALL 保留会话记录，并在现有配置校验路径中给出可理解的错误，不得回退并改写为其他会话的配置。

### 需求 3：保存入口必须安全且不破坏运行中会话

**用户故事：** 作为维护者，我希望一次选择保存只影响目标会话的后续消息，以便并发运行和其他会话不受影响。

#### 验收标准

1. WHEN 客户端保存会话级选择 THEN System SHALL 校验会话归属和配置文件字段的合法性。
2. WHEN 保存成功 THEN System SHALL 返回最新会话摘要，供导航和页面状态同步使用。
3. WHEN 会话当前有活动 run THEN System SHALL 不修改该 run 的参数；新选择仅影响后续 send 或 queue dispatch。
4. WHEN 保存请求失败 THEN System SHALL 保留用户当前可见选择，并显示错误；不得静默改写账号默认模型。

## 6. 非功能需求

### 6.1 兼容性

1. 旧数据库启动时必须通过增量 schema 迁移补齐字段，不要求导出或重建数据库。
2. 旧会话缺少字段时必须被解释为“未指定模型 + 全局默认配置”。

### 6.2 一致性

1. 选择保存后，接口响应、导航摘要和下次加载的会话详情必须返回同一组值。
2. 多次快速选择时，以服务端最后成功保存的请求为准；客户端不得把旧响应覆盖成新选择。

### 6.3 可维护性

1. 模型与 preset 使用同一个会话绑定记录，不新建并行的本地存储或私有缓存。
2. 测试必须覆盖 A/B 两会话隔离、旧会话回退和运行中不影响当前 run 三条主线。

## 7. 成功定义

- A 与 B 会话可保存并恢复不同的模型和 preset。
- 模型下拉框不再写入账号级 `defaultModel`。
- 相关 Host 与 user-app 定向测试通过，且没有新增 `node:sqlite` 使用。
