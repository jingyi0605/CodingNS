# 统一更新机制验收记录

## 这份记录是干什么的

这份文档只记录 `spec001.6` 现在已经验过什么，哪些结果已经能当交付结论用。

## 验收范围

这次验收覆盖三条链路：

1. 桌面端官方 updater
2. Android `APK` 直装更新
3. 服务端全局 npm 包升级

## 已完成的验收结果

### 1. 桌面端

确认结果：

- 桌面端 Rust 更新逻辑已切到 `tauri-plugin-updater`
- 设置页可以手动检查和安装更新
- 应用启动后会在桌面端自动检查一次更新
- 如果检测到新版本，会发系统通知

已验证：

- `cargo check`：`apps/desktop/src-tauri`
- `pnpm --dir apps/user-app exec vitest run src/app/DesktopAutoUpdateEffect.test.tsx`
- `pnpm --dir apps/user-app exec vitest run src/settings/ReleasePanel.test.tsx`

### 2. Android

确认结果：

- Android 可以读取 `android-apk` 清单
- 可以下载 APK、校验 `sha256`、校验包名和 `versionCode`
- 可以拉起系统安装器
- 缺权限时会给出明确引导
- 用户回到应用后，如果版本没变，会显示“安装已取消或未完成，可重新触发安装”
- 校验失败时会清理坏 APK

已验证：

- `cargo check`：`apps/user-app/src-tauri`
- `pnpm --dir apps/user-app exec vitest run src/settings/AndroidReleasePanel.test.tsx`
- `pnpm --dir apps/user-app exec vitest run src/features/settings/pages/SettingsPage.test.tsx`

### 3. 服务端

确认结果：

- 可以检查受管 npm 包是否有更新
- 可以点击触发全局升级后台任务
- 可以轮询任务状态
- 升级成功后会明确提示“需要重启”

已验证：

- `pnpm --dir apps/host exec vitest run tests/integration/client-routes.test.ts`
- `pnpm --dir apps/user-app exec vitest run src/settings/ServiceUpdatePanel.test.tsx`

## 设置页验收结果

确认结果：

- Web/H5 只显示服务端更新
- 桌面端显示服务端更新和桌面客户端更新
- Android 显示服务端更新和 Android `APK` 更新
- iOS 明确显示“当前不支持安装更新”，不伪造安装按钮

已验证：

- `pnpm --dir apps/user-app exec vitest run src/features/settings/pages/SettingsPage.test.tsx`

## 当前仍保留的真实边界

1. Android 的“取消安装”不是系统显式回调，而是应用回到前台后的结果推断。
2. 服务端升级成功后仍需要人工重启 Host，第一版不做 supervisor 自动控制。
3. 桌面端 `beta` 通道目前仍复用 `stable` 的 `latest.json` 发布地址，后续如果真做 beta，需要独立元数据源。

## 结论

`spec001.6` 这一轮已经把“客户端与服务端统一更新机制”从半成品状态收口到可交付状态：

- 有统一设置页入口
- 三条链路都能跑通
- 失败状态能解释
- 关键系统边界没有被故意说成“已自动完成”
