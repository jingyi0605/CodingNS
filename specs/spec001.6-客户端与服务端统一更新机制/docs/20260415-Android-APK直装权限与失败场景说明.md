# Android APK 直装权限与失败场景说明

## 这份说明是干什么的

这份文档只回答 Android `APK` 直装里最容易说不清的几件事：

- 哪些步骤是应用自己能做的
- 哪些步骤一定要交给 Android 系统安装器
- 缺权限、校验失败、用户取消安装时，现在到底会发生什么

## 先把边界说死

Android 这条链路现在做到的是：

1. 检查新版 `APK` 清单
2. 下载 APK 到应用私有缓存目录
3. 校验 `sha256`
4. 校验包名和 `versionCode`
5. 拉起系统安装器
6. 用户回到应用后，按当前版本结果推断“已安装”还是“已取消/未完成”

没有做到的事也要说清楚：

- 没有静默安装
- 没有绕过系统安装确认
- 没有直接拿到 Android 官方“用户点击了取消”回调

现在的“取消安装”状态，是**应用在拉起安装器后，等用户回到前台，再根据当前版本是否变化做结果推断**。

这不是完美方案，但它是第一版里最简单、最不撒谎的方案。

## 现在的状态流转

1. 用户在设置页点击“检查客户端”
2. 应用读取 `android-apk` 发布清单
3. 若 `manifest.versionCode > current.versionCode`，显示“发现新版本”
4. 用户点击“安装更新”
5. 应用下载 APK，并在本地完成校验
6. 校验通过后，交给系统安装器
7. 用户回到应用后：
   - 如果当前 `versionCode` 已经变成目标版本，界面显示“已检测到新版本完成安装”
   - 如果当前 `versionCode` 还是旧版本，界面显示“安装已取消或未完成，可重新触发安装”

## 各种异常现在怎么处理

### 1. 未知来源安装权限没开

当前行为：

- 应用先打开系统的“允许此来源安装应用”页面
- 设置页显示“请先允许当前应用安装未知来源应用”
- 用户授权后，可以回到设置页重新点击安装

明确不做：

- 不在权限没开时假装“已经开始安装”

### 2. APK 下载失败

当前行为：

- 安装流程直接失败
- 设置页保留失败摘要
- 用户可以重新点击安装

### 3. `sha256` 校验失败

当前行为：

- 安装流程直接失败
- 坏 APK 会从缓存目录删除
- 不允许把校验失败的包继续交给系统安装器

### 4. APK 包名或 `versionCode` 不匹配

当前行为：

- 安装流程直接失败
- 错误会明确指出字段不匹配
- 当前下载文件同样会被清理，避免下次误用

### 5. 用户在系统安装器里取消

当前行为：

- 系统安装器关闭后，用户重新回到应用
- 应用重新检查当前版本
- 如果版本还是旧的，就写成“安装已取消或未完成，可重新触发安装”

这里要诚实：

- 这一步不是 Android 明确告诉我们“用户点了取消”
- 是我们根据“应用回来了，但版本没变”做的结果推断

## 缓存目录约定

APK 下载缓存目录现在固定在应用私有缓存下的：

- `updates/`

对应的 `FileProvider` 也只开放这一个子目录，避免把整个缓存目录都暴露出去。

## 当前还保留的系统边界

下面这些东西，第一版就是拿不到可靠控制权：

- 用户在系统安装器页面里停留多久
- 用户最终点击“安装”还是“取消”
- 安装完成后系统是否立刻回到当前应用

所以设置页只承诺“检查、下载、校验、拉起安装器、回到应用后给出结果推断”，不承诺“自动装完并回传成功回调”。
