# 需求文档 - spec004-文件上下文能力

状态：Draft

## 简介

这个 Spec 要解决的是一个很实际的问题：
用户在对话里提到“看下这个文件”“改这里”，系统必须真的能在工作区里稳定地找文件、读文件、改文件，并把文件作为会话上下文挂上去。

这件事如果不先定好边界，后面会很快烂掉，常见烂法有三种：

- 文件操作越权，跑到工作区外面去读写
- 文件上下文和会话消息混成一坨，最后谁是真相都说不清
- 想一步做成网页版 IDE，结果把核心流程拖死

本 Spec 的目标很明确：把“文件作为上下文能力”做稳，不做重型 IDE。

## 术语表

- **System**：`码不能停` 的 Host + 客户端整体系统
- **Workspace Root（工作区根目录）**：允许文件操作的根路径边界
- **File Context Binding（文件上下文挂载）**：把某个文件或文件片段挂到会话上下文中的关系记录
- **Path Traversal（路径穿越）**：通过 `../` 等路径逃逸访问工作区外文件的行为
- **Recent Files（最近打开）**：按用户在工作区内打开时间排序的文件记录
- **Preview（预览）**：按文件类型进行的只读展示，不等于完整编辑器能力

## 范围说明

### In Scope

- 文件树浏览
- 文件读取、保存、创建、删除、重命名、移动
- 搜索、筛选、最近打开
- 文件预览与基础编辑
- 文件与会话的上下文挂载关系
- 工作区白名单边界校验与鉴权保护

### Out of Scope

- 重型 IDE 编辑能力（LSP、断点调试、复杂重构等）
- 复杂协同编辑与多人冲突解决
- 脱离工作区边界的任意路径访问
- 把文件上下文能力做成“第二套会话消息真相”

## 需求

### 需求 1：所有文件操作必须受工作区边界和鉴权保护

**用户故事：** 作为系统管理员，我希望任何文件请求都不能越过工作区边界，且未登录用户不能访问文件数据，以便系统不会出现裸奔和越权读写。

#### 验收标准

1. WHEN 客户端请求任意文件操作 THEN System SHALL 先校验登录态和工作区权限。
2. WHEN 请求路径不在工作区白名单根目录内 THEN System SHALL 拒绝并返回边界错误。
3. WHEN 请求包含路径穿越模式（如 `../`） THEN System SHALL 拒绝并记录安全日志。

### 需求 2：文件树和基础文件操作必须可用

**用户故事：** 作为开发者，我希望能在工作区内稳定浏览并操作文件，以便不离开会话主界面也能完成日常改动。

#### 验收标准

1. WHEN 用户进入文件面板 THEN System SHALL 返回可展开的文件树结构（含目录和文件元信息）。
2. WHEN 用户执行读取、保存、创建、删除、重命名、移动 THEN System SHALL 在工作区范围内完成操作并返回明确结果。
3. WHEN 文件操作失败 THEN System SHALL 返回可读错误码和错误原因，不允许静默失败。

### 需求 3：搜索、最近打开、预览必须覆盖核心场景

**用户故事：** 作为高频用户，我希望快速定位文件并查看内容，以便减少在目录树里来回翻找的时间。

#### 验收标准

1. WHEN 用户输入搜索关键词 THEN System SHALL 支持按文件名和路径搜索并返回分页结果。
2. WHEN 用户打开文件 THEN System SHALL 更新最近打开记录，并按时间排序可查询。
3. WHEN 用户查看文件 THEN System SHALL 提供预览能力，并对不支持预览的类型给出明确提示。

### 需求 4：基础编辑能力必须稳定且有最小冲突保护

**用户故事：** 作为开发者，我希望基础编辑可用且不会轻易覆盖他人或系统刚修改的内容，以便减少误操作造成的数据损坏。

#### 验收标准

1. WHEN 用户保存文件 THEN System SHALL 支持基础文本保存并返回最新版本信息。
2. WHEN 文件在保存前已被外部修改 THEN System SHALL 给出冲突错误或版本不一致提示。
3. WHEN 保存请求内容非法（如超限、编码不支持） THEN System SHALL 拒绝并返回校验错误。

### 需求 5：文件上下文挂载必须与 spec003 会话运行时对接

**用户故事：** 作为会话用户，我希望把文件或片段挂到当前会话上下文，以便 AI 在正确上下文里回答和执行。

#### 验收标准

1. WHEN 用户在会话中挂载文件上下文 THEN System SHALL 记录 `sessionId + filePath + range/hash` 的绑定关系。
2. WHEN 会话页请求上下文列表 THEN System SHALL 返回当前会话的文件上下文绑定记录和状态。
3. WHEN 文件上下文被移除 THEN System SHALL 更新绑定关系并同步到会话运行时展示。

### 需求 6：文件上下文不能伪造或覆盖会话消息真相

**用户故事：** 作为系统维护者，我希望文件上下文只是会话辅助信息，不会篡改会话消息来源，以便和 spec002/spec003 的单一真相原则保持一致。

#### 验收标准

1. WHEN 系统挂载文件上下文 THEN System SHALL 只保存上下文绑定元数据，不复制成新的会话原始消息仓库。
2. WHEN 会话展示消息 THEN System SHALL 继续以 provider/Host 的消息链路为准，不以文件上下文替代消息真相。
3. WHEN 需要追溯上下文来源 THEN System SHALL 能定位到具体文件路径、范围和版本标识。

### 需求 7：API 边界必须清晰且默认受保护

**用户故事：** 作为前端与客户端开发者，我希望文件相关接口边界明确，以便联调时不猜测哪些接口可用、哪些受保护。

#### 验收标准

1. WHEN 定义文件相关接口 THEN System SHALL 统一挂在受保护 API 域下，不开放匿名访问。
2. WHEN 新增文件操作接口 THEN System SHALL 默认继承鉴权和工作区边界校验，不允许绕过。
3. WHEN 返回文件操作结果 THEN System SHALL 使用统一错误格式和错误码命名规则。

## 非功能需求

### 非功能需求 1：性能

1. WHEN 用户展开中等规模工作区文件树 THEN System SHALL 在可接受时延内返回首屏节点（目标 P95 < 1s）。
2. WHEN 用户进行文件名/路径搜索 THEN System SHALL 在可接受时延内返回分页结果（目标 P95 < 2s）。

### 非功能需求 2：可靠性

1. WHEN Host 重启后 THEN System SHALL 保持最近打开和文件上下文绑定数据可恢复。
2. WHEN 文件操作失败 THEN System SHALL 保证不产生半成功脏状态（例如已改名但索引未更新）。

### 非功能需求 3：可维护性

1. WHEN 后续扩展移动端文件轻操作 THEN System SHALL 复用本 Spec 的文件 API 和上下文绑定模型。
2. WHEN 排查文件相关问题 THEN System SHALL 能从日志中定位 workspace、path、session 和操作类型。

### 非功能需求 4：安全性

1. WHEN 任意文件请求进入服务端 THEN System SHALL 执行鉴权、路径规范化和边界校验三步检查。
2. WHEN 请求试图访问工作区外路径 THEN System SHALL 拒绝访问并记录安全事件。

## 成功定义

- 用户可以在受保护会话内完成“找文件、看文件、改文件、挂上下文”主流程。
- 文件能力保持在“上下文工具”定位，不演化成重型 IDE。
- 文件上下文与会话运行时对接完成，但不破坏“会话消息真相只有一个来源”原则。
- 文件相关接口边界明确，未授权和越界请求都能稳定拒绝。
