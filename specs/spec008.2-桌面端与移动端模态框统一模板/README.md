# spec008.2-桌面端与移动端模态框统一模板

## 当前定位

这个子 Spec 只解决一件事：

- 把 `apps/user-app` 里桌面端模态框和移动端 sheet 收成两套统一、可复用、可迁移的基础模板

它不接受下面这些偷懒做法：

- 继续每个弹窗自己写一套 `portal + backdrop + card + footer`
- 继续靠业务 `className` 临时补宽度、补高度、补滚动
- 继续让移动端 action sheet、form sheet、picker sheet 各长各的 DOM 结构
- 顺手重做整站视觉风格，把问题从“模态框混乱”升级成“全站返工”
- 一口气把所有历史弹窗重写完，最后把主流程一起搞崩

一句人话：
先把“弹窗”这件事收成规矩。桌面端一套，移动端一套，尺寸、布局、按钮区、表单区、列表区都固定下来，后面业务弹窗直接选模板，不再重复手搓。

## 计划覆盖

- 桌面端统一模态框基础组件
- 移动端统一 sheet 基础组件
- 固定尺寸档位、固定高度档位、固定布局类型
- 模态框里的按钮、字段、标签、列表、空态等基础模板
- 对现有 `WorkbenchModal` 的兼容和迁移路径
- 首批代表性弹窗迁移清单
- 模态框新增开发规则和回归验证要求

## 本阶段明确不做

- 不重做整站设计系统
- 不在这次把所有历史弹窗一次性推倒重来
- 不新长一套和现有按钮、输入框完全平行的“第三套控件库”
- 不把文件查看器、工作台多窗口、移动端导航这些问题混进来一起做
- 不允许为了一个特殊弹窗再发明新的基础壳
