## 3. 新增弹层的硬规则

### 3.1 壳层规则

- 桌面端新增弹窗默认必须使用 `DesktopModal`
- 移动端新增 sheet 默认必须使用 `MobileSheet`
- 不允许在业务代码里再直接写 `workbench-modal-layer`
- 不允许在业务代码里再直接写 `ios-action-sheet-overlay`

### 3.2 尺寸和布局规则

- 桌面端普通模态框默认统一走“约 60% 浏览器宽度，低分辨率自动增大占比”的规则
- `narrow / compact / regular / wide / xwide` 现在不再继续拉开一堆不同百分比，它们在标准弹窗上统一宽度语义
- `full` 仍然保留给查看器和大型工作面板
- 移动端高度只能从 `auto / half / three-quarter / full` 里选
- 如果你想写“这次先临时 62%”，那就是没接模板，别自欺欺人

### 3.3 内容结构规则

- 字段区优先用 `ModalField`
- 分组说明和卡片区优先用 `ModalSection`
- 底部按钮区优先用 `ModalActions`
- 列表型内容优先用 `ModalList / ModalListItem`
- 空态优先用 `ModalEmptyState`
- 标签和状态 pill 优先用 `ModalTag`

### 3.4 视觉基线规则

- 模态框和通用操作按钮统一使用设置页按钮风格，不允许再长出一套“模态框专用按钮皮肤”
- 默认按钮使用设置页同款浅底、细边框和 hover 边框强调
- 危险按钮使用设置页同款浅红底、浅红边框和红色文本
- 模态框里的记录信息优先平铺展示，用分割线隔开，不要继续叠白底卡片
- 如果某个内容块非要保留独立底板，先问自己一句：这真是业务需要，还是网页风格残留

### 3.5 允许例外，但必须说人话

只有这两类情况允许偏离：

1. 查看器类大弹层，确实需要超出普通表单/列表的滚动和工具区模型
2. 业务上必须保持现有 DOM 结构，否则会直接破坏已有交互或测试

出现例外时，必须补三句话：

- 为什么不能直接用现有基础件
- 偏离的是壳层、尺寸，还是内部结构
- 后续准备怎么收回来
