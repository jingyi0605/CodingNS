# 迁移说明

这份文档回答的是：

- 从当前实现迁到目标实现，用户会看到什么变化
- 开发时哪些旧路径要退场

## 1. 用户能直接感知到的变化

### 1.1 结构变化

旧版思路：

- 手机上继续用桌面三栏的缩小版
- 左边是导航抽屉
- 右边是工具抽屉

新版思路：

- 手机上改成 `工作区 / 会话 / 工具 / 设置` 四个一级目的地
- 会话页保持消息沉浸
- 工具能力从右侧栏拆成工具流和全屏子页

### 1.2 操作变化

旧版：

- 一堆动作是小图标
- 返回和前进在侧栏头部
- 批量选择、新建会话、切换工作区并排塞在一起

新版：

- 主操作保留直达
- 次操作进菜单
- 批量动作进编辑模式
- 前进按钮退出手机主路径

## 2. 旧路径退场清单

下面这些内容后续要退出移动端主路径：

- 左侧抽屉作为一级导航
- 右侧抽屉作为工具入口
- 左右边缘手柄
- 手机上的前进常驻按钮
- 标题栏 icon cluster

注意：

- 这些路径退出的是移动端主流程
- 不代表桌面端必须删除

## 3. 桌面端保留清单

下面这些东西继续保留在桌面端：

- 三栏工作台
- 左侧导航
- 右侧辅助信息栏
- 面向桌面效率的密度更高的布局

也就是说：

- 这次迁移不是把桌面端变成移动端
- 是把移动端从桌面缩小版里救出来

## 4. 开发迁移顺序

推荐顺序：

1. 先引入平台和宽度等级模型
2. 再引入移动端独立壳
3. 再迁一级导航和页面骨架
4. 再迁动作和工具流
5. 最后清理旧移动端抽屉路径

## 5. 风险提示

如果后面开发时有人说：

- “先用左抽屉顶一下吧”
- “右侧栏先在手机上保留也没事”
- “这些小图标先不动”

那基本就是在往旧方案里退。

后面一旦退回去，再想收回来，代价只会更大。
