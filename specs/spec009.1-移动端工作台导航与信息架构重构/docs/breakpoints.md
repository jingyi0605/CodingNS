# 宽度分级说明

这份文档回答一个很实际的问题：

- 移动端工作台到底什么时候是单栏，什么时候可以上双区，什么时候可以接近桌面三栏

当前实现只有一个：

- `MOBILE_BREAKPOINT_PX = 720`

这太粗暴了，会把大屏手机、横屏、折叠屏、小平板全部混成一锅。

## 1. 目标宽度等级

建议统一为 3 档：

| 等级 | 建议范围 | 目标设备 |
| --- | --- | --- |
| `compact` | `< 768px` | 手机竖屏、普通紧凑宽度 WebView |
| `medium` | `768px - 1023px` | 横屏手机、小平板、折叠屏半展开 |
| `expanded` | `>= 1024px` | 平板、大平板、桌面 Web、桌面壳 |

## 2. 各等级布局策略

### 2.1 `compact`

原则：

- 单栏优先
- 详情页全屏
- 一级导航固定可见
- 不允许常驻双侧栏

适用页面：

- 工作区首页
- 会话索引页
- 会话详情页
- 工具首页
- 文件 / Git / 终端全屏页

### 2.2 `medium`

原则：

- 可以上双区，但不要直接回到桌面三栏
- 优先列表 + 详情
- 工具页允许主内容 + 辅助导航

适用布局：

- 工作区列表 + 当前工作区详情
- 会话列表 + 当前会话详情
- 文件列表 + 文件预览

### 2.3 `expanded`

原则：

- 允许回到桌面式双栏或三栏
- 但导航意图不能退回到“必须理解侧栏才能用”

适用布局：

- 工作区 / 会话 / 工具 三栏工作台
- 列表 + 主舞台 + 辅助面板

## 3. 页面级规则

| 页面 | compact | medium | expanded |
| --- | --- | --- | --- |
| 工作区首页 | 单栏卡片流 | 列表 + 详情 | 列表 + 详情 + 工具摘要 |
| 会话索引 | 单栏列表 | 列表 + 当前会话摘要 | 列表 + 会话舞台 |
| 会话详情 | 全屏消息流 | 消息流主区，可附带轻辅助区 | 可回到桌面主舞台 + 工具区 |
| 工具页 | 工具首页后再进入全屏子页 | 工具导航 + 主内容 | 主内容 + 辅助面板 |

## 4. 实现要求

后续实现里，至少要有一个统一模型，例如：

```ts
type ViewportClass = "compact" | "medium" | "expanded";
```

然后由壳层统一提供，不要每个页面自己乱写媒体查询判断。

## 5. 明确禁止

- 禁止继续只靠 `720px` 一个断点解决全部问题
- 禁止 `compact` 继续使用左右边缘手柄当主导航
- 禁止 `medium` 直接照抄桌面三栏
- 禁止 `expanded` 另起一套和移动端意图完全不同的路由

## 6. 验收口径

后续验收至少要覆盖：

1. 手机竖屏：`compact`
2. 手机横屏 / 折叠屏半展开：`medium`
3. 平板或宽窗口：`expanded`

只验一个手机宽度，等于没验。
