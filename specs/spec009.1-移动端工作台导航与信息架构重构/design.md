# 设计文档 - spec009.1 移动端工作台导航与信息架构重构

状态：Draft

## 1. 概述

### 1.1 目标

- 保留当前 PC 三栏工作台的完整业务能力
- 把移动端从“桌面侧栏抽屉版”改成“页面栈 + 工具流”
- 让 H5 移动端、iOS、Android 使用同一套业务真相，但分别按各自平台习惯呈现
- 为平板、折叠屏和更宽窗口预留回到双栏或三栏的路径

### 1.2 覆盖需求

- `requirements.md` 需求 1：完整功能，简化操作
- `requirements.md` 需求 2：三栏拆成移动端页面结构
- `requirements.md` 需求 3：H5 移动端最佳实践
- `requirements.md` 需求 4：iOS 交互模型
- `requirements.md` 需求 5：Android 交互模型
- `requirements.md` 需求 6：小图标改造
- `requirements.md` 需求 7：工具流接入
- `requirements.md` 需求 8：宽度等级自适应
- `requirements.md` 需求 9：不破坏桌面端

### 1.3 技术约束

- 继续复用现有 Host、现有领域能力和现有共享状态
- 前端只改 `apps/user-app`
- 当前移动端不能继续直接复用桌面 `WorkbenchLayout` 的结构假设
- 所有新增用户可见文案必须进 i18n 字典

### 1.4 当前实现诊断

当前实现已经暴露出几个明确问题：

1. `WorkbenchLayout` 用单一 `MOBILE_BREAKPOINT_PX = 720` 决定是否进入移动端，宽度模型太粗。
2. 移动端入口依赖 `mobileNavOpen`、`mobileInfoOpen` 和左右边缘手柄，本质仍是桌面双侧栏抽屉。
3. 左侧 `SidebarContent` 混着工作区、收藏、搜索、导入、克隆、批量选择、创建会话等多种职责，手机上入口密度太高。
4. 右侧 `WorkbenchInfoPanel` 继续把文件、Git、终端管理装进一个辅助栏，这在手机上会和主任务互相争位置。

一句人话：
现在的移动端不是没做，而是做成了桌面工作台的折叠版，这个方向本身就不对。

## 2. 信息架构

### 2.1 当前 PC 三栏到移动端的映射

| PC 区域 | 当前职责 | 移动端目标承载 |
| --- | --- | --- |
| 左侧导航栏 | 工作区、会话、收藏、搜索、导入/克隆、批量动作 | 工作区首页、会话页、搜索页、页面右上角菜单 |
| 中央主舞台 | 消息流、输入区、终端主内容 | 会话详情页、终端详情页全屏主舞台 |
| 右侧信息栏 | 文件、Git、终端管理等辅助能力 | 工具页、工作区详情 tab、会话内工具入口、全屏子页 |
| 头部/列表小图标 | 返回、前进、折叠、切换、批量、更多动作 | 顶部返回、底部一级导航、更多菜单、编辑模式、sheet |

### 2.2 移动端一级结构

紧凑宽度下采用 4 个一级目的地：

- `工作区`
- `会话`
- `工具`
- `设置`

这样做的原因很简单：

- `工作区` 负责空间和上下文
- `会话` 负责最近、收藏、跨工作区会话访问
- `工具` 负责文件、Git、终端、进程这些辅助能力
- `设置` 保持独立，不挤占主工作流

### 2.3 页面层级

#### 2.3.1 工作区页

职责：

- 展示工作区总览
- 进入工作区详情
- 提供导入、克隆、切换、创建会话入口

子路径：

- `工作区首页`
- `工作区详情页`

#### 2.3.2 会话页

职责：

- 展示最近会话、收藏会话、按工作区筛选的会话
- 进入会话详情页
- 承载重命名、收藏、归档等会话级操作

子路径：

- `会话索引页`
- `会话详情页`

#### 2.3.3 工具页

职责：

- 统一承载文件、Git、终端、进程、日志等辅助能力
- 根据当前工作区或当前会话确定上下文

子路径：

- `工具首页`
- `文件页`
- `Git 页`
- `终端页`
- `进程页`
- `日志页`

#### 2.3.4 设置页

职责：

- 承载客户端配置、主题、连接、版本、账号等配置能力

## 3. 平台导航模型

### 3.1 H5 移动端

导航模型：

- 底部固定一级导航
- 顶部页面标题栏
- 页面内搜索入口
- sheet / 弹层用于次操作

约束：

- 不伪装成 iOS 或 Android 原生样子
- 重点解决浏览器安全区、动态视口高度、键盘遮挡和滚动抖动
- 对浏览器返回保持兼容，但主流程不能只靠浏览器返回

### 3.2 iOS

导航模型：

- `Tab Bar` 承载一级目的地
- `Navigation Stack` 承载列表到详情
- `Sheet` / `Full Screen Modal` 承载次级任务和重操作

规则：

- 会话详情页以导航栏返回为主，保留系统手势返回
- 主操作放导航栏右侧或明显按钮
- 次操作进 `menu`、`context menu`、`action sheet`
- 不再依赖左右边缘拖手柄

### 3.3 Android

导航模型：

- `Bottom Navigation` 承载一级目的地
- `Top App Bar` 承载标题、搜索、更多
- `Bottom Sheet` / `Dialog` / 全屏目的地承载次级任务

规则：

- 系统返回和页面 back stack 一致
- 高频主操作可放 FAB 或 Top App Bar 主按钮
- 次操作放 overflow menu 或 bottom sheet
- 不与系统边缘返回手势冲突

## 4. 宽度等级与自适应

### 4.1 宽度等级

当前只用一个 `720px` 阈值，这不够。

目标改成 3 档：

| 等级 | 建议范围 | 布局策略 |
| --- | --- | --- |
| `compact` | `< 768px` | 单栏堆栈式 |
| `medium` | `768px - 1023px` | 列表 + 详情 或 主内容 + 辅助区 |
| `expanded` | `>= 1024px` | 双栏或三栏，可接近桌面结构 |

### 4.2 各等级布局

#### `compact`

- 只保留一个主内容区
- 一级导航固定可见
- 会话页和工具页默认全屏

#### `medium`

- 允许工作区列表 + 当前详情并列
- 允许会话列表 + 当前会话并列
- 工具页可采用主内容 + 辅助导航

#### `expanded`

- 允许复用桌面式工作台思路
- 但仍遵守移动端建立好的导航意图，不再回到“必须靠侧栏抽屉理解系统”

## 5. 页面设计

### 5.1 工作区首页

应该做什么：

- 展示工作区列表、最近活动、可恢复入口
- 提供导入工作区、克隆工作区、新建会话

不该做什么：

- 不在首页塞满文件、Git、终端面板
- 不把批量选择常驻在默认态

### 5.2 工作区详情页

应该做什么：

- 作为某个工作区的上下文页
- 承载 `会话 / 文件 / Git / 终端 / 进程` 的二级切换

不该做什么：

- 不让用户在这里同时背负全局导航和会话详情

### 5.3 会话详情页

应该做什么：

- 头部只保留返回、标题、状态、更多
- 中间保持消息沉浸
- 底部输入区固定
- 工具入口通过顶部按钮或输入区扩展入口进入

不该做什么：

- 不把文件树或 Git 侧栏常驻在会话页旁边
- 不再展示桌面折叠按钮、前进按钮、侧栏开关

### 5.4 工具页

应该做什么：

- 统一承载文件、Git、终端、进程、日志等辅助能力
- 允许从会话页或工作区页进入

不该做什么：

- 不再让用户先理解“右信息栏”这个桌面概念

### 5.5 终端与重操作页

规则：

- 进入输入密集、滚动密集、工具栏复杂的状态时，直接全屏
- 不要求用户在半屏抽屉里操作终端、diff 或日志过滤

## 6. 操作模型

### 6.1 动作分级

所有操作先分级，再决定放哪：

| 等级 | 说明 | 呈现方式 |
| --- | --- | --- |
| 主操作 | 高频、流程核心 | 直达按钮、FAB、导航栏主按钮 |
| 行内操作 | 与列表项强相关 | 行尾菜单、滑动动作、长按菜单 |
| 次操作 | 低频、不值得常驻 | 更多菜单、bottom sheet、action sheet |
| 风险操作 | 删除、归档、批量、高风险提交 | 独立确认流、编辑模式、确认弹层 |

### 6.2 当前桌面动作迁移矩阵

| 当前动作 | 当前位置 | 移动端改造 |
| --- | --- | --- |
| 导入工作区 | 左栏图标 | 工作区页右上更多菜单 |
| 克隆工作区 | 左栏图标 | 工作区页右上更多菜单 |
| 新建会话 | 工作区头部图标 | 工作区页主按钮；Android 可用 FAB |
| 切换工作区 | 工作区头部图标 | 工作区卡片点击进入；更多菜单放切换/设为当前 |
| 批量选择会话 | 工作区头部图标 | 会话页编辑模式入口 |
| 搜索 | 左栏段落按钮 | 顶部搜索入口或独立搜索页 |
| 收藏/归档/重命名会话 | 会话行尾更多按钮 | 行尾菜单、长按菜单、滑动动作 |
| 左右侧栏折叠 | 顶栏/边缘 | 移动端直接取消 |
| 返回/前进 | 左栏头部按钮 | 保留返回；取消常驻前进 |
| 文件/Git/终端切换 | 右栏 tab | 工具页 tab 或工作区详情二级切换 |

### 6.3 新的数据与组件边界

建议引入下列抽象：

#### `ViewportClass`

```ts
type ViewportClass = "compact" | "medium" | "expanded";
```

#### `MobileWorkbenchDestination`

```ts
type MobileWorkbenchDestination =
  | "workspaces"
  | "sessions"
  | "tools"
  | "settings";
```

#### `ActionPresentation`

```ts
type ActionPresentation =
  | "primary"
  | "icon"
  | "overflow"
  | "sheet"
  | "swipe"
  | "edit_mode";
```

## 7. 模块落点

建议新增或拆分的模块：

- `apps/user-app/src/features/mobile-shell/*`
- `apps/user-app/src/features/mobile-workspaces/*`
- `apps/user-app/src/features/mobile-sessions/*`
- `apps/user-app/src/features/mobile-tools/*`
- `apps/user-app/src/features/mobile-shared/*`

现有模块的处理：

- `WorkbenchLayout` 继续服务桌面端和大宽度布局
- 紧凑宽度不再直接复用 `WorkbenchLayout` 的双抽屉交互
- `ConversationPage`、文件、Git、终端、进程等业务能力继续复用现有运行时和接口

## 8. 迁移策略

### 8.1 先拆壳，再迁页

顺序必须是：

1. 先建立移动端壳和宽度等级模型
2. 再把工作区、会话、工具三个主域迁进去
3. 最后清理当前边缘手柄和移动端抽屉主路径

### 8.2 保持桌面端稳定

规则：

- 桌面端三栏工作台继续作为独立路径保留
- 平台差异和宽度差异收敛在壳层，不把桌面逻辑改烂

### 8.3 逐步替换

分三步走：

1. 新壳先能跑空骨架和路由
2. 逐页接入工作区、会话、工具
3. 旧移动端抽屉退场

## 9. 风险

### 9.1 最大风险

- 继续复用桌面 `WorkbenchLayout` 的结构，只在 CSS 上缝补

这条路会导致：

- 导航和页面职责继续混乱
- iOS / Android 手势冲突继续存在
- 小图标问题继续存在
- 后续每加一个能力都要在抽屉里再塞一块垃圾

### 9.2 规避方式

- 从信息架构层重排，不从样式层硬补
- 先定义一级导航和页面职责，再迁动作
- 明确区分主操作、次操作、风险操作
