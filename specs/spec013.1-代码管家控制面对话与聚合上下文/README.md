# spec013.1-代码管家控制面对话与聚合上下文

## 当前定位

这个子 Spec 只解决一件事：

- 把“代码管家”从一组项目管理接口，补成一个真正可对话、可汇总、可续接项目工作的控制面会话

它不接受下面这种偷懒方案：

- 直接拿某个项目会话冒充“管家聊天”
- 前端只加一个按钮，后端还是没有独立的管家控制会话
- 把项目、会话、记忆、巡视、验证几张表原样拼成 prompt，就当完成聚合

一句人话：
用户要的不是“再开一条项目对话”，而是一个知道全局情况、能解释现状、能接着推动项目的代码管家。

## 计划覆盖

- `ButlerProfile` 初始化模型：provider、工作目录、`AGENTS.md`、人格和工作习惯配置
- `ButlerControlSession` 独立控制会话模型与生命周期
- 项目、会话、记忆、巡视、验证的分层聚合上下文
- 独立的 Butler Chat API，而不是复用普通项目会话接口
- 管家身份下的项目会话续接、巡视触发、验证触发和信息解释能力
- `apps/user-app` 中“管家”入口、管家工作台和 provider 切换行为

## 依赖关系

- 前置依赖：`spec013`
- 直接影响：`apps/host`、`apps/user-app`
- 后续受益：管家工作台 UI 落地、跨项目进度沟通、统一项目管控入口

## 本阶段明确不做

- 不在这个子 Spec 里直接展开浏览器验证和视觉验证实现细节
- 不在这个子 Spec 里放开高风险自动写代码
- 不让“管家控制会话”和“项目执行会话”混成一个对象
- 不为了聊天方便，破坏已有 `ButlerProject` / `ButlerSession` / `PatrolRun` / `VerificationRun` 的边界
