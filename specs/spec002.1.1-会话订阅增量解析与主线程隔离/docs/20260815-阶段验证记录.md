## 夹具能证明什么

当前长 JSONL 夹具包含 350 条历史记录。追加两条新记录时，测试确认：

- `bytesRead` 等于新增字节数，而不是整份文件大小。
- 返回消息只有两条新增消息。
- reader 复用原有 `entries` 和 `messages` 数组，只更新变化下标和新增下标。
- 半行、截断和文件替换仍走既有恢复模式。

这证明正常追加路径已经同时减少文件读取和历史消息数组复制；它不是生产火焰图，也不能替代真实用户 JSONL 回放。

- 未据此宣布 helper/Host 的生产延迟指标达标；仍需上线采样确认。

## 设计边界

- Host 订阅路径不再同步读取 Codex JSONL 正文；低频兜底只做异步 metadata `stat`。
- JSONL 首次建立 checkpoint 或明确 reset 时允许 helper 全量重建；正常追加只读 byteOffset 之后的数据和固定尾部窗口。
- watcher 只打 dirty 标记，重读统一走 `TaskManager` 的 `session.history_delta_read`。
- workbench 广播门禁只影响会话正文 delta，不阻断已经发出的会话消息。
