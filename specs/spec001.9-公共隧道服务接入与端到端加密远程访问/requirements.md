# 需求文档 - spec001.9 公共隧道服务接入与端到端加密远程访问

状态：Draft

## 简介

当前 `CodingNS` 的远程访问方式有两个明显问题：

1. 很多用户没有公网地址，只能在局域网或自建网络里访问 Host
2. 现有访问链路没有把“公共中继不可见明文”做成正式能力

这次要解决的事很明确：

1. 提供一个 CodingNS 自己托管的公共隧道服务，让没有公网地址的 Host 也能被访问
2. 在本仓库里实现 Host 侧隧道客户端和客户端 / H5 接入层，不在本仓库里实现公共云站点代码
3. 让客户端 / H5 与 Host 之间建立端到端加密信道，公共中继只能转发密文
4. 支持三级域名、流量计量、流量限额和套餐购买
5. 保持现有业务登录、Token、权限和本地直连流程不被破坏

## 术语表

- **公共隧道服务**：CodingNS 官方托管的公网接入服务，负责账号、域名、流量和中继转发
- **控制面**：负责账号、Host 绑定、三级域名、套餐、订单和流量配额的服务
- **数据面**：负责盲转发加密流量并记录字节数的服务
- **盲中继**：中继节点只知道谁在连、连了多久、传了多少字节，但看不到业务明文
- **Host 身份密钥**：Host 首次启用公共隧道时生成的一对长期密钥，用来标识这个 Host
- **隧道绑定**：把当前 Host 绑定到某个公共隧道账号和一个三级域名
- **可信接入端**：官方桌面端、移动端，或从固定可信域名加载的官方 H5
- **流量钱包**：用户可消费的流量额度
- **独立子仓库**：放公共隧道云端代码的单独 Git 仓库，不由本仓库跟踪

## 范围说明

### In Scope

- 定义实例级公共隧道配置、绑定状态和身份公钥模型
- 定义 Host 侧隧道客户端、自动重连、恢复和错误状态
- 定义客户端 / H5 到 Host 的端到端加密传输层
- 定义设置页里的公共隧道入口、绑定、启停和状态展示
- 定义公共隧道控制面与数据面的仓库边界
- 定义三级域名分配、流量计量、配额检查和套餐购买边界
- 定义本地直连、局域网直连、Tailscale 与公共隧道并存规则

### Out of Scope

- 在本仓库里实现公共隧道站点代码
- 在本仓库里实现支付后台代码
- 用公共隧道账号替代 CodingNS 业务登录
- 让用户三级域名直接托管完整 H5 业务页面并仍宣称中继不可见明文
- 第一阶段就做企业组织、共享套餐、经销商和复杂结算

## 需求

### 需求 1：本仓库与公共隧道站点必须强制分仓

**用户故事：** 作为项目维护者，我希望本仓库只承担客户端和协议接入，不跟踪公共云站点代码，避免两个系统绑死在一起。

#### 验收标准

1. WHEN 启动 `spec001.9` THEN System SHALL 明确规定本仓库只实现 Spec、Host 侧隧道客户端、客户端 / H5 接入层和端到端加密协议
2. WHEN 后续开始实现公共隧道站点 THEN System SHALL 要求其放入当前仓库下的独立子仓库，而不是直接并入主仓库
3. WHEN 主仓库检查版本控制边界 THEN System SHALL 不跟踪公共隧道站点代码

### 需求 2：系统必须有正式的实例级公共隧道配置模型

**用户故事：** 作为服务管理员，我希望公共隧道配置属于当前 Host 实例，而不是某个登录用户的私人偏好。

#### 验收标准

1. WHEN 系统保存公共隧道配置 THEN System SHALL 将其保存为实例级配置，而不是账户偏好
2. WHEN 不同业务用户登录同一台 Host THEN System SHALL 看到同一份公共隧道当前状态
3. WHEN 服务重启 THEN System SHALL 恢复上次保存的公共隧道配置和绑定状态

### 需求 3：Host 必须支持绑定公共隧道账号和三级域名

**用户故事：** 作为服务管理员，我希望在设置页里把当前 Host 绑定到我的公共隧道账号，并拿到一个可访问的三级域名。

#### 验收标准

1. WHEN 管理员在设置页启用公共隧道 THEN System SHALL 支持登录公共隧道账号并绑定当前 Host
2. WHEN 绑定成功 THEN System SHALL 返回当前 Host 对应的三级域名、Host 标识和绑定状态
3. WHEN 管理员解绑当前 Host THEN System SHALL 释放本地绑定状态，并停止继续使用旧绑定

### 需求 4：客户端与 Host 之间必须建立端到端加密信道

**用户故事：** 作为使用公共隧道访问 Host 的用户，我希望中继只能看到密文字节，不能查看或篡改业务明文。

#### 验收标准

1. WHEN 客户端或 H5 通过公共隧道访问 Host THEN System SHALL 在应用层建立独立于外层 TLS 的端到端加密信道
2. WHEN 中继节点转发流量 THEN System SHALL 只能看到连接元数据和字节数，不能解密业务请求和响应内容
3. WHEN 加密握手失败、指纹不匹配或会话密钥失效 THEN System SHALL 拒绝继续传输业务内容，并给出明确错误

### 需求 5：系统必须把“可信接入端”和“用户三级域名”边界写死

**用户故事：** 作为架构维护者，我希望系统不要一边说中继不可见内容，一边又让中继域名直接托管完整业务 H5 页面。

#### 验收标准

1. WHEN 官方 H5 需要访问 Host THEN System SHALL 从固定可信域名加载 H5 代码，而不是把完整业务页面直接挂在用户三级域名下
2. WHEN 用户访问三级域名 THEN System SHALL 只把它当成路由入口、跳转入口或隧道标识，而不是端到端加密的业务代码托管域
3. WHEN 产品文档描述 H5 访问方式 THEN System SHALL 明确写出这条信任边界，不得继续混淆

### 需求 6：公共隧道启用后必须保持现有业务认证体系不变

**用户故事：** 作为现有用户，我希望只是网络接入方式变了，不是整个登录体系被推翻。

#### 验收标准

1. WHEN 外部用户通过公共隧道访问 Host THEN System SHALL 继续使用现有 CodingNS 登录流程
2. WHEN 公共隧道启用或停用 THEN System SHALL 不重写现有用户名密码、Access Token、Refresh Token 和 WebSocket 鉴权语义
3. WHEN 未启用公共隧道 THEN System SHALL 保持当前本地 / 局域网 / Tailscale 访问方式不变

### 需求 7：系统必须支持流量计量和流量限额

**用户故事：** 作为公共隧道运营者，我希望能按用户和 Host 统计流量，并在超过配额时阻止继续使用。

#### 验收标准

1. WHEN 隧道有数据传输 THEN System SHALL 按隧道、Host 和账号记录双向传输字节数
2. WHEN 用户达到流量上限 THEN System SHALL 拒绝建立新连接，必要时中断现有连接
3. WHEN Host 或客户端查看状态 THEN System SHALL 能看到当前套餐余量、最近消耗和超额原因

### 需求 8：系统必须支持成熟支付方式购买流量套餐

**用户故事：** 作为公共隧道用户，我希望直接购买流量套餐，而不是通过线下转账或手工开通。

#### 验收标准

1. WHEN 用户进入公共隧道站点 THEN System SHALL 支持通过成熟支付方式购买流量套餐
2. WHEN 支付成功 THEN System SHALL 把对应流量额度写入流量钱包，并更新配额状态
3. WHEN 支付失败、取消或回调异常 THEN System SHALL 保持订单和流量账本一致，不得凭空加量或扣量

### 需求 9：Host 侧隧道客户端必须支持长连接、自动重连和启动恢复

**用户故事：** 作为服务管理员，我希望 Host 重启后能恢复隧道，网络抖动后能自动重连，而不是每次都手动重绑。

#### 验收标准

1. WHEN Host 已启用公共隧道且服务重启 THEN System SHALL 尝试恢复隧道客户端和绑定状态
2. WHEN 外网短暂抖动或中继连接断开 THEN System SHALL 自动重连，并在设置页展示当前阶段
3. WHEN 持续重连失败 THEN System SHALL 明确显示失败原因，而不是静默离线

### 需求 10：未初始化实例必须避免通过公共隧道直接暴露初始化入口

**用户故事：** 作为服务管理员，我不希望一台还没初始化的 Host 一启用公共隧道就把首个管理员入口暴露到公网。

#### 验收标准

1. WHEN 当前实例尚未完成 bootstrap THEN System SHALL 阻止正式启用公共隧道对外暴露
2. WHEN 管理员尝试在未初始化状态启用公共隧道 THEN System SHALL 明确提示必须先完成初始化
3. WHEN 实例完成初始化后再次启用公共隧道 THEN System SHALL 正常继续绑定和连通流程

## 非功能需求

### 非功能需求 1：安全性

1. WHEN 客户端和 Host 建立公共隧道会话 THEN System SHALL 使用正式的密钥协商和会话密钥轮换机制，而不是自己拼一个明文 token 加异或
2. WHEN Host 身份公钥首次展示给用户 THEN System SHALL 支持查看指纹或等价标识，避免完全黑盒
3. WHEN 端到端加密未建立成功 THEN System SHALL 不得回退到明文业务传输

### 非功能需求 2：可观测性

1. WHEN 隧道在线状态变化 THEN System SHALL 记录可观测事件和最近错误
2. WHEN 流量被限额或支付未到账 THEN System SHALL 给出可追踪的状态和错误码

### 非功能需求 3：兼容性

1. WHEN 客户端不启用公共隧道 THEN System SHALL 保持当前本地地址、局域网地址、Tailscale 地址的连接方式不变
2. WHEN 公共隧道不可用 THEN System SHALL 允许用户继续使用本地直连或其他已有远程访问方式

## 成功定义

- 本仓库只承担客户端和协议接入，公共云站点代码明确分仓
- 管理员可以在设置页里启用、绑定、停用和查看公共隧道状态
- 客户端 / H5 与 Host 之间通过中继转发时，中继看不到业务明文
- 用户可以拿到三级域名并通过官方客户端或官方 H5 访问 Host
- 流量可以被计量、限额和购买
- 现有业务认证、本地直连和 Tailscale 访问方式保持可用
