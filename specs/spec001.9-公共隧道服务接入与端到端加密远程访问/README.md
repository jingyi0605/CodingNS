# spec001.9-公共隧道服务接入与端到端加密远程访问

## 当前定位

这是 `spec001` 下的新子 Spec，也是 `spec001.4-Tailscale接入与实例级远程访问` 之后的下一步。

它只解决一件事：
把“用户只能在局域网或自建网络里访问 Host”升级成“通过 CodingNS 自己托管的公共隧道服务访问 Host”，同时把通讯内容做成端到端加密，让公共中继只能看到密文字节和流量统计，看不到业务明文。

这次要定住的不是“再加一个公网入口”，而是下面这些真问题：

- 没有公网地址的用户，怎么把内网 Host 挂到互联网上
- 现有直连模式里没有统一的端到端加密，怎么补安全底线
- 公共服务站点、Host、客户端三者之间，谁能看见什么内容
- 三级域名、账号绑定、流量限额、套餐购买这些控制面，应该落在哪个仓库
- 本仓库到底改什么，不该改什么

一句人话：
这次做的是“公共隧道服务接入 + 端到端加密传输”，不是“在本仓库里顺手写个反向代理站点”。

## 计划覆盖

- 实例级公共隧道配置模型、绑定状态和最近状态快照
- Host 侧隧道客户端、长连接、自动重连和启动恢复
- 客户端 / H5 到 Host 的端到端加密信道
- 公共服务控制面与数据面的仓库边界
- 用户三级域名、Host 绑定、公钥登记和指纹展示
- 流量计量、流量限额、超额断流和套餐购买边界
- 设置页里的公共隧道入口、绑定、启停、状态展示
- 与现有本地直连、局域网直连、Tailscale 远程访问并存的规则
- 控制台站点、正式数据库、真实邮件、真实支付联调、生产化中继和上线验收由 `spec001.9.1-公共隧道服务二阶段收口与生产化验收` 继续展开
- 管理员后台、角色模型、管理员鉴权和只读管理视图由 `spec001.9.2-公共隧道管理员只读后台与权限通路` 继续展开
- 公共隧道流量优化、局域网自动直连和远程访问减量传输由 `spec001.9.3-公共隧道流量优化与局域网自动直连` 继续展开

## 本阶段明确不做

- 在本仓库里实现公共隧道站点、支付后台和云端转发节点代码
- 把“公共隧道服务”抽象成支持无限多供应商的通用网络平台
- 用公共隧道服务替代现有 CodingNS 登录体系
- 假装“用户三级域名直接出 H5 页面”还能同时保证中继永远看不到内容
- 第一阶段就做团队套餐、共享流量池、多租户企业后台

## 仓库边界

这次必须把仓库边界写死：

- **本仓库**：只放 `Spec`、Host 侧隧道客户端、客户端 / H5 接入层、端到端加密协议、设置页入口
- **独立子仓库**：公共隧道服务站点、控制面、支付、流量账本、边缘转发节点

推荐的落地方式：

- 独立子仓库路径：`apps/codingns-proxy/`
- 该目录拥有自己的 `.git`
- 主仓库通过 `.gitignore` 忽略该目录，不跟踪其代码
