# spec009-移动端体验与通知

## 当前定位

这个 Spec 现在不再是“移动端查看 + 轻操作 + 通知”。

新的定位是：

- 移动端业务能力与 PC 端对齐
- iOS / Android 的 UI 和交互分别优化
- 不再接受“缩小网页版”或者“一套组件 everywhere”的偷懒方案

一句人话：
移动端要和 PC 端做同一套事情，但看起来、点起来、返回起来，要像各自平台自己的应用。

## 核心原则

- 统一业务内核，不重复造一套移动端业务逻辑
- 系统能力走平台适配层，不把权限、分享、通知、文件导入这些逻辑散落到页面里
- 平台 UI 单独分层，iOS 和 Android 不共用一套假原生皮肤
- 客户端壳统一使用 `Tauri Mobile`

## 当前进展

- 已切回 `Tauri Mobile`
- 已完成 Android 壳初始化与首编打通
- Android Debug APK 已产出
- iOS 壳初始化与编译仍未完成

## 计划覆盖

- 移动端全量业务能力与 PC 对齐
- iOS / Android 分平台导航与视觉规范
- `core / platform adapter / platform ui` 三层结构
- 会话、工作区、文件、Git、终端、日志、进程、设置、通知的移动端交付
- 推送、分享、文件导入、权限、生物识别、触感反馈等系统能力接入

## 子 Spec 拆分

`spec009` 现在负责移动端的大盘子，别再什么都往一个文件里塞。

已经拆出的子问题：

- `spec009.1-移动端工作台导航与信息架构重构`
- `spec009.2-移动端对话主入口与助手侧栏重构`

它专门负责：

- 当前 PC 三栏工作台怎么拆成移动端页面结构
- H5 移动端、iOS、Android 的导航容器与页面职责
- 当前桌面小图标动作怎么迁到移动端按钮、菜单、sheet、编辑模式

`spec009.2` 专门负责：

- 移动端对话页重新成为主入口
- 文件 / Git 收回对话页左侧页
- 底部导航里终端、助手、工具职责重新摆正
- 助手页补齐工作区切换头、对话列表侧页、右侧信息栏

`spec009` 自己继续负责：

- 三层架构
- 业务能力与 PC 对齐
- 系统能力适配
- 通知与后台恢复
- 原生壳与平台接入

一句话：
页面结构总盘子看 `spec009.1`；
对话 / 终端 / 助手这次的入口和侧页重排看 `spec009.2`；
系统能力和整体架构，还看 `spec009`。

## 本阶段明确不做

- 重新定义 `spec003/004/005/007/008` 已经确定的核心协议
- 用一套无差别组件硬抹平 iOS 和 Android 差异
- 把移动端做成桌面窗口布局的缩略图
