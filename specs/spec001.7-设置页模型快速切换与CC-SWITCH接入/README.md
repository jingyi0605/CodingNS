# spec001.7-设置页模型快速切换与CC-SWITCH接入

## 当前定位

这是 `spec001` 下的新子 Spec。

它只解决一件事：
把设置页里“快速切换各 CLI 默认模型”这件事做成一个正式入口，而且第一期明确基于本机已经存在的 `cc-switch` 预设来做。

先把实话说清楚：

- `cc-switch` 现在稳定暴露的是 provider 预设切换，不是通用的“直接写模型 ID”接口
- CodingNS 现在已经能在会话里识别“跟随 CLI 默认模型”，但没有一个统一的设置页入口去改默认值
- 如果第一期硬要把“模型切换”“provider 编辑”“动态拉模型并写回所有 CLI 配置”一起做，最后只会写成一坨

一句人话：
这次先做“模型预设快速切换”，不是做“全功能模型编辑器”。

## 计划覆盖

- 设置页里的模型管理入口和最小图形化交互
- `codex`、`claude-code`、`gemini`、`opencode` 四个应用的统一展示模型
- Host 侧 `cc-switch` 读取和切换适配层
- 当前预设、当前模型、可切换项和不可用状态的统一返回结构
- 切换后的状态刷新，以及与现有 provider capabilities 的衔接
- `cc-switch` 命令路径发现、失败提示和安全边界

## 依赖关系

- 前置依赖：`spec001-平台底座与工作区基础`
- 强相关依赖：
  - `spec001.5-多CLI-Skill统一管理与同步`
  - `spec010-Provider扩展框架`
- 直接影响：
  - `apps/host`
  - `apps/user-app`

## 本阶段明确不做

- 不做模型新增、编辑、删除
- 不做 provider 新增、编辑、删除
- 不把 `cc-switch` 的 sqlite 表结构直接当成系统内部公共协议
- 不在前端直接调用本地 CLI
- 不在会话页主流程塞一个新的“全局模型管理器”
- 不承诺第一期就支持同一 provider 内任意模型自由改写
- 不为了“立刻可切”去暴露 API key、完整配置文本或其他敏感字段
