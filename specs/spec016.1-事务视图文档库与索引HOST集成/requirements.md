# 需求文档 - spec016.1-事务视图文档库与索引HOST集成

状态：Draft

## 简介

`spec016` 已经把事务视图的壳层搭起来了，但文档库内容现在还是占位数据。当前实现拿工作区会话去拼“文档对象”，这在结构上就是错的。

用户真正需要的是：

- 进入事务视图时，先确认这个工作区要看哪一套文档库
- 绑定一个文档库路径后，看到该路径对应的真实文件视图
- 左侧能看真实收藏和真实标签
- 中间能看真实文档对象
- 右侧能围绕真实对象做详情和助手联动

同时，索引能力不能继续飘在项目外面。`doc-semantic-index-node` 这套能力必须正式接进 `apps/host`，并且所有重活都要走当前统一的后台任务体系，不能为了文档库再长一套私有 `inflight`、`timer`、私有 watcher。

## 术语表

- **System**：`CodingNS`
- **文档库绑定**：把某个工作区的事务视图明确绑定到一个资料库根路径
- **索引服务**：基于 `doc-semantic-index-node` 提供的扫描、标签、导出、查询能力
- **导出快照**：索引服务输出给前端消费的静态结构化结果，例如 `exports-v2/manifest.json` 和分片数据
- **事务文档对象**：事务视图里展示的真实文档，不再是会话占位对象
- **后台索引任务**：配置应用、重扫、标签重算、导出刷新、状态同步等可去重、可观测的后台活

## 范围说明

### In Scope

- 工作区级文档库路径绑定和持久化
- 事务视图文档库默认首页的真实数据接入
- 真实文档、真实标签、真实收藏的数据模型
- `apps/host` 内部索引服务封装
- 索引相关任务的 `TaskManager` 接入、状态模型和观测口径
- 事务视图读取索引快照、刷新状态和错误状态的 Host API
- 首阶段前端主链路：绑定路径、展示列表、标签筛选、收藏、详情、助手上下文
- 为这条主链路服务的前端样式改造和助手初始化逻辑升级

### Out of Scope

- 文档库全文搜索和语义搜索的完整产品化
- 多索引器插件化框架
- 首阶段就支持所有静态文档浏览器里的高级交互细节
- 重做 `doc-semantic-index-node` 的全部命令行体验
- 全量替换现有待办、自动化、插件分区设计
- 与真实文档库主链路无关的纯审美式样式重画
- 重写 Butler/助手底层运行时

## 需求

### 需求 1：系统必须在事务视图里绑定真实文档库路径

**用户故事：** 作为使用者，我希望进入事务视图时先确认这套工作区对应哪一份资料库，这样后面看到的内容才是我要的文档。

#### 验收标准

1. WHEN 用户首次进入某个工作区的事务视图且还没有文档库绑定 THEN System SHALL 提示用户选择或填写文档库路径。
2. WHEN 用户完成文档库绑定 THEN System SHALL 把该绑定保存为工作区级配置，而不是只放在当前页面内存里。
3. WHEN 用户再次进入同一工作区的事务视图 THEN System SHALL 自动恢复上次绑定的文档库路径。
4. WHEN 绑定路径无效、索引目录缺失或配置不可读 THEN System SHALL 给出明确错误，而不是继续展示假文档列表。

### 需求 2：系统必须让事务视图文档库展示真实文档对象

**用户故事：** 作为使用者，我希望事务视图里看到的文档就是资料库里的真实文件，而不是会话占位对象。

#### 验收标准

1. WHEN 事务视图加载文档库主列表 THEN System SHALL 基于真实索引结果展示文档路径、标题、摘要、更新时间和标签。
2. WHEN 用户切换标签、收藏或目录范围 THEN System SHALL 重新筛选真实文档结果，而不是用会话标题临时猜标签。
3. WHEN 用户选中文档对象 THEN System SHALL 在右侧展示该文档的真实路径、真实标签和摘要信息。
4. WHEN 当前文档库没有任何可用文档 THEN System SHALL 显示真实空态，而不是回退到会话占位数据。

### 需求 3：系统必须支持真实收藏和真实标签列表

**用户故事：** 作为使用者，我希望左侧收藏和标签是文档库自己的导航，不是从别的模块硬拼出来的。

#### 验收标准

1. WHEN 文档库已完成绑定并存在索引结果 THEN System SHALL 展示真实标签列表或标签树。
2. WHEN 用户在事务视图里查看收藏 THEN System SHALL 展示文档库范围内的真实收藏项，至少支持文件夹收藏和标签收藏。
3. WHEN 用户点击某个标签或收藏 THEN System SHALL 让中间文档列表和右侧摘要一起切到对应范围。
4. WHEN 收藏或标签结果为空 THEN System SHALL 明确告诉用户当前没有数据，而不是静默失败。

### 需求 4：系统必须把索引能力正式集成到 HOST

**用户故事：** 作为维护者，我希望事务视图通过本项目 HOST 访问索引能力，而不是继续让前端自己拼 CLI 或依赖外部静态页。

#### 验收标准

1. WHEN `apps/user-app` 需要读取文档库数据 THEN System SHALL 通过 `apps/host` 暴露的正式 API 获取数据。
2. WHEN Host 需要读取索引配置、导出快照或触发索引任务 THEN System SHALL 通过 Host 内部索引服务统一处理，而不是散落在多个模块里直接调命令。
3. WHEN Host 尚未找到索引工具目录、配置文件或导出快照 THEN System SHALL 返回结构化错误和可读提示。
4. WHEN 事务视图文档库主链路已经跑通 THEN System SHALL 不再依赖静态 HTML 页面作为正式运行入口。

### 需求 5：系统必须把索引重活接入统一后台任务体系

**用户故事：** 作为系统维护者，我希望文档库接进来后不会重新把 Host 主线程拖死，也不会再长出新的一套散装后台任务。

#### 验收标准

1. WHEN 系统执行索引配置应用、全量重扫、标签重算或导出刷新 THEN System SHALL 通过 `TaskManager` 注册和调度对应后台任务。
2. WHEN 这些任务涉及扫描文件、处理大量 SQLite 数据或调用 CLI THEN System SHALL 运行在 `helper_process` 或 `external_process`，而不是请求主线程。
3. WHEN 同一工作区同一类索引任务已经在跑 THEN System SHALL 基于 `taskType + key` 去重，不得并发重复跑第二份重活。
4. WHEN 前端只是读取当前索引结果 THEN System SHALL 只读缓存或最近结果，不得在读接口里顺手发起重扫描。
5. WHEN watcher 或配置变化触发刷新 THEN System SHALL 只打脏标记并调度后台任务，不得在 watcher 回调里同步做重活。

### 需求 6：系统必须提供统一的索引状态和错误状态

**用户故事：** 作为使用者，我希望知道文档库现在是正常、过期、正在刷新还是出错，而不是只看到一个空列表。

#### 验收标准

1. WHEN 文档库绑定完成后 THEN System SHALL 对外暴露最少 `fresh`、`stale`、`running`、`failed`、`cooldown` 这几种索引状态。
2. WHEN 后台索引任务开始、完成、失败或进入冷却期 THEN System SHALL 更新当前工作区文档库状态。
3. WHEN 前端读取文档库快照时 THEN System SHALL 同时返回最近一次刷新时间、当前状态和必要的错误摘要。
4. WHEN 后台任务失败 THEN System SHALL 保留最近一次可用结果，并把失败原因以可读方式暴露给前端。

### 需求 7：系统必须保证事务视图助手围绕真实文档对象工作

**用户故事：** 作为使用者，我希望右侧助手看到的上下文来自真实文档，而不是会话占位对象。

#### 验收标准

1. WHEN 用户在事务视图里选中文档 THEN System SHALL 让右侧助手上下文切到该文档的真实标题、摘要、路径和标签。
2. WHEN 当前没有选中文档 THEN System SHALL 明确告诉助手当前还没有事务对象，而不是继续沿用代码会话语境。
3. WHEN 用户从标签、收藏或目录切换对象 THEN System SHALL 让右侧详情和助手上下文一起切换。

### 需求 7.1：系统必须升级事务视图助手初始化逻辑

**用户故事：** 作为使用者，我希望事务视图第一次打开时，助手就进入正确语境，而不是继续拿原助手页面的代码会话初始化逻辑硬顶。

#### 验收标准

1. WHEN 用户首次进入事务视图 THEN System SHALL 先判断当前工作区是否已经绑定文档库路径。
2. WHEN 当前工作区还没有绑定文档库路径 THEN System SHALL 让助手和右侧面板进入“还没有事务对象 / 先完成文档库绑定”的初始化状态。
3. WHEN 当前工作区已经绑定文档库路径且存在默认文档对象 THEN System SHALL 让助手初始化语境直接围绕该真实文档对象，而不是沿用代码会话语境。
4. WHEN 事务视图初始化过程中还没有选中文档 THEN System SHALL 给出清楚的空上下文提示，而不是继续显示旧助手页面残留状态。

### 需求 7.2：系统必须把前端样式改造限制在真实文档库主链路内

**用户故事：** 作为维护者，我希望这次前端改造先为真实文档库链路服务，不要借机把整个事务视图变成无边界重画。

#### 验收标准

1. WHEN 前端新增或修改文档库相关页面、区块、列表、空态、按钮和错误态 THEN System SHALL 统一按 `apps/user-app` 的设计规范实现。
2. WHEN 需要新增文档库绑定入口、错误态、空态、刷新态或详情态 THEN System SHALL 把样式改造收敛在真实文档库主链路必需范围内。
3. WHEN 某个样式改动与文档库绑定、真实对象展示、详情联动或助手初始化无关 THEN System SHALL 不把它塞进本 Spec 当成本轮必做项。

## 非功能需求

### 非功能需求 1：性能

1. WHEN 前端读取文档库主列表、标签列表或详情快照 THEN System SHALL 优先读取已有导出快照或缓存结果，不在主线程现算重扫描。
2. WHEN 索引后台任务处理大目录、重 SQLite 或导出刷新 THEN System SHALL 不阻塞 Host 请求主链路。
3. WHEN 同一工作区被反复打开事务视图 THEN System SHALL 复用最近结果和冷却状态，避免重复触发等价重活。

### 非功能需求 2：可靠性

1. WHEN 索引工具缺失、导出快照损坏或配置错误 THEN System SHALL 返回结构化错误，并允许用户重新绑定或重试。
2. WHEN 后台索引任务失败 THEN System SHALL 保留最近一次可用结果和最近失败信息，而不是把整个文档库读链路一起拖死。

### 非功能需求 3：可维护性

1. WHEN 后续继续补文档搜索、更多筛选或对象动作 THEN System SHALL 复用本 Spec 建立的 Host 索引服务和事务文档对象模型。
2. WHEN 后续新增索引相关后台任务 THEN System SHALL 遵守 `spec001.2` 和 `spec001.2.1` 的统一后台任务规则，不再长私有 `inflight`、私有 `timer`、私有 watcher 重活链路。

## 成功定义

- 事务视图文档库不再显示会话拼出来的假对象
- 用户首次进入事务视图时能绑定文档库路径，并在后续自动恢复
- 左侧能显示真实收藏和真实标签
- 中间能显示真实文档列表，右侧能显示真实对象详情和助手上下文
- 索引服务正式进入 HOST，并通过统一后台任务体系管理重活
- 文档库接入后不会明显拖慢整体 Host 主线程性能
