# spec016-代码视图与事务视图双工作台重构

## 这份 Spec 现在解决什么问题

`CodingNS` 现在的前端主界面，本质上还是一套围着“代码会话”展开的工作台：

- 左侧是会话和工作区导航
- 中间是对话消息或终端/Butler 等中心区
- 右侧是工具和信息栏

这套结构对代码开发是成立的，但对你现在要接进来的另一类工作就开始吃力了：

- 文档库管理
- 标签和收藏视图
- 对象文件管理
- 代办管理
- 自动化管理
- 浏览器、文档、运维等办公类插件
- 生活、学习这类不属于代码开发，但又需要长期沉淀和操作的事务

一句人话：

现在这套 UI 适合“围着会话做事”，不适合“围着对象和事务做事”。

所以这份 Spec 要解决的核心问题不是“改两个按钮文案”，而是把 `CodingNS` 的前端顶层结构正式拆成两套工作台：

1. **代码视图**：继续服务代码开发，会话仍然是主舞台
2. **事务视图**：服务文档、待办、自动化、插件和对象文件管理，对象和事务成为主舞台

## 这次计划覆盖什么

- 重构桌面端主工作台左上角入口，把现在的“对话 / 助手”等中心区切换，升级成顶层视图切换
- 明确两个顶层视图的正式命名、路由模型、状态模型和布局骨架
- 保持代码视图现有“三栏工作台”主结构不变，优先保证零破坏迁移
- 新建事务视图三栏布局：左侧导航、中间主对象区、右侧详情与 AI 对话区
- 要求事务视图整体 UI 语言和开发视图保持一致，避免用户一切换就像换了应用
- 把文档库作为事务视图第一优先接入对象
- 为待办、自动化、插件入口预留正式位置，而不是继续零散塞按钮
- 统一两个视图与工作区、会话、文件、助手、office 能力之间的关系
- 保留现有助手能力和底层逻辑，但把它从“代码类跟进管家”扩成事务视图里的通用 AI 助手
- 给移动端和小屏场景补降级策略，避免桌面方案直接硬压到移动端

## 这次明确不做什么

- 不在这份 Spec 里直接实现文档库全部业务细节
- 不在第一阶段重写代码视图内部已有消息流、会话树、Git、终端等成熟区域
- 不删除现有 Butler 页面和 Butler 底层逻辑
- 不把“事务视图”做成一个独立新应用再 iframe 塞回 `CodingNS`
- 不把办公、生活、学习分别拆成三个顶层模式
- 不在没有明确对象模型前，就先往事务视图里胡乱塞页面和按钮

## 为什么现在就要立这个 Spec

因为这次不是普通 UI 调整，而是改前端主骨架。

如果不先把骨架写清楚，后面很容易长出几种垃圾：

1. 左上角只是换了按钮名，底层仍然是旧的 center tab 模型
2. 事务视图只是多了一页静态页面，没有正式路由和状态模型
3. 文档库、待办、自动化、插件各做各的入口，最后又回到散装工作台
4. 桌面端勉强能看，移动端直接炸掉
5. AI 对话在代码视图和事务视图里职责混乱，谁是主舞台说不清

这类问题不是后面补几条 CSS 能救回来的。

## 命名结论先写死

这次顶层视图，优先采用下面这组正式命名：

- **代码**
- **事务**

原因很简单：

- “代码”足够直接
- “事务”比“办公”更宽，能覆盖办公、生活、学习、待办、自动化、插件和对象文件管理
- 不会把文档库、待办、自动化这种明显超出“办公”范围的东西硬塞进错误命名里

如果后续评审要调整文案，也必须保持这个原则：

**第二个视图必须是通用事务视图，不能退回到狭义“办公”视图。**

## 硬边界先写死

### 边界 1：顶层视图切换不是文案替换，是正式模式切换

- 代码 / 事务 是顶层工作台模式
- 不能继续挂在旧的 center tab 语义下假装重构完成

### 边界 2：代码视图优先零破坏

- 左侧会话栏、中间消息区、右侧工具栏的主要结构先保持不变
- 这次不拿成熟代码工作台做试验田

### 边界 3：事务视图的主舞台必须是对象，不是聊天

- 中间主区优先展示文档库、待办、自动化、插件等对象视图
- AI 对话在事务视图里是辅助面板，不再抢主舞台

### 边界 4：事务视图不能做成独立外挂页面

- 文档库、对象文件、待办、自动化和插件要逐步纳入 `user-app` 正式结构
- 允许首阶段复用现有静态能力，但不能把最终方案建立在 iframe 或孤岛页面上

### 边界 5：双视图必须共享同一套 UI 语言

- 左上角顶层模式切换始终存在
- 顶部通用工具按钮始终存在
- 中间主工作区顶部栏高度要和代码视图标题栏对齐
- 右侧详情与 AI 助手顶部栏高度也要对齐
- 不能让事务视图看起来像外插的第二个应用

### 边界 6：移动端必须有降级方案

- 这次不能只盯桌面端三栏布局
- 事务视图必须提前定义移动端折叠、抽屉、切页和信息密度规则
