# 需求文档 - spec004.2-静态HTML演示文档编辑器与导出能力

状态：Draft

## 简介

当前 CodingNS 已经能在文件管理里打开 HTML、图片、PDF，也能做基础文本编辑。

但用户手里的真实内容不是“普通网页”，而是一类越来越常见的东西：

- 用 AI 或人工写出来的单文件 HTML PPT
- 用 HTML/CSS 表达版式的报告文档
- 重点不是响应式网页，而是固定版式、固定页面、固定视觉结果

这类文件直接用代码编辑器改，效率太低；只用 iframe 预览，也只能看不能改。

所以这次要做的是一个夹在“代码编辑器”和“Office 套件”之间的东西：

- 输入是静态 HTML
- 编辑方式是 PPT/版式文档视图
- 输出仍然是 HTML，同时能导出 `PDF / PPTX`

## 术语表

- **System**：CodingNS 及其可独立打包的静态 HTML 文档编辑器内核
- **静态 HTML 演示文档**：单文件或单主文件 HTML，主要靠 HTML/CSS 表达固定页面版式，可用于 PPT 或报告交付
- **编辑内核**：负责页面识别、组件选择、画布编辑、保存回写和导出的核心模块，不包含 CodingNS 文件树外壳
- **页面模型**：把一个 HTML 文档拆成页面、组件、样式、顺序等可编辑结构后的内部表示
- **版式一致导出**：导出结果的视觉布局、字号、颜色、间距和分页尽量与编辑视图一致

## 范围说明

### In Scope

- 在文件管理中识别并打开静态 HTML 演示文档
- 用逐页视图编辑 `PPT` 风格 HTML
- 支持文本内容编辑
- 支持基础文本样式调整：字体、字号、粗细、颜色、对齐、换行
- 支持组件位置、大小、层级的基础调整
- 支持组件复制
- 支持把编辑结果保存回 HTML 文件
- 支持导出 `PDF`
- 支持导出 `PPTX`
- 支持把编辑内核嵌入 CodingNS
- 支持把编辑内核单独打包为桌面应用

### Out of Scope

- 任意网页自动变成可完美编辑的 PPT
- 多人实时协同编辑
- PowerPoint 原生高级动画、母版、演讲者备注的完整等价支持
- `docx / pptx / xlsx` 原生导入
- 全量图形设计软件级别的绘图能力

## 需求

### 需求 1：系统必须能从文件管理中打开静态 HTML 演示文档

**用户故事：** 作为文件管理用户，我希望直接从工作区文件树打开 HTML 演示文档，并进入可编辑的 PPT 视图，而不是只能看源码或 iframe 预览。

#### 验收标准

1. WHEN 用户在文件管理中打开符合条件的 HTML 文件 THEN System SHALL 提供“进入演示文档编辑器”的入口。
2. WHEN 用户进入编辑器 THEN System SHALL 展示逐页页面列表和当前页面画布，而不是只显示源码文本框。
3. WHEN HTML 文件不符合当前可编辑规则 THEN System SHALL 明确提示原因，并允许用户退回普通 HTML 预览或源码编辑。

### 需求 2：系统必须把静态 HTML 识别成稳定的页面模型

**用户故事：** 作为维护者，我希望系统先把 HTML 拆成页面和组件，再进行编辑，这样后续新增能力时不会到处写 DOM 特判补丁。

#### 验收标准

1. WHEN 用户打开静态 HTML 演示文档 THEN System SHALL 识别页面边界、页面顺序和页面尺寸。
2. WHEN 页面里存在可识别文本块、图片块或容器块 THEN System SHALL 把它们映射成可编辑组件。
3. WHEN 某些节点无法安全结构化编辑 THEN System SHALL 保留原始内容并标记为受限组件，而不是静默丢失。

### 需求 3：系统必须支持逐页的 PPT 视图编辑

**用户故事：** 作为编辑者，我希望像编辑 PPT 一样逐页处理 HTML 文档，这样我不需要来回在整份 HTML 里找对应节点。

#### 验收标准

1. WHEN 用户进入编辑器 THEN System SHALL 显示页缩略列表或页导航，支持切换当前页。
2. WHEN 用户切换页面 THEN System SHALL 保持固定版式画布，不因为窗口大小变化而破坏页面比例。
3. WHEN 文档包含多页 THEN System SHALL 保持页面顺序和编号稳定。

### 需求 4：系统必须支持组件级文字和基础样式编辑

**用户故事：** 作为编辑者，我希望选中某个组件后，能直接改文字和常见样式，而不是退回源码硬改。

#### 验收标准

1. WHEN 用户选中文本组件 THEN System SHALL 支持直接修改文字内容。
2. WHEN 用户调整字体、字号、字重、颜色、对齐和换行 THEN System SHALL 在画布中立即反映结果。
3. WHEN 用户修改样式后保存 THEN System SHALL 把这些修改写回 HTML，而不是只保存在临时内存里。

### 需求 5：系统必须支持组件复制、移动和缩放

**用户故事：** 作为编辑者，我希望把现有组件复制一份再调整位置和大小，而不是每次都手改 HTML 结构。

#### 验收标准

1. WHEN 用户复制组件 THEN System SHALL 在当前页生成同类组件副本，并保留基础样式。
2. WHEN 用户拖动组件 THEN System SHALL 更新组件位置，并在保存后保持一致。
3. WHEN 用户调整组件尺寸 THEN System SHALL 更新组件边界，并在保存后保持一致。

### 需求 6：系统必须把编辑结果稳定保存回单文件 HTML

**用户故事：** 作为文件管理用户，我希望编辑完成后仍然得到一个普通 HTML 文件，这样它还能被现有工作流、Git 和外部浏览器继续使用。

#### 验收标准

1. WHEN 用户保存文档 THEN System SHALL 生成可直接打开的 HTML 文件，而不是私有二进制格式。
2. WHEN 用户只修改少量组件 THEN System SHALL 尽量保留未改动内容，不允许大面积无意义改写。
3. WHEN 保存发生版本冲突 THEN System SHALL 复用现有文件冲突保护机制，而不是静默覆盖。

### 需求 7：系统必须支持导出版式一致的 PDF

**用户故事：** 作为交付用户，我希望把编辑后的 HTML 演示文档导出为 PDF，页面布局和视觉效果与编辑器看到的保持一致。

#### 验收标准

1. WHEN 用户触发 PDF 导出 THEN System SHALL 生成按页面分页的 PDF 文件。
2. WHEN 导出成功 THEN System SHALL 保证 PDF 的页面顺序、背景、字体大小、主要间距和组件位置与编辑视图尽量一致。
3. WHEN 导出失败 THEN System SHALL 返回明确错误，并保留原 HTML 文件不受影响。

### 需求 8：系统必须支持导出版式一致的 PPTX

**用户故事：** 作为交付用户，我希望把编辑后的 HTML 演示文档导出为 PPTX，这样我可以继续交付给只接受 PPT 的场景。

#### 验收标准

1. WHEN 用户触发 PPTX 导出 THEN System SHALL 生成可被主流 PowerPoint 软件打开的 `.pptx` 文件。
2. WHEN 导出成功 THEN System SHALL 优先保证每页视觉布局与编辑视图尽量一致。
3. WHEN 某些复杂组件无法可靠转换为可编辑 PPT 原生对象 THEN System SHALL 允许使用位图化页面作为保底方案，而不是输出错位的假可编辑页面。

### 需求 9：系统必须同时支持嵌入 CodingNS 和独立桌面打包

**用户故事：** 作为产品维护者，我希望这套编辑能力既能在 CodingNS 文件管理中使用，也能单独打包，不需要维护两套完全不同的实现。

#### 验收标准

1. WHEN 编辑器嵌入 CodingNS THEN System SHALL 通过清晰的宿主接口接收文件内容、保存结果和导出命令。
2. WHEN 编辑器单独打包为桌面应用 THEN System SHALL 仍能打开本地 HTML 文件、保存和导出。
3. WHEN 宿主变化为 CodingNS 或独立桌面外壳 THEN System SHALL 复用同一套页面模型和编辑内核。

### 需求 10：系统不能破坏现有文件管理和普通 HTML 工作流

**用户故事：** 作为现有用户，我希望这次新增能力不会把原来能看的 HTML、能改的源码和现有文件保存链路搞坏。

#### 验收标准

1. WHEN 用户继续以普通方式预览或编辑一般 HTML 文件 THEN System SHALL 保持现有预览和源码编辑链路可用。
2. WHEN 当前 HTML 文件不适合进入演示文档编辑器 THEN System SHALL 允许用户继续使用旧链路。
3. WHEN 新增导出和编辑能力上线 THEN System SHALL 不影响文件树、最近打开、Git 跟踪和会话文件上下文能力。

## 非功能需求

### 非功能需求 1：版式一致性

1. WHEN 用户在编辑器中预览并导出 THEN System SHALL 保证页面尺寸、主要间距、主要字体大小和组件位置的一致性优先级高于“内部结构完全语义化”。
2. WHEN 系统无法同时满足“完全可编辑 PPT 结构”和“版式不跑” THEN System SHALL 优先保证导出结果不跑版。

### 非功能需求 2：性能

1. WHEN 用户打开常见 10 至 30 页的静态 HTML 演示文档 THEN System SHALL 在可接受时间内完成页面识别并显示首屏页面。
2. WHEN 用户执行保存和导出 THEN System SHALL 使用后台任务或异步流程，避免把 Host 主线程长时间卡死。

### 非功能需求 3：可维护性

1. WHEN 后续要扩展 HTML 报告模式或新的导出器 THEN System SHALL 允许在不推翻页面模型的前提下新增适配层。
2. WHEN 排查导入、保存或导出问题 THEN System SHALL 能明确区分是页面识别、编辑回写还是导出渲染阶段出错。

### 非功能需求 4：安全性

1. WHEN 系统处理工作区内 HTML 文件 THEN System SHALL 继续遵守工作区路径边界和文件权限校验。
2. WHEN 系统执行导出 THEN System SHALL 不默认把源文件上传到第三方在线服务换取结果。

## 成功定义

- 用户可以直接从 CodingNS 文件管理中打开静态 HTML PPT，并按页编辑。
- 至少常见文本块、图片块和容器块可以被稳定选中、复制、移动、缩放和保存。
- 编辑后的文件仍然是普通 HTML，继续能进 Git、能被浏览器打开。
- `PDF` 和 `PPTX` 导出结果版式基本不跑。
- 编辑内核不与 CodingNS 外壳死绑，可以单独打包为桌面应用。
