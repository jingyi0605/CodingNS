# 20260515-页面模型与回写约束

## 这份文档要回答什么

这份文档只回答三个问题：

1. 编辑器内部到底用什么页面模型
2. 什么节点能改，什么节点必须锁住
3. 保存回 HTML 时，哪些东西能补丁式回写，哪些不能硬来

一句人话：

后面写代码时，谁再想“先做出来再说”，先看这份文档。不然最后一定会把 HTML 改成一坨没人敢碰的垃圾。

## 总体原则

### 原则 1：宿主无关

页面模型不能依赖 CodingNS 的文件树、模态框和会话状态。

原因很简单：

- 这套编辑器还要支持独立桌面打包
- 以后还可能挂到别的宿主里

所以模型里只保留：

- 文档本身
- 页面本身
- 组件本身
- 保存和导出所需的最小上下文

### 原则 2：内容层和展示壳分开

像这些东西，不应该直接进入“可编辑内容层”：

- 翻页按钮
- 进度条
- 全局浮层提示
- 粒子背景
- 发光背景
- `active / next / prev` 这类展示态类

这些都应该归到：

- 全局装饰层
- 页面装饰层
- 运行时展示状态

### 原则 3：宁可锁定，也别假装可编辑

第一阶段最危险的做法，不是“能力不够”，而是：

- UI 看起来能点
- 用户也能改
- 一保存就跑版

所以复杂节点先锁成只读，后面再慢慢放开。

## 页面模型正式定义

### 1. `DocumentProject`

`DocumentProject` 代表一份正在编辑的静态 HTML 文档。

建议正式字段：

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| `id` | `string` | 当前项目 ID | 会话内唯一 |
| `schemaVersion` | `number` | 模型版本 | 第一阶段从 `1` 开始 |
| `mode` | `"presentation" \| "report"` | 文档模式 | 第一阶段只正式支持 `presentation` |
| `source` | `DocumentSource` | 来源信息 | 宿主无关 |
| `canvas` | `ProjectCanvasConfig` | 全局画布配置 | 固定尺寸优先 |
| `pages` | `DocumentPage[]` | 页面数组 | 至少 1 页 |
| `assets` | `DocumentAsset[]` | 资源数组 | 外链图片等 |
| `warnings` | `ProjectWarning[]` | 导入和保存警告 | 不可丢 |
| `meta` | `ProjectMeta` | 附加信息 | 非编辑主链路 |

补充说明：

- `source` 不直接写死成 CodingNS 工作区结构
- `canvas` 放全局页面尺寸和缩放基准
- `warnings` 要留着，不要只在导入阶段弹一下就没了

### 2. `DocumentSource`

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| `kind` | `"codingns" \| "desktop"` | 来源宿主 | 第一阶段二选一 |
| `path` | `string` | 文件路径 | CodingNS 可相对，桌面可绝对 |
| `version` | `string \| null` | 文件版本 | CodingNS 模式复用现有版本号 |
| `entryHtmlHash` | `string` | 初始 HTML 指纹 | 用于判断整份内容是否异常漂移 |

### 3. `ProjectCanvasConfig`

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| `width` | `number` | 设计宽度 | 像素值 |
| `height` | `number` | 设计高度 | 像素值 |
| `unit` | `"px"` | 设计单位 | 第一阶段只认 `px` |
| `aspectRatioLocked` | `boolean` | 是否锁定页面比例 | 演示文档必须为 `true` |

### 4. `DocumentPage`

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| `id` | `string` | 页面 ID | 稳定标识 |
| `order` | `number` | 页面顺序 | 从 0 开始 |
| `title` | `string \| null` | 页面标题 | 可空 |
| `frame` | `PageFrame` | 页面尺寸和背景 | 固定 |
| `rootNodeId` | `string` | 根节点 ID | 必填 |
| `sourceRef` | `SourceRef` | 原页锚点 | 必填 |
| `runtimeHints` | `PageRuntimeHints` | 运行态提示 | 不参与编辑值保存 |

### 5. `DocumentNode`

第一阶段建议把节点类型定成下面这几种：

| 类型 | 说明 | 第一阶段策略 |
| --- | --- | --- |
| `group` | 容器节点 | 支持 |
| `text` | 纯文本或文本为主节点 | 支持 |
| `image` | 图片节点 | 基础支持 |
| `shape` | 简单图形块、卡片块、线条块 | 条件支持 |
| `html` | 无法进一步结构化但需要保留的 HTML 片段 | 只读 |
| `svg` | 内联 SVG 或复杂矢量内容 | 只读 |
| `decoration` | 背景、粒子、光效、全局装饰 | 默认只读 |

正式字段建议：

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| `id` | `string` | 节点 ID | 项目内唯一 |
| `type` | `DocumentNodeType` | 节点类型 | 见上表 |
| `name` | `string` | 节点显示名 | 图层面板使用 |
| `editable` | `boolean` | 是否允许直接编辑 | 必填 |
| `lockedReason` | `string \| null` | 锁定原因 | 锁定时必填 |
| `box` | `NodeBox` | 位置和尺寸 | 页面坐标 |
| `style` | `DocumentNodeStyle` | 白名单样式 | 非白名单不入模 |
| `content` | `DocumentNodeContent` | 文本或资源内容 | 按类型变化 |
| `children` | `string[]` | 子节点列表 | 容器型使用 |
| `sourceRef` | `SourceRef` | 原节点锚点 | 必填 |
| `patchStrategy` | `PatchStrategy` | 保存时怎么回写 | 必填 |
| `runtimeFlags` | `string[]` | 运行态提示 | 不参与稳定保存 |

## 只读与可编辑规则

### 可编辑节点

第一阶段允许直接编辑的节点：

- `text`
- 以文本为主的 `group`
- 普通卡片容器
- 常规图片块
- 简单绝对定位块

判定标准：

1. 节点在初始 DOM 中稳定存在
2. 节点内容主要由文本、背景、边框、间距构成
3. 节点保存后不会破坏兄弟节点布局关系

### 条件可编辑节点

这些节点可以进入模型，但要限制能力：

- `image`
- `shape`
- 局部绝对定位图表块

限制方式：

- 允许移动和缩放
- 允许改基础样式
- 不允许改复杂内部结构

### 默认只读节点

这些节点第一阶段默认只读：

- `svg`
- `html`
- `decoration`
- 带强运行态状态类的节点
- 粒子背景、光效背景、翻页控件

原因：

- 一改就容易破坏视觉稳定性
- 回写成本高
- 对当前核心价值帮助不大

## 样式白名单

### 第一阶段允许进模型的样式

| 分类 | 字段 | 说明 |
| --- | --- | --- |
| 文字 | `fontFamily` | 白名单字体 |
| 文字 | `fontSize` | 像素 |
| 文字 | `fontWeight` | 常见粗细 |
| 文字 | `lineHeight` | 数值或像素 |
| 文字 | `letterSpacing` | 选做，建议只支持像素 |
| 文字 | `color` | 直接色值 |
| 文字 | `textAlign` | 左中右 |
| 文字 | `whiteSpace` | 普通、保留换行 |
| 盒模型 | `padding` | 四边值 |
| 盒模型 | `margin` | 仅必要时进入模型 |
| 边框 | `borderRadius` | 像素 |
| 边框 | `borderWidth` | 像素 |
| 边框 | `borderColor` | 色值 |
| 背景 | `backgroundColor` | 色值 |
| 透明度 | `opacity` | 0 到 1 |

### 第一阶段不进模型的样式

- `filter`
- `backdrop-filter`
- `mix-blend-mode`
- 复杂 `box-shadow`
- 复杂 `text-shadow`
- `animation`
- `transition`
- 3D `transform`

注意：

- `transform` 不是完全不用
- 但不能直接把原始 `transform` 原样开放给用户编辑

第一阶段建议做法：

- 导入时把可换算的位置与尺寸折算到 `box`
- 原始复杂 `transform` 保留在只读节点或原始样式片段里

## 回写锚点 `SourceRef`

### 为什么不能只靠选择器

只靠 `.card`、`.panel` 这种类名回写，迟早出事。

原因：

- 同类节点很多
- 复制组件后类名会重复
- 后续模板自己也可能调整结构

### 第一阶段锚点策略

`SourceRef` 至少要包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `pageId` | `string` | 所属页面 |
| `selectorPath` | `string[]` | 从页根到节点的稳定路径 |
| `nodeTag` | `string` | 原始标签名 |
| `nodeIndex` | `number` | 同级索引 |
| `dataNodeId` | `string \| null` | 若已有内部标记则直接复用 |

保存后新增节点，应补 `data-cns-node-id`。

一句人话：

第一阶段要允许“老节点靠路径定位，新节点靠内部 ID 定位”双轨并存。

## 回写策略 `PatchStrategy`

第一阶段建议只允许这 4 类回写策略：

| 策略 | 说明 | 适用场景 |
| --- | --- | --- |
| `text_only` | 只改文本内容 | 标题、正文、列表项 |
| `style_only` | 只改内联样式 | 位置、尺寸、颜色、字号 |
| `text_and_style` | 同时改文本和样式 | 普通文本块 |
| `replace_node` | 整节点替换 | 复制出来的新节点、无法安全补丁的简单块 |

第一阶段禁止：

- `replace_page` 作为默认策略
- `replace_document` 这种偷懒方案

只有在明确失败降级时，才允许整页重生成，而且必须写警告。

## 复制节点规则

复制节点不是简单 `cloneNode(true)` 就完事。

第一阶段要求：

1. 新节点生成新的 `id`
2. 新节点写入新的 `data-cns-node-id`
3. 复制时只继承白名单样式和允许的内容
4. 不把运行态类、展示态类一起复制过去

## 对 `design.md` 的直接收紧建议

当前设计里需要补充这几个硬规则：

1. `DocumentNode.type` 要新增 `svg` 和 `decoration`
2. `DocumentNode` 要新增 `editable`、`lockedReason`、`patchStrategy`
3. `DocumentProject` 要新增 `schemaVersion` 和更明确的 `source`
4. `DocumentNodeStyle` 必须明确是白名单，不是原始 CSS 全量镜像
5. `SourceRef` 不能只靠一个选择器字符串

## 结论

页面模型的目标不是“把 HTML 完整复制一份到内存里”，而是：

- 只抽出后续真的要编辑和保存的稳定部分
- 把高风险部分锁起来
- 让回写路径尽量局部、尽量可控

这才是好品味。  
不是把所有东西都做成“理论上可编辑”，而是先把真正有价值、真正能稳定保存的部分做扎实。
