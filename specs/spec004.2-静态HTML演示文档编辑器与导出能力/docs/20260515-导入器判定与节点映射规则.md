# 20260515-导入器判定与节点映射规则

## 这份文档要回答什么

这份文档只回答两件事：

1. 一份 HTML 到底能不能进入演示文档编辑器
2. 进入以后，页内 DOM 怎么变成 `DocumentNode`

这一步不解决：

- 画布怎么渲染
- 工具栏怎么排
- 导出怎么做

## 总体原则

### 原则 1：先判定，再导入

不要一拿到 HTML 就直接开始建节点树。

正确顺序是：

1. 先判断是不是演示文档候选
2. 再识别页面边界
3. 再过滤展示壳
4. 最后才做节点映射

### 原则 2：先保结构稳定，再追求覆盖率

第一阶段的目标不是“尽量多吃 HTML”，而是“吃进去以后还能稳定保存和导出”。

所以：

- 少支持一点没问题
- 一旦支持，就要尽量稳定

### 原则 3：页内映射走自顶向下

不要从叶子节点往上拼。

正确做法是：

1. 先找页根
2. 再找主内容容器
3. 再把容器内块状结构映射成节点
4. 最后才细拆文本和资源

## 第一阶段导入器入口判定

### 1. 基础前置条件

满足下面全部条件，才进入下一步：

1. 文件扩展名是 `.html` 或 `.htm`
2. 文本内容是合法 HTML
3. 初始 DOM 中存在明确分页节点
4. 页节点数量大于等于 1

不满足时：

- 直接退回普通 HTML 预览或源码编辑

### 2. 分页节点识别顺序

第一阶段按下面顺序探测：

1. `body .deck > section.slide`
2. `body .deck > .slide`
3. `section.slide`
4. `.slide[data-title]`
5. `.slide[data-slide]`
6. `body > .deck > *`，但前提是这些子节点数量稳定且视觉上代表独立页面

说明：

- 优先找语义更明确的分页结构
- 越往后越宽松，也越危险

### 3. 直接拒绝进入编辑器的情况

出现下面任意情况，第一阶段直接拒绝：

- 页面节点主要靠脚本运行后才插入
- 页面主体内容主要在 `canvas`
- 页面数量极不稳定，或分页结构互相嵌套混乱
- 页内主要布局依赖连续动画帧或运行时计算
- 整页几乎没有稳定文本和块级内容，只剩纯视觉特效

## 导入阶段的 4 个输出

`HtmlPresentationProbe` 第一阶段要输出这 4 类结果：

### 1. `supported`

- `true` / `false`

### 2. `mode`

- 第一阶段固定输出 `presentation`

### 3. `pages`

至少包含：

- 页面顺序
- 页面标题
- 页面根节点引用
- 页面尺寸推断

### 4. `warnings`

至少记录：

- 哪些页包含复杂 `svg`
- 哪些页包含重装饰层
- 哪些节点会被只读导入
- 哪些结构可能在保存时降级成节点替换

## 页面边界识别规则

### 1. 页标题来源

按顺序取值：

1. `data-title`
2. 页面头部主要标题
3. `Slide 01 / XXX` 这类页眉文本
4. 回退为 `第 N 页`

### 2. 页面尺寸推断

按顺序取值：

1. 样板中明确的设计尺寸变量，例如 `--deck-width / --deck-height`
2. 页面容器固定宽高
3. `viewport` 推导结果
4. 默认回退值：
   - `1600 x 900` 用于典型 16:9 演示文档

### 3. 页面级运行态壳过滤

这些内容默认不进入页面主内容树：

- 翻页按钮
- 页进度条
- 全局目录浮层
- 提示条
- 粒子背景
- 背景 glow
- 只用于切页控制的脚本附属节点

这些内容应记为：

- 页面装饰
- 全局装饰
- 运行态外壳

## 节点映射顺序

### 第 1 步：识别主内容容器

页根下面优先找这些节点作为主内容容器：

- `.panel`
- `.slide-shell`
- `.content`
- `.hero-main`
- `.head + .content`

如果页根本身就是内容容器，也允许直接使用页根。

### 第 2 步：识别块级节点

优先映射成块级节点的结构：

- `card`
- `panel`
- `metric`
- `kpi`
- `module-card`
- `feature-card`
- `timeline-step`
- `diagram-box`
- 表格外层块

映射原则：

- 一个视觉上独立的内容块，优先变成一个 `group` 或 `shape`
- 不要一开始就把每个 `div` 都变成节点

### 第 3 步：识别文本节点

这些节点优先映射成 `text`：

- `h1 h2 h3 h4`
- `p`
- `li`
- 单独存在的 `span`，但前提是它承担独立文案而不是纯装饰
- 表格里的稳定文本单元格

文本节点合并规则：

- 同一视觉块内连续文本，如果共享同一定位上下文，可以先并成一个文本节点
- 不要把一句话拆成 10 个 `span` 节点

### 第 4 步：识别图片节点

这些节点映射成 `image`：

- `img`
- 背景图片明确且承担主要内容表达的块

但注意：

- 纯装饰背景图默认不作为可编辑图片节点

### 第 5 步：识别只读节点

这些节点第一阶段直接映射成只读：

- `svg`
- 无法安全结构化的复杂 `html` 片段
- 装饰背景层
- 粒子和发光层
- 带强展示状态的动画壳节点

## 节点类型映射规则

| 原始结构 | 目标节点类型 | 第一阶段策略 |
| --- | --- | --- |
| 块级容器 | `group` | 支持 |
| 纯文本块 | `text` | 支持 |
| 图片 | `image` | 基础支持 |
| 卡片背景、分隔条、标签块 | `shape` | 条件支持 |
| 复杂 HTML 片段 | `html` | 只读 |
| 内联 SVG | `svg` | 只读 |
| 背景与装饰层 | `decoration` | 只读 |

## 位置和尺寸换算规则

### 1. 优先来源

优先使用：

- `getBoundingClientRect` 对应的稳定布局结果
- 再换算到页面坐标系

而不是直接存原始 CSS：

- `top / left / transform`

### 2. 绝对定位节点

对于常规绝对定位节点：

- 允许导入为可编辑节点
- 但要把位置和尺寸落到 `box`

对于复杂 `transform` 节点：

- 能拆出稳定 `box` 就导入
- 拆不稳就转只读

### 3. 网格和弹性布局节点

对于 `grid / flex`：

- 第一阶段不要求完整保存其布局语义
- 导入时先落地为稳定视觉框

一句人话：

第一阶段更在乎“看起来不跑”，不是“完整保留原 CSS 布局思想”。

## 文本内容规则

### 可直接编辑

- 标题
- 正文段落
- 列表项
- 卡片说明文字
- 页脚标题文字

### 只读或受限

- 全大写装饰标签，如果同时承担语义和装饰，可编辑文字但限制样式
- 由多个 `span` 拼接出的炫技文案，先尽量合并，不稳就只读

## 页内特殊结构处理

### 1. 表格

第一阶段表格按保守方案：

- 把整张表作为 `group`
- 单元格文字可做第二优先级支持

不要一开始就做全功能表格编辑器。

### 2. 图表

简单柱状图：

- 如果本质是几个普通 `div.bar`
- 可以映射成 `shape + text` 组合

复杂关系图：

- 默认只读

### 3. SVG 架构图

默认只读。

原因：

- 一旦开放编辑，马上就变成另一套矢量编辑器问题

## 导入结果质量分级

导入完成后，建议给每页一个质量等级：

| 等级 | 含义 |
| --- | --- |
| `A` | 主要节点都可编辑，风险低 |
| `B` | 主要内容可编辑，但有部分只读复杂节点 |
| `C` | 页面可显示，但大部分关键块只读，不建议作为第一阶段主样板 |

这不是给用户看的炫技指标，而是给后续实现和验收看的。

## 第一阶段判定结论

基于现有样板，第一阶段导入器应明确支持：

- `section.slide`
- `.slide`
- `[data-title]`
- `[data-slide]`
- 固定 DOM 中完整存在的多页结构

并且明确过滤：

- 全局展示壳
- 翻页控制
- 运行态状态类
- 重动画装饰层

## 对后续任务的直接影响

### 对任务 2.1

`DocumentProjectBuilder` 必须按本文件的顺序实现：

1. 先判定
2. 再分页
3. 再过滤
4. 再映射

不能把这些步骤打散到不同页面组件里。

### 对任务 2.2

编辑器 UI 只能给：

- `editable = true` 的节点开放直接编辑
- `lockedReason` 非空的节点显示只读提示

### 对任务 3.1

回写逻辑必须尊重：

- `patchStrategy`
- `SourceRef`
- 只读节点不应被误写

## 结论

导入器不是“把 DOM 树复制一份”。

导入器的职责是：

- 判断值不值得进编辑器
- 把可编辑内容提纯出来
- 把危险内容锁起来

这一步如果做脏了，后面所有编辑、保存和导出都会跟着脏。
