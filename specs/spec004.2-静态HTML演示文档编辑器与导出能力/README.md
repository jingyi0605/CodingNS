# spec004.2-静态HTML演示文档编辑器与导出能力

## 当前定位

`spec004` 解决的是“文件能不能打开、能不能保存、能不能挂到会话里”。

`spec004.1` 解决的是“文件打开以后，图片、PDF、HTML 至少别难看、别难用”。

但这还不够。用户现在要的不是“看一个 HTML 文件”，而是：

- 把单文件 HTML 演示稿当成真正的 PPT 去逐页编辑
- 在画布里直接改文字、改位置、改大小、复制组件
- 导出成版式尽量一致的 `PDF` 和 `PPTX`
- 这套能力既能塞进 CodingNS 文件管理，也能单独打包成桌面应用

一句人话：

这不是再补一个预览器，这是要补一个“静态 HTML 文档编辑内核”。

## 计划覆盖

- 从文件管理中识别并打开静态 HTML 演示文档
- 用 `PPT` 视图逐页展示和编辑单文件 HTML
- 支持常见文本组件的文字、字体、字号、换行、位置、大小调整
- 支持组件复制、拖拽、缩放、基础样式调整
- 把编辑结果回写为单文件 HTML
- 导出 `PDF`
- 导出 `PPTX`
- 抽出可复用编辑内核，支持独立桌面打包

## 依赖关系

- 前置依赖：`spec004`、`spec004.1`
- 主要影响：
  - `apps/host/src/modules/file/`
  - `apps/host/src/modules/tasks/`
  - `apps/user-app/src/features/conversation/components/`
  - `apps/user-app/src/features/` 下新增静态 HTML 文档编辑器模块
- 后续可承接：
  - HTML 报告文档模式
  - 插件化导出能力
  - AI 生成后的结构化二次编辑
  - Office 文档更深层导入导出

## 本阶段明确不做

- 不把它做成通用网页搭建器
- 不承诺支持任意野生 HTML 一步导入后 100% 结构化编辑
- 不在这一轮解决多人协同编辑
- 不在这一轮承诺导出的 `PPTX` 仍然保持 PowerPoint 内可自由重排的完全语义化结构
- 不把 `docx / xlsx / pptx` 原生导入混进本轮

## 关键边界

### 边界 1：先把“静态 HTML 演示文档”吃稳

样板文件已经证明，当前真实输入是：

- 单文件 HTML
- 内联 CSS
- 少量内联脚本
- 通过 `.slide`、`section.slide`、`[data-slide]` 等结构表达页面

所以第一阶段优先解决这种格式，不把输入面扩大到“所有网页”。

### 边界 2：编辑内核必须独立于 CodingNS 外壳

CodingNS 只是宿主，不应该把编辑器和文件管理、会话面板、模态框死绑。

否则后面一旦要独立打包，就得再拆一遍，纯属重复劳动。

### 边界 3：导出优先保证版式一致，再谈语义还原

尤其是 `PPTX`，如果一开始就追求“每个文本框和形状都还能在 PowerPoint 里完美继续编辑”，范围会立刻爆炸。

第一阶段先保证：

- 用户看到的版式别跑
- 导出的 `PDF / PPTX` 和编辑器视图尽量一致
