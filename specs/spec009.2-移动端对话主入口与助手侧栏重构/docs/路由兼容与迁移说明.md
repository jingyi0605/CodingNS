# 路由兼容与迁移说明

这份文档只解释一件事：

- 旧的工具路由以后怎么处理，避免历史入口直接失效

## 1. 兼容目标

当前仓库里已经存在这些路由：

- `/workspaces/:workspaceId/tools`
- `/workspaces/:workspaceId/tools/files`
- `/workspaces/:workspaceId/tools/git`
- `/workspaces/:workspaceId/tools/processes`

这次不能粗暴删除。

原因很简单：

- 代码里还有跳转调用
- 用户可能已经收藏过这些地址
- 测试里也可能还在依赖它们

## 2. 迁移规则

| 旧地址 | 新去向 | 说明 |
| --- | --- | --- |
| `/workspaces/:workspaceId/tools` | 当前工作区对话主入口 + 默认打开文件侧页 | 旧工具首页不再作为一级主页面保留 |
| `/workspaces/:workspaceId/tools/files` | 当前工作区对话主入口 + 打开文件侧页 | 保持“看文件”的意图 |
| `/workspaces/:workspaceId/tools/git` | 当前工作区对话主入口 + 打开 Git 侧页 | 保持“看 Git”的意图 |
| `/workspaces/:workspaceId/tools/processes` | 终端页或终端页下兼容子路由 | 进程页暂时不从对话页接管 |

## 3. 没有活动会话时怎么办

这是最容易写脏的地方。

原则：

1. 如果当前工作区有最近会话，优先回到最近会话，再打开对应侧页。
2. 如果当前工作区没有最近会话，先去会话索引页，不强行伪造一个空对话页。
3. 如果连工作区都不存在，回工作区首页。

一句人话：
先保证用户能落地，再谈面板要不要打开。不要为了“保持工具意图”把人送进一个没有上下文的假页面。
