# 需求文档 - spec009.2 移动端对话主入口与助手侧栏重构

状态：Draft

## 简介

`spec009.1` 已经把移动端工作台拆成了更合理的页面结构，但现在还有一个很现实的问题没收尾：

- 对话页还是主要处理“消息流”
- 文件、Git 还留在独立工具页里
- 底部导航上的“工具 / 终端 / 助手”职责分配不顺
- 助手页缺少和主工作台一致的工作区切换头，以及移动端应有的左右侧页

这次要做的不是发明新能力，而是把已经有的能力放到用户真正找得到、滑得到、退得回去的位置上。

## 术语表

- **对话页**：当前移动端会话详情页，以消息流和输入区为核心
- **左侧页**：从主内容页向左滑或通过显式入口呼出的全屏侧页，主要承载列表或辅助面板
- **右侧页**：从主内容页向右滑或通过显式入口呼出的全屏侧页，主要承载当前实体的附加信息和设置
- **文件 / Git 侧页**：挂在对话页左侧页中的两个标签
- **助手页**：当前 `butler` 页面，对外统一叫“助手”
- **助手对话列表**：当前工作区内与助手相关的对话入口列表
- **助手右侧信息栏**：当前助手的 `信息 / 自动化 / 设置` 三个分区

## 范围说明

### In Scope

- 移动端底部导航中“工具 / 终端 / 助手”入口职责重排
- 对话页左滑后的全屏文件 / Git 侧页
- 文件 / Git 侧页右滑或后退返回对话页
- 助手页顶部接入统一工作区切换器
- 助手页右滑对话列表、左滑右侧信息栏
- 助手右侧信息栏增加 `设置` 标签
- 相关 i18n 文案、路由兼容、回退路径和测试

### Out of Scope

- 新增文件、Git、终端、助手后端接口
- 设计新的助手业务模型
- 改桌面端导航
- 改移动端工作区首页和设置页的信息架构

## 需求

### 需求 1：对话页必须重新成为移动端主入口

**用户故事：** 作为用户，我希望进入会话后，文件和 Git 就在当前对话上下文里，而不是再跳去一个平行的工具页。

#### 验收标准

1. WHEN 用户位于移动端对话页 THEN System SHALL 支持左滑呼出文件 / Git 全屏侧页。
2. WHEN 文件 / Git 侧页打开 THEN System SHALL 继续保持当前工作区和当前会话上下文，不得切丢对话状态。
3. WHEN 用户从文件 / Git 侧页右滑、点击返回或触发系统返回 THEN System SHALL 回到当前对话页，而不是跳回工作区首页或其他旧页面。

### 需求 2：文件和 Git 必须从“独立工具主入口”降级为“对话上下文侧页”

**用户故事：** 作为用户，我希望文件和 Git 服务当前对话，而不是和对话抢一级入口。

#### 验收标准

1. WHEN 用户在移动端打开文件 / Git THEN System SHALL 通过对话页左侧页承载，而不是继续把它们当成底部一级导航主入口。
2. WHEN 用户在文件 / Git 之间切换 THEN System SHALL 提供明确标签切换，而不是要求用户反复回退后再进入。
3. WHEN 旧路由 `/workspaces/:workspaceId/tools`、`/tools/files`、`/tools/git` 仍被访问 THEN System SHALL 提供兼容跳转，不允许直接失效。

### 需求 3：底部导航里的工具入口必须改成终端入口

**用户故事：** 作为用户，我希望底部那个入口点开后就是终端，不想再先进工具页再找终端。

#### 验收标准

1. WHEN 用户点击原工具按钮位置 THEN System SHALL 直接进入终端页面。
2. WHEN 用户已经在终端页面 THEN System SHALL 正确高亮底部终端入口。
3. WHEN 没有当前工作区上下文 THEN System SHALL 提供合理回退路径，不得进入空白死页。

### 需求 4：底部导航里的终端入口必须改成助手入口

**用户故事：** 作为用户，我希望助手是一级主入口，因为它已经不是附属功能。

#### 验收标准

1. WHEN 用户点击原终端按钮位置 THEN System SHALL 直接进入助手页面。
2. WHEN 用户已经在助手页面 THEN System SHALL 正确高亮底部助手入口。
3. WHEN 用户从其他一级页面切到助手 THEN System SHALL 保持当前工作区上下文连续。

### 需求 5：助手页顶部必须使用和其他页面一致的工作区切换器

**用户故事：** 作为用户，我希望在助手页切工作区的方式和对话页、终端页一致，而不是再学一套头部。

#### 验收标准

1. WHEN 用户进入移动端助手页 THEN System SHALL 使用统一的 `MobileWorkspaceSwitcherHeader`。
2. WHEN 用户在助手页切换工作区 THEN System SHALL 同步切换到目标工作区的助手页面。
3. WHEN 当前工作区不存在 THEN System SHALL 给出空态而不是渲染损坏头部。

### 需求 6：助手页必须支持左右双侧页

**用户故事：** 作为用户，我希望助手页像一个完整工作台：右滑看对话列表，左滑看当前助手信息和设置。

#### 验收标准

1. WHEN 用户在助手页向右滑 THEN System SHALL 打开助手对话列表侧页。
2. WHEN 用户在助手页向左滑 THEN System SHALL 打开当前助手右侧信息栏。
3. WHEN 任一侧页已经打开 THEN System SHALL 提供明确的关闭路径，并避免和主内容滚动手势打架。

### 需求 7：助手右侧信息栏必须支持三段切换

**用户故事：** 作为用户，我希望在助手页里直接查看信息、自动化和设置，不想再跳转到别处找设置。

#### 验收标准

1. WHEN 用户打开助手右侧信息栏 THEN System SHALL 显示 `信息 / 自动化 / 设置` 三个标签。
2. WHEN 用户在三个标签间切换 THEN System SHALL 保持当前助手上下文不变。
3. WHEN 助手设置还没有对应内容 THEN System SHALL 至少给出明确占位和后续扩展位置，不允许空白无反馈。

### 需求 8：新的滑动结构不能破坏现有移动端返回和系统手势

**用户故事：** 作为用户，我希望左右滑是帮我省事，不是和系统返回互相抢。

#### 验收标准

1. WHEN 页面运行在 iOS 或 Android 紧凑宽度场景 THEN System SHALL 让自定义滑动只在明确区域和明确方向生效。
2. WHEN 系统返回或浏览器返回触发 THEN System SHALL 优先回退当前已打开的侧页，再回退页面栈。
3. WHEN 页面内容处于纵向滚动中 THEN System SHALL 避免轻易误判成横向切页。

### 需求 9：现有工作区、会话、终端、助手上下文必须连续

**用户故事：** 作为用户，我希望切页面只是换视图，不是把上下文全丢掉。

#### 验收标准

1. WHEN 用户在对话页打开文件 / Git 侧页 THEN System SHALL 保持当前会话、工作区和未发送输入不丢失。
2. WHEN 用户在终端页和助手页之间切换 THEN System SHALL 保持当前工作区连续。
3. WHEN 用户从助手页打开对话列表或右侧信息栏 THEN System SHALL 不重置当前助手页已有数据状态。

## 非功能需求

### 非功能需求 1：路由兼容

1. WHEN 旧的移动端工具相关路由仍被访问 THEN System SHALL 提供可预期的兼容跳转。
2. WHEN 新结构引入新的查询参数或面板状态 THEN System SHALL 保证刷新后不会落入错误页面。

### 非功能需求 2：交互清晰

1. WHEN 页面提供滑动手势 THEN System SHALL 同时保留可见按钮或系统返回路径，不能只靠“记住手势”。
2. WHEN 用户进入新结构 THEN System SHALL 让入口命名和页面职责一致，避免“按钮名和页面内容对不上”。

### 非功能需求 3：实现边界

1. WHEN 实现本子 Spec THEN System SHALL 只改 `apps/user-app` 和对应 Spec 文档。
2. WHEN 新增或修改用户可见文案 THEN System SHALL 全部进入 i18n 字典，不允许硬编码。

## 成功定义

- 对话页重新成为移动端主入口，文件 / Git 不再是平行主页面。
- 底部导航中的终端和助手职责清楚，按钮名和页面内容一致。
- 助手页补齐统一头部、对话列表侧页和右侧信息栏。
- 旧工具路由仍能走通，不会把现有用户直接打断。
