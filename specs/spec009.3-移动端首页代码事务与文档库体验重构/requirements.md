# 需求文档 - spec009.3 移动端首页代码事务与文档库体验重构

状态：Draft

## 简介

当前移动端页面已经落后于 PC 端产品结构。

现在 PC 端已经不是“助手会话”一个中心，而是两条线：

- **代码模式**：有工作区，有代码会话，有文件、Git、终端等工具
- **事务模式**：没有代码工作区概念，包含文档库、对话、工作台

移动端也要跟上这个结构，但不能照搬 PC 三栏。手机上最重要的是：

1. 首页先告诉用户“现在有什么要处理”
2. 对话负责轻量事务会话，不绑定代码工作区
3. 代码负责工作区切换、代码会话和代码工具
4. 文档页必须贴合当前文档库真实功能：目录、收藏、标签、对象详情
5. 工作台负责事务事项的进度和待确认结果

一句话：移动端要变成 CodingNS 的随身指挥台，不是桌面端缩小版。

## 术语表

- **事务模式**：不绑定代码工作区的全局事务视图，包含文档库、轻量对话、工作台。
- **代码模式**：绑定代码工作区的开发视图，包含工作区切换、代码会话、文件、Git、终端。
- **首页**：移动端一级入口，聚合代码和事务的待处理信息。
- **轻量对话**：事务模式里的对话，不带本地代码工具。
- **代码会话**：绑定某个代码工作区的会话，可使用文件、Git、终端等工具。
- **文档库**：当前事务视图里的全局文档库，PC 端已有目录、收藏、标签、对象详情等能力。
- **对象详情**：PC 文档库右侧详情栏，展示当前文件夹、文档或标签的详情和标签操作。

## 范围说明

### In Scope

- 移动端底部导航改成 `首页 / 对话 / 代码 / 文档 / 工作台`
- 首页顶部头像承载原“我的 / 设置 / 通知 / Host 管理”等低频入口
- 首页聚合事务待处理、代码工作区已完成未读会话、运行中任务和最近更新
- 对话页定位为事务轻量会话入口，不绑定代码工作区
- 代码页保留当前移动端顶部工作区切换器，展示当前工作区的代码会话、Git、终端、文件入口
- 文档页按照当前 PC 文档库能力重做移动端结构：浏览、收藏、标签、详情
- 工作台页展示事务事项、待确认结果、进行中和已完成状态
- 对现有 `apps/user-app` 移动端路由、壳、i18n、样式和相关测试进行规划

### Out of Scope

- 不重写 Host 文档库索引服务
- 不新增文档库后端数据模型
- 不重写桌面端事务三栏
- 不把手机做成完整 IDE，不在本 Spec 做重型代码编辑器
- 不在本 Spec 改 Android/iOS 原生打包链路
- 不在本 Spec 引入新的文档格式解析能力

## 需求

### 需求 1：底部导航必须匹配新的产品结构

**用户故事：** 作为移动端用户，我希望底部导航的入口和当前产品结构一致，不再看到过时的“助手 / 终端 / 设置”组合。

#### 验收标准

1. WHEN 用户进入移动端默认壳 THEN System SHALL 显示 `首页 / 对话 / 代码 / 文档 / 工作台` 五个底部入口。
2. WHEN 用户点击任一底部入口 THEN System SHALL 进入对应页面，并正确高亮当前入口。
3. WHEN 用户需要设置、通知、账号或 Host 管理 THEN System SHALL 通过首页顶部头像进入，不再占用底部导航。
4. WHEN 旧移动端路由仍被访问 THEN System SHALL 提供合理跳转或兼容页面，不直接落入空白页。

### 需求 2：首页必须同时聚合代码和事务的待处理信息

**用户故事：** 作为用户，我希望打开手机后先看到今天要处理什么，而不是先判断自己该去代码页还是事务页。

#### 验收标准

1. WHEN 用户打开首页 THEN System SHALL 同时展示事务待处理、工作台待确认、文档更新和代码工作区未读信息。
2. WHEN 某个代码工作区的代码会话已完成但用户未读 THEN System SHALL 在首页“等待处理”里显示它，并标明所属工作区。
3. WHEN 首页展示代码信息 THEN System SHALL 只显示摘要和入口，不把文件树、Git diff、终端详情直接塞进首页。
4. WHEN 首页没有待处理项 THEN System SHALL 显示清楚的空态和下一步入口，例如新建对话、进入代码、打开文档库。

### 需求 3：对话页必须是事务轻量会话，不绑定代码工作区

**用户故事：** 作为用户，我希望移动端“对话”是快速问答和事务讨论，不被代码工作区切换器干扰。

#### 验收标准

1. WHEN 用户进入对话页 THEN System SHALL 展示事务轻量会话列表，而不是按代码工作区筛选的代码会话列表。
2. WHEN 用户新建对话 THEN System SHALL 创建轻量事务会话，默认不带代码工作区上下文。
3. WHEN 用户需要关联文档或工作台事项 THEN System SHALL 允许选择事务对象作为上下文，但不强制选择代码工作区。
4. WHEN 旧的代码会话列表入口仍在移动端出现 THEN System SHALL 将其迁移到代码页，不继续叫“对话”。

### 需求 4：代码页必须保留顶部工作区切换器并承载代码会话

**用户故事：** 作为用户，我希望进入代码页后能直接看到上次使用的工作区，也能快速切换到其他工作区继续代码会话。

#### 验收标准

1. WHEN 用户进入代码页 THEN System SHALL 默认显示上次使用或当前代码工作区。
2. WHEN 当前代码工作区存在 THEN System SHALL 继续使用 `MobileWorkspaceSwitcherHeader` 展示工作区名和路径。
3. WHEN 用户点击工作区切换器 THEN System SHALL 展示可切换的代码工作区列表，并保留 Host 切换能力。
4. WHEN 当前工作区有代码会话 THEN System SHALL 展示等待输入、运行中、最近代码会话等分组。
5. WHEN 当前工作区有 Git 变更或终端运行中 THEN System SHALL 在代码页展示摘要入口，但详细操作进入会话内工具或代码工具子页。

### 需求 5：文档页必须贴合当前 PC 文档库真实功能

**用户故事：** 作为用户，我希望手机上的文档页和 PC 文档库是同一套东西，只是换成适合手机的浏览方式。

#### 验收标准

1. WHEN 用户进入文档页 THEN System SHALL 基于当前文档库数据展示目录浏览、收藏、标签、对象详情入口。
2. WHEN 用户处于目录浏览 THEN System SHALL 展示当前目录的子文件夹和直接文档，并支持网格 / 列表显示方式。
3. WHEN 用户进入收藏视图 THEN System SHALL 展示文件夹收藏、标签收藏和标签组合收藏，不用通用“收藏文章”模型替代。
4. WHEN 用户进入标签视图 THEN System SHALL 展示当前标签树、标签数量、已选标签和命中文档列表。
5. WHEN 用户选中文件夹、文档或标签 THEN System SHALL 能在移动端查看对应对象详情。
6. WHEN 文档库未绑定、关闭、刷新中或出错 THEN System SHALL 使用当前文档库状态给出可理解的空态和恢复入口。

### 需求 6：文档对象详情必须能在移动端完成关键操作

**用户故事：** 作为用户，我希望手机上也能查看目录或文档详情，并处理标签、收藏、打开、下载等常用动作。

#### 验收标准

1. WHEN 用户查看文件夹详情 THEN System SHALL 展示当前目录、直接子文件夹数、直接文档数、子树文档数、创建和修改时间。
2. WHEN 用户查看文档详情 THEN System SHALL 展示标题、路径、摘要、大小、更新时间、手动标签、系统标签或来源标签。
3. WHEN 当前对象支持收藏 THEN System SHALL 提供加入收藏和取消收藏入口。
4. WHEN 当前对象支持标签分配 THEN System SHALL 提供添加、移除、推荐标签入口，并复用现有文档库标签能力。
5. WHEN 当前对象支持打开或下载 THEN System SHALL 提供适合移动端的操作入口，不把 PC 右键菜单照搬到手机。

### 需求 7：工作台页必须承载事务事项，而不是代码任务列表

**用户故事：** 作为用户，我希望工作台页看到事务进度、待确认结果和异常，不想和代码会话混在一起。

#### 验收标准

1. WHEN 用户进入工作台页 THEN System SHALL 展示事务事项的待处理、进行中、已完成、异常分组。
2. WHEN 事务事项关联文档或对话 THEN System SHALL 能从卡片进入对应对象。
3. WHEN 代码会话已完成未读 THEN System SHALL 优先在首页等待处理聚合展示，不把工作台页变成代码会话列表。
4. WHEN 工作台没有事项 THEN System SHALL 显示清楚空态和创建/查看入口。

### 需求 8：移动端页面必须高信息密度但不牺牲触控可用性

**用户故事：** 作为手机用户，我希望一屏能看到足够多的信息，但按钮仍然好点、文字仍然看得清。

#### 验收标准

1. WHEN 页面运行在手机竖屏 THEN System SHALL 使用紧凑 Header、紧凑列表、底部导航和必要的横向 chip，不使用大面积空白卡片。
2. WHEN 列表项包含主信息和次信息 THEN System SHALL 保持一眼可读，不把重要信息藏进多层弹窗。
3. WHEN 页面有高频操作 THEN System SHALL 保留足够点击区；低频操作进入更多菜单或 sheet。
4. WHEN 新增用户可见文案 THEN System SHALL 全部走 i18n 字典。

### 需求 9：改造不能破坏 PC 端和已有移动端主链路

**用户故事：** 作为现有用户，我希望移动端重构不会顺手把 PC 端文档库、对话、代码会话搞坏。

#### 验收标准

1. WHEN 桌面端进入事务视图 THEN System SHALL 保持当前 PC 文档库三栏结构不变。
2. WHEN 移动端进入文档页 THEN System SHALL 复用现有文档库数据、接口和状态，不新增一套脱节数据。
3. WHEN 移动端进入代码页 THEN System SHALL 继续复用当前工作区导航和代码会话链路。
4. WHEN 回归测试运行 THEN System SHALL 覆盖底部导航、首页聚合、代码页工作区切换、文档库移动端视图和工作台入口。

## 非功能需求

### 非功能需求 1：性能

1. WHEN 首页加载 THEN System SHALL 优先使用已有快照和列表摘要，避免为了首页同步拉完整文档库或完整 Git diff。
2. WHEN 文档页展示大目录或大标签结果 THEN System SHALL 继续使用分页、虚拟列表或分批加载策略，不一次性渲染全部 13686 份文档。
3. WHEN 用户切换文档库浏览、收藏、标签、详情视图 THEN System SHALL 保持当前已加载状态，避免每次切换都全量刷新。

### 非功能需求 2：可靠性

1. WHEN 文档库索引正在运行 THEN System SHALL 显示索引状态，并允许用户继续浏览已有快照。
2. WHEN 文档库接口失败 THEN System SHALL 显示错误和刷新入口，不让页面白屏。
3. WHEN 旧路由或旧入口被访问 THEN System SHALL 保持可恢复路径。

### 非功能需求 3：可维护性

1. WHEN 实现移动端文档库 THEN System SHALL 复用 `AffairsWorkbenchView` 里的文档库数据模型和 API，不重新发明一套 `mobileDocument` 数据。
2. WHEN 新增移动端页面组件 THEN System SHALL 放在 `apps/user-app` 当前移动端和事务相关目录下，不改历史前端目录。
3. WHEN 新增样式 THEN System SHALL 优先复用当前移动端页面基线，不新增一套割裂的按钮和卡片体系。

## 成功定义

- 底部导航变成 `首页 / 对话 / 代码 / 文档 / 工作台`，用户不再看到过时入口。
- 首页能同时看到事务待处理和代码会话完成未读。
- 对话页不再承担代码工作区会话列表职责。
- 代码页保留工作区切换器，并能继续进入代码会话。
- 文档页能在手机上完成当前 PC 文档库的核心路径：目录浏览、收藏、标签、对象详情。
- PC 端事务视图和现有代码会话链路不被破坏。
