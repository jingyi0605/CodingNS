# spec001.3.3-HOST与PEERHOST资源作用域统一与切换收口

## 当前定位

这是 `spec001.3` 下的新子 Spec。

它只解决一件事：把当前 `HOST / PEERHOST` 下会话、文件、Git、调试、终端这些资源的“归谁管、怎么切、什么时候断开旧连接”彻底说清楚并收口成统一规则。

这次不是继续加一个按钮，也不是继续在各处补 `targetHostId`。

真正要定住的是：

- 左侧展示工作区和真正发请求的工作区，到底是不是同一个 ID
- 当前页面正在看的会话，到底属于当前 HOST 还是某个 PEERHOST
- 切到另一个工作区、另一个会话、另一个 HOST 时，哪些连接必须先断
- URL、缓存 key、订阅 key、请求参数，到底从哪一份“作用域真相”生成
- 哪些模块可以继续保留“当前 HOST 默认行为”，哪些模块必须显式带上目标 HOST

一句人话：
现在的问题不是一个 session 点不开，而是资源身份模型是糊的，所以一切跨 HOST 操作都有机会串线。

## 为什么要单独拆出来

`spec001.3` 解决的是“多 HOST 可切换”。

`spec001.3.2` 解决的是“当前 HOST 代理访问其他 HOST 的仓库和主链路 API”。

但这两层能力叠起来以后，前端工作台内部还缺最后一层：**资源作用域统一**。

如果这层不补：

- 会话可能拿着 PEERHOST 的 `sessionId`，却按主 HOST 的 `workspaceId` 去请求
- 终端可能还挂着旧 HOST 的订阅，却在新工作区里继续显示
- 文件、Git、调试可能共享同一个“当前工作区”状态，但它们实际请求目标已经不同
- 页面 URL 看着像切过去了，连接、缓存和订阅却还活在上一个作用域

继续在组件里零碎补丁，只会把代码搞得更乱。

## 计划覆盖

- 定义统一的资源作用域模型
- 统一“显示工作区”和“实际请求工作区”的关系
- 统一会话、文件、Git、调试、终端的作用域解析入口
- 统一跨 HOST / 跨工作区 / 跨会话切换时的连接清理顺序
- 统一 URL、缓存 key、订阅 key、请求参数的生成规则
- 第一阶段先收口会话与终端，再让文件 / Git / 调试复用同一套规则

## 依赖关系

- 前置依赖：
  - `spec001.3-多HOST接入与跨端切换`
  - `spec001.3.2-当前HOST代理访问其他HOST仓库`
- 强相关依赖：
  - `spec001.2-后端任务调度与主线程压力治理`
  - `spec006-终端核心能力`
  - `spec007-进程管理与启动器`
  - `spec003-对话式主界面与消息运行时`

## 本阶段明确不做

- 不重写后端 Peer HOST 代理协议本身
- 不把多个 HOST 的资源并排混成一个全局聚合舞台
- 不在第一阶段里顺手重构所有工作台组件
- 不改动用户已有的 HOST 连接管理入口和交互文案
- 不新增第二套“临时作用域”概念
