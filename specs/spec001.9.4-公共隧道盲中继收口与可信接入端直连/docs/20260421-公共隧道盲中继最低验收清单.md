# 公共隧道盲中继最低验收清单

日期：2026-04-21

这份清单只验一件事：

`relay-edge` 现在是不是已经退回成真正的盲中继，而不是换个名字继续偷做公网 HTTP / WebSocket 明文代理。

如果下面任何一条不成立，就不要说“中继看不到业务明文”。

## 1. 硬边界

必须同时满足：

1. `relay-edge` 不允许直接处理公网业务 HTTP 请求体。
2. `relay-edge` 不允许直接处理公网业务 WebSocket 明文消息。
3. 客户端和 Host 必须自己完成端到端加密，Channel 端不参与业务解密。
4. `*.tunnelDomain` 只能作为入口标识、跳转入口或提示页，不能直接承载业务代理。
5. H5 业务代码必须从可信主域加载，不能让 `*.tunnelDomain` 直接返回业务页面。

一句人话：

中继只能看到“谁连了谁、什么时候连的、转了多少字节”，不能看到“你请求了哪个业务接口、传了什么 JSON、WebSocket 发了什么业务消息”。

## 2. 入口行为清单

### 2.1 `*.tunnelDomain` 的 HTTP 行为

必须是下面这个矩阵：

| 请求类型 | 预期行为 |
| --- | --- |
| `GET /` 或 `GET /*` | 如果域名绑定有效，302 到可信主域的 `/tunnel-entry`；如果不是有效入口域名，返回 `410 PUBLIC_TUNNEL_PROXY_DISABLED` |
| `POST/PUT/PATCH/DELETE/OPTIONS/HEAD /*` | 一律返回 `410 PUBLIC_TUNNEL_PROXY_DISABLED` |

不允许出现的行为：

1. `relay-edge` 直接把 `/api/*` 转给 Host。
2. `relay-edge` 直接回业务 HTML。
3. `relay-edge` 直接读业务 body 再转发。

### 2.2 `*.tunnelDomain` 的 WebSocket 行为

必须是下面这个矩阵：

| 请求类型 | 预期行为 |
| --- | --- |
| 旧公网业务 `ws(s)://*.tunnelDomain/*` | 一律关闭，close code `1008`，reason `PUBLIC_TUNNEL_PROXY_DISABLED` |
| 正式隧道 `/ws?sessionId=...&role=downstream&connectTicket=...` | 只允许已经过 `connect-init` / `reserve` 的正式会话接入 |
| Host 上游 `/ws?role=host-upstream&bindingId=...&challengeId=...&proof=...` | 只允许通过 challenge 校验后的 Host 长连 |

## 3. 抓包与日志验收

### 3.1 抓包验收

最少做这几件事：

1. 用桌面客户端或可信 H5 发一个真实业务请求。
2. 在 `relay-edge` 所在机器抓包，只允许看到 TLS/WSS 密文和隧道元数据方向，不能看到业务 URL、JSON、业务 WebSocket 文本。
3. 同一次请求在 Host 本地可以正常解密并落到真实业务接口。

如果你在 `relay-edge` 侧还能直接看到 `/api/login`、`/ws/terminal`、业务 JSON、终端输入输出，那就说明架构还是脏的，验收失败。

### 3.2 日志验收

默认日志里只允许出现这些信息：

1. `bindingId`
2. `sessionId`
3. `tunnelDomain`
4. `usageId`
5. 连接建立、关闭、限流、余额耗尽这类状态

默认日志里不允许出现：

1. 业务请求路径正文
2. 业务请求体
3. 业务响应体
4. 业务 WebSocket 消息正文
5. E2EE 明文前后的 payload

## 4. 存储验收

数据库、Redis 或其他共享状态里，只允许保留这些内容：

1. 账号、绑定、域名、额度、订单这类控制面数据
2. 会话元数据
3. Host challenge、connect ticket、usage 幂等键这类短期控制字段
4. 流量统计

不允许把这些东西写进去：

1. 业务 HTTP 请求体
2. 业务 HTTP 响应体
3. 业务 WebSocket 消息明文
4. 客户端与 Host 的会话解密结果

## 6. 最低人工验收动作

发布前至少人工确认下面这些：

1. 直接访问 `https://<tunnelDomain>/demo`，不会再看到 Host 业务页面，只会被引导到可信主域入口页或明确拒绝。
2. 直接用旧公网业务 WebSocket 入口连接，会被明确拒绝。
3. 从可信主域加载的 H5 可以完成 `connect-init -> downstream ws(connectTicket) -> E2EE`。
4. 桌面客户端可以走同一套客户端隧道 SDK 成功接入。
5. Host 只维持一条持久上游信道，不会按每个会话反复 claim。

## 7. 失败判定

只要出现下面任一情况，就视为不合格：

1. `relay-edge` 新增了业务 HTTP 转发代码。
2. `relay-edge` 新增了业务 WebSocket 明文桥接代码。
3. `*.tunnelDomain` 再次直接返回业务页面或代理业务接口。
4. 默认日志开始记录业务正文。
5. 数据库存了业务明文。

这份清单不是建议，是底线。
