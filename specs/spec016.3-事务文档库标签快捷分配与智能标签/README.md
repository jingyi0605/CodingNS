# spec016.3-事务文档库标签快捷分配与智能标签

## 这份 Spec 现在只解决什么

这份 Spec 只写当前要做的标签系统。

一句话：

**让用户可以在文档库里更快地打手动标签，同时正式支持可管理、可解释的智能标签。**

## 这次要交付什么

### 1. 快捷手动标签

- 文件详情里的标签输入框直接支持搜索已有标签
- 输入不存在的标签名时，可以当场新建并分配
- 文件夹详情也用同一套分配逻辑，不再只给一排静态按钮
- 右键文件、文件夹时，也能用同一套快捷分配入口

### 2. 文件夹标签绑定长期生效

- 给文件夹分配的标签，不只作用到当前已有文件
- 该文件夹和子文件夹后续新增的文件，也会自动带上这份文件夹标签结果

### 3. 智能标签

- 标签管理模态框里支持创建和维护智能标签
- 智能标签可以挂到现有标签树任意位置，不额外长第二棵树
- 每个智能标签支持多条规则
- 规则支持“与 / 或 / 非”三种关系
- 规则支持四类条件：
  - 文件名包含指定字符
  - 文件内容包含指定字符
  - 指定文件类型
  - 文件修改时间范围

## 这次明确不做什么

- 不做 AI 自动起标签名
- 不做推荐标签树
- 不做推荐批次导入
- 不做跨工作区标签模板
- 不做复杂嵌套表达式编辑器，第一版只做线性规则列表
- 不把智能标签单独做成第二套树或第二套分类系统

## 这次的硬边界

### 边界 1：标签树仍然只有一套

无论是普通手动标签，还是带规则的智能标签，都挂在同一棵 `tags` 树里。

### 边界 2：分配入口统一

文件详情、文件夹详情、右键菜单，最终都走同一套“搜索 / 新建 / 分配”交互和同一套 Host 能力。

### 边界 3：智能标签必须可解释

每个命中的智能标签，都要能说清楚：

- 命中了哪条规则
- 为什么命中
- 它和手动标签、文件夹继承标签谁优先

### 边界 4：后台链路必须继续走 TaskManager

只要涉及标签重算、索引后补标签、规则生效刷新，就继续走现有后台任务体系，不允许新长私有 timer 或 inflight。
