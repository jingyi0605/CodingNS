# 需求文档 - spec016.3-事务文档库标签快捷分配与智能标签

状态：Draft

## 简介

事务文档库的标签系统现在要解决两个真问题：

1. 现在手动打标签太慢，创建标签和分配标签被拆开了
2. 现在没有正式可用的智能标签，很多重复劳动只能靠人手反复点

这次目标很明确：

**把“创建标签、分配标签、智能打标签”收成一套用户能真正用起来的正式标签系统。**

## 术语表

- **System**：`CodingNS`
- **标签定义**：标签树里的一个正式节点，包含名称、路径、父子关系和状态
- **手动文件标签**：用户直接给某个文件分配的标签
- **文件夹标签绑定**：用户给某个文件夹分配的标签，作用到该文件夹及其子树文件
- **智能标签**：带规则的正式标签，规则命中后自动出现在文件标签结果里
- **标签快速分配器**：文件详情、文件夹详情、右键菜单共用的标签搜索 / 新建 / 分配组件

## 范围说明

### In Scope

- 标签树继续作为唯一正式标签结构
- 文件详情里快捷搜索、快捷新建、快捷分配标签
- 文件夹详情里快捷搜索、快捷新建、快捷绑定标签
- 右键文件、文件夹时快捷分配标签
- 标签管理模态框里维护标签树、批量修改 / 删除、智能标签规则
- 智能标签规则的保存、读取、执行和结果解释
- 文件新增、刷新、重扫后自动补齐文件夹标签和智能标签结果

### Out of Scope

- AI 自动总结标签
- 标签推荐批次
- 标签模板市场
- 多层嵌套布尔表达式编辑器
- 基于用户行为自动学习规则

## 需求

### 需求 1：系统必须支持更快的手动标签分配

1. WHEN 用户在文件详情页输入标签名 THEN System SHALL 检索已有标签并展示可选结果。
2. WHEN 用户输入的标签名不存在 THEN System SHALL 支持在当前入口直接新建标签并立即分配给该文件。
3. WHEN 用户在文件夹详情页输入标签名 THEN System SHALL 使用和文件详情页一致的搜索、新建和分配逻辑。
4. WHEN 用户从文件或文件夹的右键菜单进入标签分配 THEN System SHALL 使用和详情页一致的搜索、新建和分配逻辑，而不是只展示固定几个标签按钮。

### 需求 2：系统必须支持文件夹标签绑定持续生效

1. WHEN 用户给文件夹分配标签 THEN System SHALL 把标签应用到该文件夹及其子文件夹里的所有文件。
2. WHEN 该文件夹树下后续新增文件 THEN System SHALL 在索引或刷新完成后自动补上对应文件夹标签结果。
3. WHEN 用户取消某个文件夹标签绑定 THEN System SHALL 在受影响范围内移除该标签结果。
4. WHEN 文件夹绑定发生变化 THEN System SHALL 只重算受影响目录范围，不整库重跑。

### 需求 3：系统必须支持正式的智能标签

1. WHEN 用户在标签管理模态框中创建标签 THEN System SHALL 允许创建普通标签或带规则的智能标签。
2. WHEN 用户输入的标签名称包含层级路径 THEN System SHALL 自动合并到现有标签树，而不是额外创建独立分类体系。
3. WHEN 智能标签包含多条规则 THEN System SHALL 支持配置规则之间的“与 / 或 / 非”关系。
4. WHEN 用户配置规则内容 THEN System SHALL 至少支持以下条件：
   - 文件名称包含指定字符
   - 文件内容包含指定字符
   - 文件类型属于指定集合
   - 文件修改时间落在指定范围

### 需求 4：系统必须解释标签结果来源

1. WHEN 前端读取文件标签详情 THEN System SHALL 返回手动文件标签、文件夹继承标签、智能标签、系统派生标签这几类来源。
2. WHEN 同一个标签路径同时被多种来源命中 THEN System SHALL 按稳定优先级合并结果。
3. WHEN 标签来自智能规则 THEN System SHALL 返回命中规则和命中证据，方便前端解释。
4. WHEN 标签来自系统派生标签 THEN System SHALL 允许前端弱化显示，不把它混进手动标签候选。

### 需求 5：系统必须把标签管理模态框收成正式管理入口

1. WHEN 用户打开标签管理模态框 THEN System SHALL 让这个模态框承担标签树维护、批量修改、批量删除和智能规则管理。
2. WHEN 用户只是想临时新增标签并分配给某个文件或文件夹 THEN System SHALL 不要求用户先跳到独立模态框创建标签再回来分配。
3. WHEN 用户在模态框里维护智能标签 THEN System SHALL 能同时看到标签树位置和规则内容，避免名称、层级、规则分散在多个入口。

## 非功能需求

### 非功能需求 1：性能和刷新范围

1. WHEN 用户修改单个文件标签、单个文件夹绑定或单个智能标签规则 THEN System SHALL 优先按文档、目录或标签范围增量重算。
2. WHEN 后台执行标签重算 THEN System SHALL 继续走 `TaskManager` 和 helper process，不把重活塞回主线程。

### 非功能需求 2：可维护性

1. WHEN 后续再扩展标签规则 THEN System SHALL 基于同一套标签树、规则 DTO 和重算链路扩展，不再长第二套标签系统。
2. WHEN 前端接入新的标签入口 THEN System SHALL 优先复用同一套标签快速分配器，不重复造按钮堆和私有搜索框。

## 成功定义

- 文件详情、文件夹详情、右键菜单都能直接搜索标签、快速新建标签并完成分配
- 文件夹标签会覆盖当前文件，也覆盖后续新增文件
- 标签管理模态框能正式管理智能标签规则
- 智能标签命中后能在详情里解释来源和证据
- 类型检查、定向测试和人工验收通过
