# spec001.8-登录设备管理与主设备控制

## 当前定位

这是 `spec001` 下的新子 Spec。

它只解决一件事：
把“当前账号在哪些设备登录过、哪些设备还在线、哪些设备是主设备、怎么从主设备退出其他设备”这条链路做成正式能力。

先把最重要的话钉死：

- `token` 不是设备 ID。现在的 `access token / refresh token` 会刷新、会轮换，拿它直接当设备主键是坏设计。
- 设备管理和最近登录记录不是一张表能糊过去的东西。一个是“现在还有哪些设备在用”，一个是“最近发生过哪些登录”。
- 主设备不是唯一，也不是自动猜出来的。它必须由当前登录设备通过管理员密码显式设置。

一句人话：
这次做的是“账号设备管理”，不是“安全中心全家桶”。

## 计划覆盖

- 设置页里的登录设备管理入口
- 当前设备、其他在线设备、最近登录记录的统一展示
- 设备识别模型：`client instance id + client type + 最近来源地址`
- 基于现有 token 体系的设备会话绑定与批量失效
- 主设备的显式设置、取消和权限判断
- 主设备上“退出其他设备”的后端接口和前端交互
- 最近登录记录只保留 10 条的裁剪规则
- 旧登录态兼容和数据库迁移边界

## 本阶段明确不做

- 不做多用户和 RBAC
- 不做登录地区解析
- 不做失败登录审计面板
- 不做设备名称手工重命名
- 不做单个“其他设备”的逐条踢下线，第一阶段只做“退出其他设备”
- 不做短信、邮箱、二次验证码之类的新认证体系
- 不让前端自己上报“来源地址”，来源地址只认 Host 请求上下文
- 不把助手运行时 token、内部自动化 token 混进用户设备列表里
