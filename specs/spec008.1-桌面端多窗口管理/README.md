# spec008.1-桌面端多窗口管理

## 当前定位

这个子 Spec 只解决一件事：

- 在 `Desktop` 端为现有工作台增加可控的多窗口能力

它不解决下面这些偷懒问题：

- 继续把所有东西都塞在一个主窗口里，然后叫它“多窗口”
- 顺手把 `H5` 也做了，最后两边都半死不活
- 一上来就开放聊天窗、终端窗、任意工具窗满天飞
- 默认允许同一个终端在多个窗口里同时抢输入和抢尺寸

一句人话：
先把桌面端“文件 / Git / 进程管理”这几块安全面板拆出去，建立清楚的窗口数据结构和壳层命令；终端先把规矩定死，不乱开交互口子；现有单窗口工作台必须继续能用。

## 计划覆盖

- 桌面端多窗口的范围和边界
- 最小可用 `WindowDescriptor` 定义
- `Tauri` 多窗口命令与前端窗口注册表
- 第一批外部窗口：文件、Git、进程管理
- 终端多窗口规则：单主交互窗，其余明确只读
- 单窗口工作台与多窗口工作台的兼容策略

## 依赖关系

- 前置依赖：`spec008`、`spec004`、`spec005`、`spec007`
- 规则引用：`spec006`（终端核心能力）
- 直接影响：`apps/user-app`、`apps/desktop`

## 本阶段明确不做

- 不做 `H5` 多窗口
- 不做聊天独立窗口
- 不做终端多窗口同时交互
- 不做复杂窗口编排、吸附、平铺布局管理器
- 不把窗口状态真相塞进业务组件里四处分叉
