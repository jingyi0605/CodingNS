# spec006.1-终端日志持久化与历史回放

## 当前定位

这个子 Spec 只解决一件事：

- 把终端输出从“临时缓存”升级成“正式日志”，让日志在断线、刷新、Host 重启后还能继续看

一句人话：
终端输出不能再只是屏幕上飘过去的一串字。它要先在内存里顶住实时交互，再稳定落到本地日志文件里，只有用户明确关闭或删除终端时才清掉。

## 计划覆盖

- 终端日志的保留语义和清理语义
- 内存热缓存、本地日志文件、SQLite 索引三层结构
- 日志写盘、强制 flush、异常恢复规则
- PC 端和移动端统一的历史回放能力
- 终端页向上翻看更早日志的接口与前端加载方式
- `tmux` 与 Windows `embedded-pty`/ConPTY 在日志层的统一行为

## 依赖关系

- 前置依赖：`spec006`
- 直接影响：`apps/host`、`apps/user-app`
- 后续受益：Windows 终端可查看长历史、`tmux` 终端重连恢复、终端日志导出与诊断能力

## 本阶段明确不做

- 不把 `tmux copy-mode` 变成默认页面交互
- 不把大块终端正文全塞进 SQLite
- 不在这个子 Spec 里解决 Windows 持久会话 agent 全量方案
- 不做日志全文检索、跨终端聚合检索、云端同步
- 不把前端 localStorage 快照继续当正式日志真相
