# 任务清单 - spec012-并行项目编排与结果对比（人话版）

状态：Draft

## 这份文档是干什么的

这份清单只做一件事：把“并行项目编排”拆成真正能落地的步骤，避免最后变成一个会新建分支、但不会真正隔离和验证的半残功能。

这份任务清单优先回答：

1. 先把哪些地基立住，不然根本没法并行
2. 第一阶段到底交付什么，不做什么
3. 结果对比和合并建议怎么收口
4. 哪些事已经做完，哪些还只是嘴上说过

## 状态说明

- `TODO`：还没开始
- `IN_PROGRESS`：正在做
- `BLOCKED`：被外部问题卡住
- `IN_REVIEW`：已有结果，待复核
- `DONE`：已经完成，并且已回写状态
- `CANCELLED`：取消，不做了，但必须写原因

规则：

- 只有 `状态：DONE` 的任务才能勾选成 `[x]`
- 每完成一个任务，必须立刻回写本文件
- `BLOCKED` 和 `CANCELLED` 必须写清楚原因
