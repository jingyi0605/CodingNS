# 需求文档 - spec006.2-终端入口与对话工作台布局重构

状态：Draft

## 简介

现在的终端体验有个明显问题：

- 入口藏在左上角菜单里，不顺手
- 点进去是独立终端页，和对话上下文断开
- 回到对话页以后，看不到终端，只能来回切
- 终端标签列表、对话区、终端区的空间关系不稳定，用户每次都得重新适应

这不是要重写终端系统，而是要把终端前端入口和布局收回来。

这轮只做前端：

- 入口改哪里
- 终端在代码视图里怎么出现
- 终端和对话怎么同屏
- 用户手动调好的布局怎么记住

后端现有终端管理逻辑不动。

## 术语表

- **System**：`码不能停` 的代码视图终端前端体验整体
- **快捷应用**：左侧边栏底部的一组固定或用户自定义入口，点一下就能打开对应内容
- **系统快捷应用**：这轮新增的固定入口，至少包括“终端”和“技能”，用户不能删除，也不能编辑
- **终端面板**：嵌在代码视图中间区域里的终端显示区，不再等同于独立终端页面
- **对话区**：代码视图中间区域原本显示会话消息的主区域
- **布局方向**：终端和对话是上下排，还是左右排
- **布局比例**：终端区和对话区各自占多少空间
- **手动关闭**：用户明确点击终端关闭动作，不包含路由切换、页面切换或临时失焦

## 范围说明

### In Scope

- 代码视图左侧边栏底部补出快捷应用区
- 把终端和技能入口并入快捷应用，并固定置顶、不可删、不可编辑
- 保留事务视图原有快捷应用能力，并抽出可复用展示逻辑
- 点击终端快捷应用后，在代码视图中间区域弹出终端面板
- 终端面板支持上下 / 左右布局和拖拽调比例
- 终端标签列表改到终端面板右侧
- 终端面板开关状态、布局方向、比例在工作区范围内恢复
- 从其他页面切回代码视图时，按上次手动状态恢复终端显示

### Out of Scope

- 终端后端逻辑、终端 API、终端实时协议改造
- 终端实例生命周期规则调整
- 新的快捷应用后端存储方案
- 移动端终端工作台重构
- 终端页彻底删除（这轮允许保留兼容路由）

## 需求

### 需求 1：终端入口必须从菜单迁到快捷应用

**用户故事：** 作为代码视图用户，我希望直接从左侧边栏底部打开终端，而不是每次去左上角菜单找入口，这样更顺手。

#### 验收标准

1. WHEN 用户进入代码视图 THEN System SHALL 在左侧边栏底部显示快捷应用区。
2. WHEN 快捷应用区渲染 THEN System SHALL 把“终端”和“技能”放在最前面，并作为系统快捷应用固定展示。
3. WHEN 用户尝试编辑或删除“终端”“技能” THEN System SHALL 明确禁止，不把它们当普通快捷应用处理。
4. WHEN 用户点击系统快捷应用“终端” THEN System SHALL 打开代码视图内的终端面板，而不是优先跳去独立终端路由。

### 需求 2：代码视图必须支持对话和终端同屏

**用户故事：** 作为边聊边调试的用户，我希望在同一个画面里同时看到对话和终端，这样不用来回切页。

#### 验收标准

1. WHEN 用户点击终端快捷应用且当前在代码视图 THEN System SHALL 在中间区域打开终端面板，并让对话区同步让位。
2. WHEN 终端面板以默认布局打开 THEN System SHALL 采用上下布局，并表现为终端从下向上展开。
3. WHEN 终端面板已经打开 THEN System SHALL 保持对话区和终端区同时可见，而不是把其中一个完全替换掉。
4. WHEN 用户手动关闭终端面板 THEN System SHALL 恢复成正常对话视图。

### 需求 3：终端标签列表必须改到面板右侧

**用户故事：** 作为多终端用户，我希望终端标签在终端区旁边固定可见，这样切换标签更像正常 IDE，而不是到处找。

#### 验收标准

1. WHEN 终端面板打开 THEN System SHALL 在终端面板右侧显示终端标签列表。
2. WHEN 终端标签数量变化 THEN System SHALL 继续复用现有终端实例和前端数据，不新造一套终端来源。
3. WHEN 用户切换终端标签 THEN System SHALL 只切换当前显示终端，不影响后台继续运行的其他终端标签。
4. WHEN 用户从代码视图切走再回来 THEN System SHALL 保持终端标签列表和当前活动标签的状态连续。

### 需求 4：终端和对话必须支持两种布局并可拖拽调比例

**用户故事：** 作为不同屏幕尺寸的用户，我希望终端和对话可以上下排，也可以左右排，并且能自己调大小。

#### 验收标准

1. WHEN 终端面板第一次打开 THEN System SHALL 默认采用上下布局。
2. WHEN 用户切换到左右布局 THEN System SHALL 立即按左右分栏显示终端区和对话区。
3. WHEN 用户拖动中间分隔条 THEN System SHALL 实时更新终端区和对话区比例。
4. WHEN 布局方向变化 THEN System SHALL 分别记住上下布局和左右布局下的有效比例，避免每次切换都回到死板默认值。

### 需求 5：终端面板状态必须按工作区恢复

**用户故事：** 作为连续工作的用户，我希望终端只要没被我手动关掉，就算切去别的页面再回来，也按我上次的布局继续显示。

#### 验收标准

1. WHEN 用户只是切到别的页面、别的标签或别的工作台，再回到代码视图 THEN System SHALL 按上次状态恢复终端面板是否打开、布局方向和比例。
2. WHEN 用户没有手动关闭终端面板 THEN System SHALL 不因为普通页面切换就把终端面板视为关闭。
3. WHEN 用户手动关闭终端面板 THEN System SHALL 只隐藏前端面板，不自动关闭后台终端实例。
4. WHEN 后台终端实例仍在运行 THEN System SHALL 允许用户重新打开终端面板并继续使用原有终端。

## 非功能需求

### 非功能需求 1：零后端破坏

1. WHEN 本轮改造完成 THEN System SHALL 不要求修改现有终端后端路由、终端运行时和日志持久化逻辑。
2. WHEN 终端前端面板接入代码视图 THEN System SHALL 继续复用现有终端数据获取和订阅链路。

### 非功能需求 2：体验稳定

1. WHEN 终端面板显示状态恢复 THEN System SHALL 在工作区切换时避免串用别的工作区布局状态。
2. WHEN 用户拖拽调整比例 THEN System SHALL 限制最小可视尺寸，避免把对话区或终端区压成不可用。

### 非功能需求 3：可维护性

1. WHEN 后续还要给代码视图增加更多快捷应用 THEN System SHALL 复用统一的快捷应用数据结构和渲染逻辑，而不是再复制一套事务视图代码。
2. WHEN 后续还要调整终端布局 THEN System SHALL 把布局状态、拖拽逻辑和终端面板壳层放在明确模块里，而不是散落在多个条件分支中。

## 成功定义

- 用户在代码视图里可以直接从快捷应用打开终端
- 对话和终端可以同屏，不再强依赖独立终端页切换
- 终端支持上下 / 左右布局和手动调比例
- 用户切走再回来，终端面板状态能恢复
- 本轮没有改坏现有终端后端逻辑
