# 设计文档 - spec006.2-终端入口与对话工作台布局重构

状态：Draft

## 1. 概述

### 1.1 目标

- 把终端主入口从旧菜单迁到代码视图左侧快捷应用
- 让终端成为代码视图里的常驻工作面板，而不是必须跳转的独立页
- 复用事务视图已有快捷应用能力，避免两套相似 UI 长成两份垃圾
- 保持现有终端后端、终端管理快照和终端实例运行逻辑不变
- 让终端面板状态按工作区恢复，不让用户每次重新摆布局

### 1.2 覆盖需求

- `requirements.md` 需求 1

- `requirements.md` 需求 3
- `requirements.md` 需求 4
- `requirements.md` 需求 5

### 1.3 技术约束

- 前端仅改 `apps/user-app`
- 显示文案必须走统一 i18n 字典
- 不修改终端后端接口和终端服务逻辑
- 代码视图仍以 `WorkbenchLayout` 为主壳层
- 快捷应用现有状态继续沿用 `affairs-dashboard-state` 这套本地快照能力
- 现有分隔拖拽能力优先复用工作台已有 `separator` / `resizer` 交互模式

### 1.4 视觉约束

- 代码视图新增的快捷应用区要和事务视图现有快捷应用区保持同一套语言，不另长新皮肤
- 终端面板默认表现是“从下向上打开”，但不是临时弹窗，而是稳定工作区的一部分
- 终端和对话的分隔条必须可见、可拖，不做花哨动画
- 终端标签列表固定在终端区右侧，优先保证切换效率

## 2. 架构

### 2.1 系统结构

这轮前端结构拆成四块：

1. **系统快捷应用层**
   - 给代码视图补出固定快捷应用入口
   - 终端、技能属于系统快捷应用，不走用户编辑流程

2. **快捷应用渲染层**
   - 复用事务视图底部快捷应用的展示方式
   - 把“哪些可编辑、哪些固定不可编辑”收成统一判断

3. **代码视图终端面板层**
   - 在 `WorkbenchLayout` 中间区域挂一个“对话 + 终端”双面板容器
   - 对话区继续承载现有会话主舞台
   - 终端区承载终端显示和终端标签列表

4. **布局状态层**
   - 负责记住终端面板是否打开
   - 负责记住上下 / 左右方向
   - 负责记住比例、最小尺寸和最近一次手动关闭状态

一句人话：
不是再做一个终端页，而是在代码视图里多一个能记住自己位置的终端面板。

### 2.2 模块职责

| 模块 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| `WorkbenchLayout` | 承载代码视图主布局，决定是否显示终端面板 | 当前路由、工作区、终端面板状态 | 对话区 + 终端面板的组合视图 |
| `CodeModeShortcutAppsRail`（新增挂载点） | 在代码视图左侧底部挂事务模式现有快捷应用 | 系统快捷应用、事务全局快捷应用、编辑状态 | 快捷应用列表 |
| `AffairsShortcutRail`（现有抽取） | 提供可复用的快捷应用列表渲染和交互基础 | 快捷应用项、编辑能力配置 | 通用快捷应用区 UI |
| `ConversationTerminalDock`（新增） | 渲染代码视图里的终端面板壳层和布局切换 | 布局状态、终端列表、当前活动终端 | 上下/左右双面板 UI |
| `TerminalManagerPanel` | 继续提供终端列表、模板、终端管理数据来源 | 工作区、终端快照、刷新订阅 | 终端列表与操作区 |
| `TerminalDockStateStore`（新增） | 管理终端面板开关、方向、比例、本地恢复 | workspaceId、用户动作 | 持久化状态快照 |

### 2.3 关键流程

#### 2.3.1 从快捷应用打开终端

1. 用户进入代码视图。
2. 左侧边栏底部显示快捷应用区。
3. 用户点击系统快捷应用“终端”。
4. `WorkbenchLayout` 把终端面板状态切到 `open=true`。
5. 中间区域切成“对话区 + 终端区”双面板。
6. 终端区按上次保存的方向和比例恢复；如果没有历史，就用默认上下布局。

#### 2.3.2 手动调整布局方向和比例

1. 用户在终端面板工具条里切换“上下 / 左右”。
2. `TerminalDockStateStore` 更新当前方向。
3. 对话区和终端区按新方向重排。
4. 用户拖动分隔条。
5. 系统在限制最小尺寸后写入新的比例。
6. 当前工作区的布局状态被本地持久化。

#### 2.3.3 切走页面再回来

1. 用户打开终端面板后切到别的页面。
2. 终端实例继续由现有后端链路运行。
3. 用户回到代码视图。
4. `WorkbenchLayout` 读取当前工作区的终端面板快照。
5. 如果上次不是手动关闭，则继续按 `open=true`、原方向、原比例恢复。
6. 如果上次是手动关闭，则保持只显示对话区。

#### 2.3.4 手动关闭终端面板

1. 用户点击终端面板关闭按钮。
2. 系统只把前端面板状态改成 `open=false`。
3. 不调用终端关闭接口，不影响后台终端实例。
4. 下次再点“终端”时，仍然复用现有终端列表和活动终端状态。

### 3.3 接口契约

覆盖需求：2、3、4、5

#### 3.3.1 前端本地状态接口

- 类型：前端函数 + `view-snapshot-cache`
- 路径或标识：建议新增 `workbench.terminal.dock.<workspaceId>`
- 输入：`workspaceId`、终端面板状态
- 输出：恢复后的 `TerminalDockLayoutState`
- 校验：非法比例回退默认值；非法方向回退 `vertical`
- 错误：快照损坏时回退安全默认值，不阻塞页面渲染

#### 3.3.2 终端数据来源接口

- 类型：复用现有前端终端订阅能力
- 路径或标识：继续复用 `TerminalManagerPanel` 与现有终端 API
- 输入：当前工作区 ID、终端刷新动作、终端订阅快照
- 输出：终端列表、活动终端、终端运行状态
- 校验：不新增后端参数
- 错误：终端面板内显示现有终端错误提示，不另外发明新协议

## 4. 数据与状态模型

### 4.1 数据关系

这轮最重要的关系只有两条：

1. **快捷应用关系**
   - 代码视图快捷应用 = 系统快捷应用 + 用户快捷应用
   - 系统快捷应用固定在前，用户快捷应用跟在后

2. **终端面板关系**
   - 一个工作区对应一个终端面板布局状态
   - 一个终端面板布局状态只控制“前端怎么显示”
   - 终端实例是否运行，仍然由现有终端链路决定

别把这两件事搅在一起。

### 4.2 状态流转

#### 4.2.1 终端面板显示状态

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `closed` | 终端面板不显示 | 默认进入；用户手动关闭 | 用户点击终端快捷应用打开 |
| `open-vertical` | 终端面板以上下布局显示 | 打开且方向为 `vertical` | 切到左右布局或手动关闭 |
| `open-horizontal` | 终端面板以左右布局显示 | 打开且方向为 `horizontal` | 切到上下布局或手动关闭 |

#### 4.2.2 手动关闭标记

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `manual-closed=false` | 可以按上次打开状态恢复 | 用户打开终端；普通页面切换 | 用户手动关闭终端面板 |
| `manual-closed=true` | 回到代码视图时默认不自动展开 | 用户点击关闭按钮 | 用户再次主动打开终端 |

## 5. 错误处理

### 5.1 错误类型

- `terminal_dock_snapshot_invalid`：终端面板本地快照损坏
- `terminal_dock_ratio_invalid`：终端比例非法
- `terminal_shortcut_action_failed`：快捷应用动作无法执行
- `terminal_panel_data_unavailable`：终端面板需要的数据暂时没拉回来

### 5.2 错误响应格式

```json
{
  "detail": "终端面板布局数据已损坏，已恢复默认显示。",
  "error_code": "terminal_dock_snapshot_invalid",
  "field": "orientation",
  "timestamp": "2026-06-10T00:00:00Z"
}
```

### 5.3 处理策略

1. **本地状态坏了就回默认值**：不能因为一个坏快照把整个代码视图搞白屏。
2. **终端数据没拉回来也要保留壳层**：面板可以显示空态或加载态，但不要直接把布局打回去。
3. **手动关闭优先级最高**：用户自己关掉的，就不要在普通切页后强行再弹出来。
4. **系统快捷应用动作失败要有明确提示**：不能点了没反应。

## 6. 正确性属性

### 6.1 属性 1：前端布局改造不改变终端后端真相

*对于任何* 终端创建、关闭、订阅和输出流程，系统都应该满足：本轮只改变入口和显示方式，不改变终端后端实例真相来源。

**验证需求：** 需求 1、需求 5

### 6.2 属性 2：终端面板显示状态和终端实例运行状态分离

*对于任何* 终端面板开关动作，系统都应该满足：关闭面板不会等于关闭终端实例。

**验证需求：** 需求 2、需求 5

### 6.3 属性 3：布局状态不跨工作区串线

*对于任何* 工作区切换和页面恢复，系统都应该满足：终端面板方向、比例、开关状态只在当前工作区生效。

**验证需求：** 需求 4、需求 5

## 7. 测试策略

### 7.1 单元测试

- 系统快捷应用与用户快捷应用合并顺序
- 终端面板状态默认值和坏快照回退
- 上下 / 左右比例边界处理
- 手动关闭标记恢复逻辑

### 7.2 集成测试

- 点击快捷应用后在代码视图中打开终端面板
- 切换布局方向后拖拽调比例并刷新恢复
- 切走页面再回来仍恢复终端面板
- 手动关闭后不自动恢复，但终端实例仍可重新打开

- 代码视图中对话和终端同屏主链路
- 终端标签列表在右侧可切换多个终端
- 技能和终端作为固定快捷应用出现，且不可删不可编辑

## 8. 风险与待确认项

### 8.1 风险

- `WorkbenchLayout` 现在已经很大，继续往里硬塞逻辑容易变脏，最好抽出终端面板状态模块。
- 事务视图快捷应用如果不先抽公共层，代码视图可能复制一份近似实现，后面维护会很烦。
- 终端标签列表从现有位置挪到右侧后，部分测试会一起变，需要集中改。

### 8.2 待确认项

- “技能”快捷应用点击后，代码视图里最终打开的是现有哪个能力面板，需要实现时再锁具体动作。
- 独立终端路由这轮是否保留为兼容入口，还是只保留深链跳转后立即重定向，需要实现阶段再定。
