# spec003.2-运行中消息追加与原生引导

## 当前定位

这个 Spec 不再解决“怎么启动真实会话”，`spec003.1` 已经把那件事说清楚了。

这次只解决一个更尖锐的问题：

- 会话已经在运行时，能不能继续追加消息
- `Claude Code` 和 `Codex` 这件事到底各自原生支持到哪一步
- 本项目要怎样最小改动地接住这些原生能力，而不是自己编一套假机制

一句话说清楚：这一步要把“运行中输入”从当前的一刀切禁用，升级成“按 provider 原生语义工作”。

## 计划覆盖

- 运行中输入能力模型
- `Claude Code` 长连接 `stdin/jsonl` 流式输入
- `Codex` 原生 `queue/steer` 语义对齐
- 运行中输入的 Host 路由复用
- 前端输入区按能力降级
- 运行中输入的错误边界与兼容性约束

## 依赖关系

- 前置依赖：`spec002`、`spec003`、`spec003.1`
- 影响范围：`packages/session-sync-core`、`apps/host`、`apps/user-app`
- 后续会直接受益：文件上下文、终端联动、移动端会话控制

## 本阶段明确不做

- 不做项目私有消息队列
- 不伪造 `Codex` 运行中即时吸收消息的能力
- 不新增新的 provider
- 不重写整套消息时间线模型
- 不把 `Claude Code` 和 `Codex` 强行抽成完全相同的行为
