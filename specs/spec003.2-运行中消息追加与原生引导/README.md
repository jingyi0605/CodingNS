# spec003.2-运行中消息追加与原生引导

## 当前定位

这个 Spec 不再解决“怎么启动真实会话”，`spec003.1` 已经把那件事说清楚了。

这次只解决一个更尖锐的问题：

- 会话已经在运行时，用户还能不能继续提交多条后续消息
- 这些后续消息能不能由本项目统一排队，而不是完全受 provider 当前接入形态限制
- `Claude Code` 和 `Codex` 在当前项目里怎样共用一套“上一条结束后立刻续跑下一条”的机制

一句话说清楚：这一步要把“运行中输入”从当前的一刀切禁用，升级成“项目内统一发送队列 + provider 原生直发能力并存”的模式。

## 计划覆盖

- 运行中输入能力模型
- `Claude Code` 长连接 `stdin/jsonl` 流式输入
- 项目内统一发送队列
- 运行中输入与排队输入的 Host 路由复用
- 前端输入区按能力降级
- 队列项删除、自动续跑、错误边界与兼容性约束

## 依赖关系

- 前置依赖：`spec002`、`spec003`、`spec003.1`
- 影响范围：`packages/session-sync-core`、`apps/host`、`apps/user-app`
- 后续会直接受益：文件上下文、终端联动、移动端会话控制

## 本阶段明确不做

- 不新增新的 provider
- 不重写整套消息时间线模型
- 不实现跨会话全局队列
- 不支持删除已经开始发送的队列项
- 不把 provider 原始历史正文写进项目数据库
