# Specs 总览

本目录用于承载 `码不能停` 的正式 Spec 资产。

当前状态：

- 核心 Spec 已经不是“空骨架”，大部分目录都补齐了 `requirements.md`、`design.md`、`tasks.md`
- 这里既有已经落地的基础能力，也有正在推进的增量迭代 Spec
- 当前编号已经扩展到 `spec013.2`，中间也补出了 `spec007.1`、`spec012.1` 这类基础子规格，后续继续按能力边界往下加，不再假装只有 `001` 到 `010`

编写原则：

- 先把地基 Spec 写清楚，再写上层能力
- 一个 Spec 只解决一类问题，不写成大杂烩
- 每个 Spec 都必须补齐 `requirements.md`、`design.md`、`tasks.md`
- 如果某个能力依赖前置 Spec，就不要抢跑实现
- `tasks.md` 不是摆设，任务做完后要及时回写状态

各 Spec 简述：

- `spec001-平台底座与工作区基础`：定义 Host、工作区、基础认证、共享协议和存储边界
- `spec001.1-账户偏好入库与跨客户端同步`：定义默认会话权限、语言、主题和 provider 默认项这些账户偏好的数据库落点、前端分层和跨客户端同步规则
- `spec001.2-后端任务调度与主线程压力治理`：定义哪些后端重活必须脱离请求主链路、哪些任务要迁到 helper 进程、如何统一后台任务调度和量化主线程压力
- `spec001.3-多HOST接入与跨端切换`：定义多 HOST Profile、激活 HOST 切换事务、按 HOST 保存登录态，以及桌面端顶部切换器和移动端 HOST 树入口
- `spec001.4-Tailscale接入与实例级远程访问`：定义实例级 Tailscale 配置、设置页动态启停和绑定流程、helper 生命周期、tailnet 地址展示，以及与现有业务认证共存的边界
- `spec001.5-多CLI-Skill统一管理与同步`：定义系统内置 Skill、本地 Skill、各 CLI skill 目录和统一 `SkillManager` 的同步边界，不再让 Butler 或单个 CLI 自己硬编码复制
- `spec001.6-客户端与服务端统一更新机制`：定义桌面端更新、Android `APK` 直装、服务端全局 npm 包升级、统一更新入口和发布产物边界
- `spec001.7-设置页模型快速切换与CC-SWITCH接入`：定义设置页里的统一模型管理入口、`cc-switch` 预设切换适配层、四个 CLI 的当前模型展示，以及第一阶段只做模型预设快速切换的边界
- `spec002-ClaudeCode与Codex会话同步核心`：打通 Claude Code / Codex provider、会话同步和能力声明
- `spec003-对话式主界面与消息运行时`：定义主对话界面、消息流、输入区和运行时交互
- `spec003.1-原生会话实时对话运行时`：定义原生会话实时通信、消息入流和基础运行时同步
- `spec003.2-运行中消息追加与原生引导`：定义运行中消息持续追加、原生入口提示与引导行为
- `spec003.3-运行时消息直推与稳定标识`：定义消息直推链路与运行时稳定标识，避免前端错位和重复
- `spec003.4-会话活动状态权威源与稳定显示`：定义会话活动状态的权威来源、推断策略和前端稳定展示
- `spec004-文件管理能力`：定义文件树、编辑、搜索、上下文挂载和文件操作边界
- `spec005-Git上下文与提交规则引擎`：定义 Git 状态、提交流程和规则校验机制
- `spec006-终端核心能力`：定义 PTY 生命周期、终端会话和基础交互
- `spec006.1-终端日志持久化与历史回放`：定义终端输出落盘、历史翻页与恢复策略
- `spec007-进程管理与启动器`：定义进程控制、日志、端口识别和启动配置
- `spec007.1-外部仓库调试进程端口编排与启动适配`：定义外部 Git 仓库调试服务的统一模型、启动适配器分层、端口租约规则、AI 兜底编辑边界，以及第一阶段可落地范围
- `spec008-桌面端与H5交付增强`：定义桌面壳、H5 交付、连接体验和分发要求
- `spec009-移动端体验与通知`：定义移动端信息架构、轻操作能力和通知机制
- `spec009.1-移动端工作台导航与信息架构重构`：定义移动端工作台导航拆分、路由结构与信息密度调整
- `spec010-Provider扩展框架`：定义新增 CLI provider 的扩展协议、测试样本和兼容边界
- `spec010.1-OpenCode兼容接入`：定义 OpenCode 作为第三个正式 provider 的接入路线、消息映射、能力边界和回归策略
- `spec010.2-GeminiCLI兼容接入`：定义 Gemini CLI 的 ACP 主链路、headless fallback、本地 chats 历史读取与回归策略
- `spec010.3-KimiCLI兼容接入`：定义 Kimi CLI 的 wire mode 主链路、本地会话读取、运行中引导映射与回归策略
- `spec011-单包安装与统一服务发布`：定义统一 NPM 包的安装、运行、发布和离线分发方式
- `spec012.1-Git工作树与工作区分叉基础`：先定义 worktree 元数据、创建/继续 fork/合并/清理、工作台“子工作树”区块，以及父工作区与子工作树的视觉区分
- `spec012-并行项目编排与结果对比`：定义同一个问题下多 provider 并行试解的案例模型、运行时隔离、结果对比和合并建议流程，底层 worktree 生命周期依赖 `spec012.1`
- `spec013-代码助手平台与跨工作区巡检编排`：定义跨工作区代码助手平台的项目/会话/记忆/巡视/验证/授权模型，以及 `Codex` / `Claude Code` 统一适配与 MVP 路线
- `spec013.1-代码助手控制面对话与聚合上下文`：定义代码助手自己的初始化配置、独立控制会话、分层聚合上下文、控制动作接口和工作台入口
- `spec013.2-助手内部API与代理执行编排`：定义助手统一能力门面，把项目/会话/终端/消息/fork 等动作收口成 Host API、CLI、MCP，并把 Butler 的执行边界固定为只读分析加代理执行

当前阅读建议：

- 先看 `spec001`、`spec001.1`、`spec001.2`、`spec001.3`、`spec001.4`、`spec001.5`、`spec001.6`、`spec001.7`、`spec002`，搞清楚底座、账户偏好、后台任务边界、多 HOST 边界、实例级远程访问边界、统一 Skill 管理边界、更新机制边界、模型预设切换边界和会话同步边界
- 再看 `spec003` 系列，理解主对话运行时和会话状态链路
- 需要工具能力时再分别查 `spec004`、`spec005`、`spec006`、`spec007`
- 涉及外部仓库调试、多工作树并行启动和端口冲突时，先看 `spec007.1`
- 涉及 worktree 和并行项目时，先看 `spec012.1`，再看 `spec012`
- 涉及交付与扩展时，再看 `spec008`、`spec009`、`spec010`、`spec011`
- 需要跨项目巡检、长期记忆、统一 agent 管理与验证时，先看 `spec013`
- 需要代码助手真正以控制面会话和用户沟通，并串联项目/会话/记忆/巡视/验证信息时，再看 `spec013.1`
- 需要让助手通过正式工具面去查项目、调会话、控终端，而不是继续靠提示词硬记路由时，再看 `spec013.2`
