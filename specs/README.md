# Specs 总览

本目录用于承载 `码不能停` 的正式 Spec 资产。

当前状态：

- 核心 Spec 已经不是“空骨架”，大部分目录都补齐了 `requirements.md`、`design.md`、`tasks.md`
- 这里既有已经落地的基础能力，也有正在推进的增量迭代 Spec
- 当前编号已经扩展到 `spec018`，中间也补出了 `spec001.9`、`spec001.9.1`、`spec001.9.4`、`spec007.1`、`spec012.1` 这类基础子规格，后续继续按能力边界往下加，不再假装只有 `001` 到 `010`

编写原则：

- 先把地基 Spec 写清楚，再写上层能力
- 一个 Spec 只解决一类问题，不写成大杂烩
- 每个 Spec 都必须补齐 `requirements.md`、`design.md`、`tasks.md`
- 如果某个能力依赖前置 Spec，就不要抢跑实现
- `tasks.md` 不是摆设，任务做完后要及时回写状态

各 Spec 简述：

- `spec001-平台底座与工作区基础`：定义 Host、工作区、基础认证、共享协议和存储边界
- `spec001.1-账户偏好入库与跨客户端同步`：定义默认会话权限、语言、主题和 provider 默认项这些账户偏好的数据库落点、前端分层和跨客户端同步规则
- `spec001.2-后端任务调度与主线程压力治理`：定义哪些后端重活必须脱离请求主链路、哪些任务要迁到 helper 进程、如何统一后台任务调度和量化主线程压力
- `spec001.2.1-读写刷新与后台任务统一规则`：定义读接口副作用边界、刷新状态模型、watcher 范围、私有 `inflight/timer` 准入标准，以及以后新增服务必须遵守的统一检查清单
- `spec001.3-多HOST接入与跨端切换`：定义多 HOST Profile、激活 HOST 切换事务、按 HOST 保存登录态，以及桌面端顶部切换器和移动端 HOST 树入口
- `spec001.3.1-桌面端本机HOST自动发现`：定义 Windows/macOS 桌面端如何自动发现本机已运行的 `codingns` Host、如何单独归类展示、如何与手动 HOST 去重，以及自动发现 HOST 的本地凭据归属
- `spec001.4-Tailscale接入与实例级远程访问`：定义实例级 Tailscale 配置、设置页动态启停和绑定流程、helper 生命周期、tailnet 地址展示，以及与现有业务认证共存的边界
- `spec001.5-多CLI-Skill统一管理与同步`：定义系统内置 Skill、本地 Skill、各 CLI skill 目录和统一 `SkillManager` 的同步边界，不再让 Butler 或单个 CLI 自己硬编码复制
- `spec001.5.1-OpenCLI接入与适配器裁剪运行时`：定义 OpenCLI 作为独立 provider 的状态模型、技能面板里的适配器选择、裁剪运行时生成方式，以及未启用适配器在 CodingNS 管理会话里真正失效的边界
- `spec001.6-客户端与服务端统一更新机制`：定义桌面端更新、Android `APK` 直装、服务端全局 npm 包升级、统一更新入口和发布产物边界
- `spec001.7-设置页模型快速切换与CC-SWITCH接入`：定义设置页里的统一模型管理入口、`cc-switch` 预设切换适配层、四个 CLI 的当前模型展示，以及第一阶段只做模型预设快速切换的边界
- `spec001.8-登录设备管理与主设备控制`：定义设置页里的登录设备管理入口、稳定设备识别、最近 10 条登录记录、主设备显式设置，以及主设备退出其他设备的边界
- `spec001.9-公共隧道服务接入与端到端加密远程访问`：定义官方公共隧道服务接入、主仓库与独立子仓库的分工、客户端与 Host 的端到端加密、三级域名入口边界，以及流量计量和套餐购买边界
- `spec001.9.1-公共隧道服务二阶段收口与生产化验收`：定义公共隧道控制台站点、正式数据库、真实邮件、真实支付联调、生产化中继、部署文档和最终验收基线
- `spec001.9.2-公共隧道管理员只读后台与权限通路`：定义公共隧道控制面里的账号角色模型、管理员鉴权、管理员只读 API、管理员前端路由和零破坏兼容策略
- `spec001.9.3-公共隧道流量优化与局域网自动直连`：定义 Host 候选连接入口、客户端自动局域网直连、relay 热备回退，以及高频远程读链路的缓存与减量传输顺序
- `spec001.9.4-公共隧道盲中继收口与可信接入端直连`：定义如何去掉 `relay-edge` 的公网明文业务代理，把 Channel 端收口成真正盲中继，并在支持 H5 的前提下简化 Host、桌面客户端、H5 客户端与 Channel 的连接步骤
- `spec002-ClaudeCode与Codex会话同步核心`：打通 Claude Code / Codex provider、会话同步和能力声明
- `spec003-对话式主界面与消息运行时`：定义主对话界面、消息流、输入区和运行时交互
- `spec003.1-原生会话实时对话运行时`：定义原生会话实时通信、消息入流和基础运行时同步
- `spec003.2-运行中消息追加与原生引导`：定义运行中消息持续追加、原生入口提示与引导行为
- `spec003.3-运行时消息直推与稳定标识`：定义消息直推链路与运行时稳定标识，避免前端错位和重复
- `spec003.4-会话活动状态权威源与稳定显示`：定义会话活动状态的权威来源、推断策略和前端稳定展示
- `spec004-文件管理能力`：定义文件树、编辑、搜索、上下文挂载和文件操作边界
- `spec005-Git上下文与提交规则引擎`：定义 Git 状态、提交流程和规则校验机制
- `spec006-终端核心能力`：定义 PTY 生命周期、终端会话和基础交互
- `spec006.1-终端日志持久化与历史回放`：定义终端输出落盘、历史翻页与恢复策略
- `spec007-进程管理与启动器`：定义进程控制、日志、端口识别和启动配置
- `spec007.1-外部仓库调试进程端口编排与启动适配`：定义外部 Git 仓库调试服务的统一模型、启动适配器分层、端口租约规则、AI 兜底编辑边界，以及第一阶段可落地范围
- `spec008-桌面端与H5交付增强`：定义桌面壳、H5 交付、连接体验和分发要求
- `spec009-移动端体验与通知`：定义移动端信息架构、轻操作能力和通知机制
- `spec009.1-移动端工作台导航与信息架构重构`：定义移动端工作台导航拆分、路由结构与信息密度调整
- `spec010-Provider扩展框架`：定义新增 CLI provider 的扩展协议、测试样本和兼容边界
- `spec010.1-OpenCode兼容接入`：定义 OpenCode 作为第三个正式 provider 的接入路线、消息映射、能力边界和回归策略
- `spec010.2-GeminiCLI兼容接入`：定义 Gemini CLI 的 ACP 主链路、headless fallback、本地 chats 历史读取与回归策略
- `spec010.3-KimiCLI兼容接入`：定义 Kimi CLI 的 wire mode 主链路、本地会话读取、运行中引导映射与回归策略
- `spec011-单包安装与统一服务发布`：定义统一 NPM 包的安装、运行、发布和离线分发方式
- `spec012.1-Git工作树与工作区分叉基础`：先定义 worktree 元数据、创建/继续 fork/合并/清理、工作台“子工作树”区块，以及父工作区与子工作树的视觉区分
- `spec012-并行项目编排与结果对比`：当前内容已重写为“并行会话组与临时子工作区”，定义并行会话组、组成员、会话级临时隔离工作区、分屏会话 UI 和升级为正式子工作区的流程，底层 worktree 生命周期依赖 `spec012.1`
- `spec013-代码助手平台与跨工作区巡检编排`：定义跨工作区代码助手平台的项目/会话/记忆/巡视/验证/授权模型，以及 `Codex` / `Claude Code` 统一适配与 MVP 路线
- `spec013.1-代码助手控制面对话与聚合上下文`：定义代码助手自己的初始化配置、独立控制会话、分层聚合上下文、控制动作接口和工作台入口
- `spec013.2-助手内部API与代理执行编排`：定义助手统一能力门面，把项目/会话/终端/消息/fork 等动作收口成 Host API、CLI、MCP，并把 Butler 的执行边界固定为只读分析加代理执行
- `spec013.5-工作区会话助手能力开放与作用域收口`：定义哪些 `codingns assistant` 能力可以正式开放给工作区会话、如何通过 `workspace_session` 和 scoped token 把范围锁死到当前工作区，以及如何补齐 `terminals.create` 和工作区办公能力入口
- `spec014-通讯平台接入与助手会话桥接`：定义钉钉、飞书、个人微信（claw）、Telegram、Slack、Discord 这些平台怎么正式接到 Butler 助手会话，包括账号模型、外部会话映射、webhook / polling / bridge 接入和回发链路
- `spec015-通用办公能力平台与统一任务执行内核`：定义浏览器执行内核、`doct` 模板驱动的专业文档内核、`SSH + 浏览器` 运维内核、重复事务自动化、统一任务模型和统一连接器体系，目标是把 `CodingNS` 从 AI 编码平台扩成完整办公执行平台
- `spec015.1-opencli浏览器桥接接入office-browser`：定义 `office.browser` 的双执行支线，保留现有无头 `Playwright` 路线，并把 `opencli Browser Bridge` 接进来作为真实浏览器调试选项，同时保持现有浏览器 `Profile`、实例和任务模型不被打坏
- `spec016-代码视图与事务视图双工作台重构`：定义桌面端前端主骨架从单一代码工作台升级为“代码 / 事务”双视图的路线，要求代码视图零破坏迁移，并把文档库、待办、自动化、插件和事务 AI 辅助逐步收口到新的事务视图里
- `spec016.1-事务视图文档库与索引HOST集成`：把事务视图里的假文档库替换成真实文档库对象，并要求索引服务正式接进 HOST、索引重活统一走 TaskManager 和 worker，不再长散装后台链路
- `spec016.2-事务文档库外部变更感知与自动刷新`：专门处理“用户主要从外部编辑文件”这个真实前提下，事务文档库怎么安全感知外部变更、怎么优先 targeted refresh、怎么用周期兜底补漏，以及 `.ai-index` 缺失时怎么自动重建。
- `spec016.3-事务文档库标签快捷分配与智能标签`：专门处理事务文档库里的快捷手动标签分配、文件夹标签持续生效，以及正式智能标签规则。
- `spec016.4-事务文档库刷新阻塞治理与索引稳定性改造`：专门处理事务文档库为什么会长期卡在排队中、为什么 watcher 漏事件后结果迟迟不新、为什么共享 helper 会互相拖死，以及怎么用双层兜底刷新、queue wait timeout、per-rootDir helper 隔离和 Host 主线程去同步 I/O 来把链路做稳。
- `spec017-事务视图对话入口与轻量会话分流`：专门处理事务模式左侧新增正式对话入口、事务主区聊天页，以及轻量会话和 Agent 会话的边界，不再把这类对话继续塞在右侧助手面板里。
- `spec018-事务表单系统与Teable集成`：专门处理 Teable 全局连接、表同步、字段映射和同步日志。
- `spec018.1-Teable自定义前端视图块`：专门处理工作台画布里的 Teable 块，用 CodingNS 自定义前端实现表格、表单、日历和看板视图，不再嵌入 Teable 分享页。
