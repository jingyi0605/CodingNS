# 20260417-最小回归验证清单

这份清单只回答一个问题：

- `spec013.3` 第一阶段落地后，最少要验证哪些链路，才能证明它不是纸上谈兵

一句人话：

别一上来就说“功能都通了”。先把最容易炸、最关键的几条链路跑透。

## 1. 自动化基础链路

### 1.1 一次性自动化创建与触发

目标：

- 证明 `once` 模型可用
- 证明兼容 `timers.create` 还活着

验证步骤：

1. 创建一条 60 秒后的单次自动化
2. 确认对象状态是 `active`
3. 确认 `nextRunAt` 正确
4. 到点后确认生成一条 run
5. 确认控制会话收到消息
6. 确认自动化状态变成 `completed`

必须看到的结果：

- 兼容 timer 视图可读
- run 记录存在
- 控制会话链路没断

### 1.2 interval 自动化递进

目标：

- 证明循环不是靠 prompt 续建

验证步骤：

1. 创建每 5 分钟一次的 interval 自动化
2. 手动触发一次调度扫描
3. 确认 run 成功
4. 确认 `lastRunAt` 更新
5. 确认 `nextRunAt` 被系统推进到下一轮

必须看到的结果：

- 同一条任务对象持续存在
- `nextRunAt` 递进，不是重新 create 一条新任务

### 1.3 cron 自动化命中

目标：

- 证明 cron 触发器计算正确

验证步骤：

1. 创建一条固定分钟 / 小时 / 周几的 cron 自动化
2. 用可控参考时间跑触发器计算
3. 确认 `nextRunAt` 命中预期时间
4. 到点后确认 run 创建和执行成功

必须看到的结果：

- 周期命中时间稳定
- 不会在同一个时间点重复无限触发

## 2. 条件触发链路

### 2.1 条件未满足时只更新下一次检查时间

目标：

- 证明条件轮询不会每次都伪造一次执行

验证步骤：

1. 创建 `git.remote_tag_changed` 条件自动化
2. 当前远端 tag 不变
3. 运行一次 `evaluate`
4. 确认没有创建成功 run
5. 确认 `nextRunAt` 推进到下一次检查时间

必须看到的结果：

- 条件未满足时不会误通知用户

### 2.2 条件满足时触发控制会话

目标：

- 证明“发现新 tag 再通知”这类真实需求能跑通

验证步骤：

1. 创建 `git.remote_tag_changed` 条件自动化，并记录基线 tag
2. 模拟远端出现新 tag
3. 运行一次 `evaluate`
4. 确认创建 run
5. 确认控制会话收到带触发上下文的消息
6. 确认自动化状态和下一次时间符合预期

必须看到的结果：

- 消息里能看到新旧基线信息
- 同一轮不会重复触发多次

## 3. 兼容链路

### 3.1 旧 `timers.create` 兼容

目标：

- 证明旧 CLI 和旧 Host API 没被打断

验证步骤：

1. 走旧 `timers.create`
2. 确认内部实际创建的是 `triggerType=once` 的新自动化
3. 再走 `timers.get / list / cancel`
4. 确认兼容 DTO 正常返回

必须看到的结果：

- 旧入口能继续用
- 新模型开始接管实际数据

### 3.2 旧 Butler 计时器区块兼容

目标：

- 证明旧页面最小可用

验证步骤：

1. 打开旧计时器显示区域
2. 确认单次自动化仍能显示标题、状态、预计时间
3. 取消后确认状态回写

必须看到的结果：

- 不要求旧区块理解 interval / cron / condition
- 但不能把单次兼容链路搞坏

## 4. 沙箱链路

### 4.1 空白沙箱创建

目标：

- 证明助手能有自己的临时空间

验证步骤：

1. 创建 `blank` 沙箱
2. 确认目录被创建
3. 确认工作区入口存在
4. 确认沙箱元数据记录存在

必须看到的结果：

- 沙箱不等于正式项目
- 目录、工作区、沙箱元数据三者能对上

### 4.2 基于 clone 的沙箱创建

目标：

- 证明助手能在临时空间里拉仓库

验证步骤：

1. 用仓库 URL 创建 `clone` 沙箱
2. 确认仓库被克隆
3. 确认工作区被导入
4. 确认沙箱状态是 `active`

必须看到的结果：

- clone 失败时只影响该沙箱
- 不污染正式项目列表

### 4.3 在沙箱中启动真实会话

目标：

- 证明 `--sandbox` 不是摆设

验证步骤：

1. 创建一个沙箱
2. 以 `sandboxId` 为目标启动真实会话
3. 确认会话实际绑定到沙箱工作区
4. 确认不要求传 `projectId`

必须看到的结果：

- 真实会话能在沙箱里运行
- 不会偷偷回落到某个默认项目

### 4.4 沙箱晋升与清理

目标：

- 证明沙箱能留、也能收

验证步骤：

1. 创建沙箱并做一次 `pin`
2. 确认工作区入口保留
3. 再创建另一个沙箱并标记过期
4. 运行清理任务
5. 确认过期沙箱元数据和工作区入口按规则回收

必须看到的结果：

- 被保留的不会误删
- 过期的能被收走

## 5. 失败隔离

### 5.1 自动化失败不影响普通会话

验证步骤：

1. 构造一条必失败的自动化动作
2. 观察失败回写
3. 同时启动普通项目会话并发消息

必须看到的结果：

- 自动化对象标记失败
- 普通项目会话链路继续可用

### 5.2 沙箱创建失败不影响现有工作区

验证步骤：

1. 构造一个必失败的沙箱创建请求
2. 检查现有工作区和项目列表

必须看到的结果：

- 错误只停留在该沙箱请求
- 不影响既有工作区显示和会话启动
