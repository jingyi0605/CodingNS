# spec015.2.1-插件运行实例与权限授权收口

状态：Draft

## 这份 Spec 解决什么问题

`spec015.2` 已经把插件注册、静态 HTML 容器、Node 动作、统一网关和基础审计搭起来了，但还差最关键的一层：

1. 插件现在虽然会带 `workspaceId` 运行，但前端链路还没有把“当前工作区里的插件运行实例”彻底做成正式对象。
2. `manifest.permissions` 现在更像“声明过就能用”，还不是“声明后再授权”。
3. 插件读写工作区文件还没有一套正式文件网关和权限提示链路。
4. 后端脚本虽然会收到 `workspaceId`，但没有一条统一的“受控文件能力入口”。

这份 Spec 就是专门补这几个缺口。

一句话：

**把插件从“能跑”升级成“按当前工作区运行、按授权拿能力、所有文件访问都能审计”的正式系统。**

## 这份 Spec 做完后应该看到什么

做完以后，系统至少要满足：

- 插件仍然是全局安装，不绑定某个工作区。
- 用户在某个工作区里打开插件时，系统会创建正式的插件运行实例。
- 前端插件桥和后端动作都只认这个运行实例，不再让前端自由传 `workspaceId`。
- 插件读文件、写文件、打开文件、打开所在目录，都要先过 Host 权限判定。
- `manifest` 只负责声明“能申请什么”，真正放行要看用户是否授权。
- 授权、拒绝、撤销、调用、失败，都有正式记录可查。

## 与上层 Spec 的关系

- `spec015`：统一办公能力平台的总设计。
- `spec015.1`：浏览器桥接接入正式能力面。
- `spec015.2`：插件管理、静态 HTML 容器、Node 动作和基础网关。
- `spec015.2.1`：在 `spec015.2` 基础上，继续把插件运行实例、权限授权和文件网关补完整。
