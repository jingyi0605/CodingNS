# 20260516-布局编辑一期边界与节点准入说明

## 这份文档是干什么的

这份说明只回答一个问题：

`spec004.2.1` 里，到底哪些节点允许做布局编辑，哪些不允许。

如果这个边界不先写清楚，后面最容易长成这种垃圾：

- 画布里什么都能选
- 什么都像是能拖
- 保存后结果又丢了

这不是功能多，这是设计烂。

## 第一原则

只有“几何信息能稳定写回 HTML”的节点，才允许进入布局编辑。

换句话说：

- 能保存
- 能重开
- 能重现

缺一项都别放进来。

## 允许进入布局编辑的节点

### 1. 草稿复制节点

这类节点已经有明确的草稿几何覆盖链路，是第一批最安全的布局编辑对象。

允许能力：

- 拖动
- 缩放
- 参与多选
- 参与左/右/顶/底对齐

原因：

- 它们本来就靠 `box` 驱动
- 保存时也需要把几何结果写回

### 2. 已明确开启几何覆盖写回的普通节点

这类节点必须满足：

- 节点本身 `editable === true`
- 节点不属于只读类型
- 节点的几何修改会被保存链路真实写回 HTML

允许能力：

- 拖动
- 缩放
- 参与多选
- 参与左/右/顶/底对齐

风险提示：

- 如果只是“内存里有 box，保存时根本不落盘”，那不算允许节点。

## 明确禁止进入布局编辑的节点

### 1. 页面根节点

比如整页根容器、主画布壳、页根分组节点。

原因：

- 它们一动，整页都会跟着乱
- 这不是在编辑组件，是在拆页面结构

### 2. 只读 `svg` 节点

原因：

- 当前导入策略对复杂 `svg` 是只读保留
- 这轮没有稳定的几何与内部结构回写方案

### 3. 只读复杂 `html` 节点

原因：

- 这类节点通常不是稳定的结构化组件
- 一旦拖完保存，很容易把原始结构改坏

### 4. 装饰层和展示壳节点

包括但不限于：

- 背景粒子
- 发光层
- 翻页控件
- 进度条
- 运行态装饰层

原因：

- 它们不属于用户真正要排版的内容
- 让它们参与多选和对齐只会制造噪音

### 5. 文本 run 内层代理节点

原因：

- 这类节点服务的是文字局部选中和原位文本编辑
- 不是独立组件
- 把它们当布局节点会把文字编辑链路打烂

### 6. 主要依赖文档流、`flex`、`grid`、复杂 `transform` 的节点

这类节点如果当前没有稳定的几何覆盖保存方案，也先禁止。

原因：

- 你今天拖动成功，不代表保存后还能维持
- 一旦强行写绝对定位，原布局语义可能直接死掉

## 多选的硬边界

### 只允许同页多选

原因很简单：

- 跨页多选没有实际排版价值
- 只会增加状态和 UI 复杂度

### 多选集合里只保留布局可编辑节点

如果追加选择时命中了不允许节点：

- 不进入选区
- 给出禁用提示或静默忽略

但不能把它混进多选集合再等后面对齐时报错。

## 对齐的硬边界

第一阶段只支持：

- 左对齐
- 右对齐
- 顶对齐
- 底对齐

第一阶段明确不支持：

- 横向分布
- 纵向分布
- 居中对齐到页面
- 吸附参考线
- 智能间距

原因：

这轮目标是把基础几何主链路跑通，不是堆一排看起来很强的按钮。

## 保存约束

布局编辑准入最终要靠保存结果说话。

任何一个节点如果满足下面任一情况，就不应该进入布局编辑：

1. 拖动后只能在 iframe 里看到变化，项目状态里没有变化
2. 项目状态有变化，但保存回 HTML 时不会落盘
3. 能落盘，但重开文件后定位不稳定

出现这种情况，不是“后面再优化”，而是说明这个节点现在就不配进入布局编辑。

## 实现上的最低要求

后续代码实现至少要保证这些判断有显式落点：

- 节点是否允许移动
- 节点是否允许缩放
- 节点是否允许参与对齐
- 不允许时的原因

不要把准入逻辑散落到：

- 某个按钮禁用条件里一点
- 某个拖拽事件里一点
- 某个保存分支里一点

那样后面只会变成一堆彼此打架的补丁。
