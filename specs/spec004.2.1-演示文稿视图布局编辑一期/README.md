# spec004.2.1-演示文稿视图布局编辑一期

## 当前定位

`spec004.2` 已经把静态 HTML 演示文档编辑器的第一条主链路跑通了：

- 能识别多页演示文稿
- 能切页
- 能选中组件
- 能改文字和基础样式
- 能复制组件
- 能用字段改 `X / Y / 宽 / 高`
- 能保存回 HTML，也能导出 `PDF / PPTX`

但这里有个很明显的问题：

现在的“位置和尺寸编辑”还停留在表单字段层，像个调参面板，不像真正的演示文稿编辑器。

用户现在要的不是“再多几个输入框”，而是三件更像人话的事：

- 在画布里直接调整组件位置
- 在画布里直接调整组件大小
- 一次选中多个组件后做左右、顶部、底部对齐

一句人话：

`spec004.2.1` 不是重做编辑器，而是把现有演示文稿视图补成“能做基础版面编辑”的样子。

## 这次要覆盖什么

- 给演示文稿视图增加“布局编辑模式”
- 让符合条件的组件支持画布内拖动位置
- 让符合条件的组件支持画布内调整大小
- 让符合条件的组件支持多选
- 让多选结果支持左对齐、右对齐、顶对齐、底对齐
- 把上述结果稳定写回 `DocumentProject`，并在保存时回写到 HTML
- 明确哪些节点能做布局编辑，哪些节点坚决不做

## 这次明确不做什么

- 不把它做成完整 PPT 编辑器
- 不做旋转、分布、吸附参考线、智能间距、组合/解组
- 不做框选选区的复杂碰撞算法
- 不处理任意 `flex / grid / transform` 布局节点的几何编辑
- 不支持复杂 `svg / html` 只读节点参与多选对齐
- 不在这一轮重做 `PDF / PPTX` 导出器

## 依赖关系

- 前置依赖：`spec004`、`spec004.1`、`spec004.2`
- 主要影响：
  - `apps/user-app/src/features/static-html-editor/`
  - `apps/user-app/src/features/conversation/components/FileViewerModal.tsx`
  - `apps/user-app/src/app/styles.css`
- 需要复用：
  - `DocumentProject / DocumentNode / SourceRef`
  - 现有 HTML 回写链路
  - 现有文件保存与版本保护链路

## 这次最关键的边界

### 边界 1：先只支持“几何信息可控”的节点

这次不是给所有节点都加拖拽手柄。

第一阶段只支持这类节点进入布局编辑：

- 已经是草稿复制节点的组件
- 已经有稳定绝对定位几何信息的组件
- 能明确回写 `left / top / width / height` 的组件

如果节点本来靠文档流、`flex`、`grid`、复杂 `transform` 才成立，那这轮先别碰。

### 边界 2：多选对齐只改几何，不改语义结构

左对齐、右对齐、顶对齐、底对齐，本质上只是批量改多个节点的 `box`。

不要把它写成“重新计算整页布局引擎”，那是给自己挖坑。

### 边界 3：不能破坏现有文本编辑和普通预览链路

这轮新增的是布局编辑能力，不允许把现有这些东西搞坏：

- 普通 HTML 预览
- 普通代码编辑
- 现有文本节点原位编辑
- 现有保存和导出
