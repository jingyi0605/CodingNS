# spec003.3-运行时消息直推与稳定标识

## 当前定位

这个 Spec 只解决一件事：

- 聊天窗口里的 AI 输出，到底是不是“运行时一产生就推到前端”

现在的问题不是没有实时运行时，而是消息正文走错了路：

- 运行时层已经能拿到 provider 的实时消息
- 但 Host 只把运行状态推到 WebSocket
- 聊天正文还要绕回历史层，用轮询再捞一次

这会带来三个直接后果：

- 正文比真实运行时慢半拍
- 同一条消息的持续更新容易被去重逻辑吃掉
- provider 明明有增量事件，聊天窗口看起来还是“伪流式”

一句话说清楚：这一步不是重做聊天页，而是把消息通道改正。

## 计划覆盖

- 运行时消息从 Host 直接推到聊天 WebSocket
- 历史层回到“真相回放”和断线补偿，不再兼职实时正文分发
- 三个 provider 的稳定消息标识策略
- 前端沿用现有消息合并逻辑，接住新的实时正文事件
- 断线重连、终态保护、去重与回放边界

## 本阶段明确不做

- 不重写聊天页面布局
- 不顺手做新的富消息 UI
- 不把所有 provider 都伪装成 token 级打字机流式
- 不推翻现有历史读取能力
- 不把 provider 原始历史全文写进项目数据库
