# spec001.2-后端任务调度与主线程压力治理

## 当前定位

这个子 Spec 只解决一件事：

- 把那些不该卡在 Host 请求主链路和主线程里的重活，正式拆成“缓存优先、后台刷新、按执行位点调度”的后台任务，并补齐统一的任务注册、调度和观测规则。

一句人话：
收件箱、代码助手、工作台刷新、新建会话这些入口，不能再为了“顺手现扫一遍 provider 会话”或者“实时探一次模型能力”把主线程拖慢。

## 计划覆盖

- 后端任务分类：请求内同步、请求触发后台刷新、周期调度、helper 进程任务
- `discoverWorkspaceSessions` 脱离请求主链路，改成缓存优先、后台刷新
- provider 会话发现从 Host 主进程同步 `fs/sqlite` 扫描迁到 helper 进程或异步分批执行
- `getOverview()`、搜索、工作台刷新改成摘要聚合，不再先构造全量 snapshot
- `getProviderCapabilities()` 先返回缓存或兜底，再异步刷新模型列表
- 全局后台任务管理器的最小边界：注册、去重、限流、取消、超时、重试、指标
- 巡检和会话跟进调度器的空转行为、退让策略和观测指标

## 本阶段明确不做

- 不把所有 HTTP 请求都包装成后台任务
- 不在这个 Spec 里重写全部 provider runtime
- 不引入“全局线程管理器”这种假大空概念
- 不为了观测而大面积改业务返回结构
- 不启动新的常驻服务进程，优先复用 Host 已有 helper 机制
