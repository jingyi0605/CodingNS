# 订单对账与人工补发说明

日期：2026-04-20

这份说明记录 `spec001.9.1` 里 `4.2` 的正式结果：现在已经有对账入口，也有人工补发工具，不再要求人肉改库碰运气。

## 1. 这次到底补了什么

补了三件真东西：

1. 订单对账视图
   - 能按订单看到 `订单状态 / payment events / grant / 补发动作`
2. 人工补发入口
   - 能按订单重放 `order -> grant` 这一步
3. 补发动作审计
   - 每次重放都会写入 `order_recovery_actions`

## 2. 已落地入口

内部接口：

1. `GET /api/internal/ops/orders/:orderId/reconciliation`
2. `POST /api/internal/ops/orders/:orderId/replay-grant`

离线命令：

1. `pnpm --filter @codingns-proxy/control-api orders:recover -- inspect --order-id <orderId>`
2. `pnpm --filter @codingns-proxy/control-api orders:recover -- replay --order-id <orderId> --reason "<原因>" [--mark-paid]`

## 3. 当前能证明什么

现在已经能证明：

1. 订单、payment events、grant 三者不再混成一个字段
2. 同一订单重复补发不会重复加量
3. 运营补发 grant 后，后续公共隧道连接可以恢复

## 4. 本次验证

验证命令：

```bash
pnpm --filter @codingns-proxy/control-api lint
pnpm --filter @codingns-proxy/control-api test -- src/app.test.ts
pnpm --filter @codingns-proxy/control-api build
pnpm --filter @codingns-proxy/relay-edge test -- src/app.test.ts
```

覆盖点：

1. `control-api`
   - 可查看订单对账状态
   - 未支付订单不会被直接补发
   - 显式 `mark paid` 后可人工补发
   - 重复补发保持幂等
   - webhook 自动发量后，对账能看见 `payment event + grant`
2. `relay-edge`
   - 钱包耗尽后，人工补发订单 grant 可以恢复后续会话预留
