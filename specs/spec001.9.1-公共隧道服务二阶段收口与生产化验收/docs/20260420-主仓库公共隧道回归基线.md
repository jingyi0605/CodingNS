# 主仓库公共隧道回归基线

日期：2026-04-20

这份文档只做一件事：把主仓库里“本地直连 / Tailscale / 公共隧道”三种接入方式的最低回归线固定下来，后续谁改远程访问链路，都按这份清单回归，不再靠印象。

## 这次固定了什么

1. `SettingsPage` 的远程访问入口继续只测“入口和切换”，不把整个公共隧道面板硬塞进页面测试里。
2. `host-transport-registry` 增加三种接入方式并存测试：
   - 本地直连继续走 `directHostTransport`
   - Tailscale 可达地址继续走 `directHostTransport`
   - 只有带 `relayTunnel.enabled=true` 的 Host 才走 `ManagedRelayTunnelHostTransport`
3. 修正一个真实回归点：
   - 公共隧道从开启改成关闭后，旧的 relay transport 缓存必须立刻关闭并清掉，不能残留陈旧连接对象

## 自动化回归

本轮固定并验证的自动化命令：

```bash
pnpm --filter user-app exec vitest run src/network/host-transport-registry.test.ts src/features/settings/pages/SettingsPage.test.tsx
pnpm --filter user-app exec tsc --noEmit -p tsconfig.json
pnpm --filter host test -- tests/integration/relay-tunnel-system-routes.test.ts tests/integration/relay-tunnel-background.test.ts
```

关注点：

1. `SettingsPage.test.tsx`
   - 桌面端和移动端都还能进入“访问方式管理”
   - 公共隧道和 Tailscale 两个标签页都能切换
   - 远程访问入口还在，但不额外长出第二套 UI
2. `host-transport-registry.test.ts`
   - 三种访问方式并存时解析正确
   - 同一个公共隧道 Host 会复用 transport
   - 一个公共隧道 Host 改配置时，不会把别的 Host 一起打断
   - 公共隧道关闭后会正确回退到直连 transport，并清理旧缓存
3. `host` 集成测试
   - 公共隧道系统接口还能完成保存配置、绑定、启停、解绑
   - 重启后状态和配置还能保留
   - 后台连接状态机没有被这次客户端侧回归改坏

## 手动走查

每次要关这类改动，至少手动走这 6 步：

1. 打开主仓库设置页，确认“远程访问”入口还在。
2. 打开“访问方式管理”，确认默认显示“隧道服务”，切到 “Tailscale” 也能正常显示。
3. 在本地直连 Host 上继续访问已有接口，确认不会被误走公共隧道。
4. 在 Tailscale 可达地址上访问已有接口，确认仍按原地址直接连接。
5. 给一个 Host 打开公共隧道，再访问它的远程地址，确认会走公共隧道链路。
6. 再把这个 Host 的公共隧道关闭，重新访问，确认客户端不会继续复用旧的隧道连接对象。

## 明确不覆盖什么

这份基线不替代下面这些验收：

1. 不替代“中继不可见业务明文”的抓包验收，那是 `5.2`。
2. 不替代支付、扣量、恢复，那是 `4.1` 到 `4.3`。
3. 不替代部署和运维文档，那是 `6.1` 以后。
