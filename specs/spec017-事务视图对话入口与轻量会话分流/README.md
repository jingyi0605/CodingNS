# spec017-事务视图对话入口与轻量会话分流

## 这份 Spec 现在解决什么问题

`spec016` 已经把事务视图的左中右骨架立起来了，也把文档库、待办、自动化和右侧助手面板接进来了。

但现在事务视图里的“对话”还不成体系，至少有两个明显问题：

1. 事务模式左侧没有正式的“对话”入口，用户只能在右侧助手面板里临时聊，或者切回代码模式的会话页。
2. 事务场景里其实有两种完全不同的会话模式，而且每种模式里都要能选 `Codex` 和 `Claude Code`：
   - **轻量会话**：像网页端一样，主要做快速问答、联网搜索、轻分析，不需要本地工具和完整 Agent 壳。
   - **Agent 会话**：围绕当前事务对象做更重的执行，直接复用现在的助手会话逻辑，也继续绑定当前工作区/文档库上下文。

一句人话：

现在事务模式里只有“右侧助手面板”这半套对话能力，还没有一块正式的对话主舞台，也没有把“会话模式”和“provider 选择”分开。

所以这份 Spec 只解决一件事：

**在事务模式里补一套正式对话入口和对话页面，并把轻量会话与 Agent 会话分流清楚。**

## 这次计划覆盖什么

- 事务模式左侧新增“对话”入口，位置固定在文档库下方
- 点击“对话”后，事务模式中间主区切到正式对话页面
- 对话页面样式和代码模式 `ConversationPage` 保持一致，不再另起一套 UI 语言
- 事务模式对话分成两种会话模式：轻量会话、Agent 会话
- 两种会话模式下都提供 `Codex` 和 `Claude Code` 选择
- 轻量会话的定位、边界和能力约束
- Agent 会话复用当前助手会话逻辑，并明确绑定当前事务文档库/工作区
- 事务模式对话列表、默认进入规则、空态和切换规则
- 事务模式与代码模式对话入口的边界，避免互相串线

## 这次明确不做什么

- 不在“工作区新增会话”入口里增加新的 CLI provider
- 不把轻量会话塞回代码模式左侧会话树
- 不在这份 Spec 里直接定义轻量会话底层 provider 的完整接入协议
- 不重写现有 `ConversationPage` 的通用消息 UI
- 不把事务模式右侧助手面板删除；它会保留，但职责要收口
- 不在这一轮把待办、自动化各自都做出独立对话页
- 不把“轻量 Codex / 轻量 Claude Code”做成代码模式 provider catalog 里的新 provider 项

## 为什么要单独起 spec017

因为这件事不是简单加一个按钮。

它至少同时涉及四层边界：

1. **事务模式左侧信息架构**：文档库下面要不要有正式对话入口。
2. **事务模式中间主舞台**：什么时候显示对象，什么时候显示对话。
3. **会话模式和 provider 模型**：轻量 / Agent 是一条轴，`Codex` / `Claude Code` 是另一条轴，不能混成一锅。
4. **现有助手逻辑复用**：Agent 会话要复用，但不能把轻量会话也拖进重链路。

如果不先把这几件事写清楚，后面很容易长出垃圾：

- 左侧随手再加一个按钮，但没有状态模型
- 中间主区既像对象页又像会话页，切换逻辑混乱
- 轻量会话最后又偷偷走了完整 CLI/Agent 链路，根本不轻
- `Codex` / `Claude Code` 只是 provider 名字，但 UI 和状态模型把它们错误当成“轻量/Agent 类型”
- Agent 会话复用现有 Butler 逻辑时，把代码模式和事务模式的上下文串了

## 硬边界先写死

### 边界 1：事务模式的轻量会话不是代码模式新 provider

- 轻量会话只在事务模式里可见
- 不能出现在代码模式“新建会话 / provider picker / 并行会话”入口里
- 不能把这件事做成“再给工作区加一个 CLI 提供商”

### 边界 2：事务模式对话页要复用现有对话 UI 语言

- 中间主区切到对话时，整体样式必须和代码模式 `ConversationPage` 一致
- 可以换数据来源和入口规则，但不能换产品语言
- 不允许为了事务模式再画一套聊天页

### 边界 3：会话模式和 provider 必须拆成两条轴

- `轻量 / Agent` 说的是能力模式
- `Codex / Claude Code` 说的是 provider
- 事务对话至少支持四种组合：
  - 轻量 + Codex
  - 轻量 + Claude Code
  - Agent + Codex
  - Agent + Claude Code
- 不能把 provider 名字直接当成会话模式，也不能把会话模式塞进 provider id

### 边界 4：Agent 会话复用现有助手会话逻辑

- Agent 会话不重造运行时
- 继续复用当前事务模式右侧助手/Butler 已经接通的会话逻辑
- `Codex` 和 `Claude Code` 在 Agent 模式下继续走现有完整助手链路，包括 AGENTS.md 注入和完整工具能力
- 但要把它提升成事务模式里的正式“对话主舞台”之一，而不是只缩在右侧面板里

### 边界 4.1：轻量会话也要能选 Codex 和 Claude Code

- 轻量模式不是“另一个 provider”
- 它只是事务模式里的另一种运行级别
- 所以轻量会话里同样可以选 `Codex` 或 `Claude Code`
- 但这两条轻量链路都不带完整本地工具和 AGENTS.md 特别注入

### 边界 5：事务模式里的 Agent 会话绑定当前文档库

- Agent 会话默认工作区就是当前事务文档库所属工作区
- 上下文默认围绕当前绑定文档库和当前选中事务对象
- 不能在事务模式里又引入“多工作区挑选器”这套代码模式逻辑
