# 需求文档 - spec017-事务视图对话入口与轻量会话分流

状态：Draft

## 简介

事务视图现在已经能围绕文档库、待办和自动化工作，但“对话”还只是右侧助手面板这半套能力。

这会直接带来四个问题：

1. 用户想在事务模式里认真聊一段时，没有正式对话主页面。
2. 用户只想快速问一句、搜一下资料，却会被现有重 Agent 逻辑拖进更重的会话壳。
3. 用户需要围绕当前事务文档做真正的 Agent 执行时，又只能挤在右侧辅助面板里，不像一条正式主链路。
4. 事务模式后面即使分成轻量和 Agent 两类，如果没有把“会话模式”和“provider 选择”拆开，最后还是会把模型和能力边界做乱。

所以这份 Spec 的目标很明确：

- 在事务模式左侧加一个正式“对话”入口
- 点进去后，中间主区切到正式对话页面
- 这套对话页面继续沿用代码模式现有聊天页样式
- 事务模式里的对话要同时回答两件事：
  - 这是 **轻量会话** 还是 **Agent 会话**
  - 这条会话用的是哪一组 **provider**，以及具体选了谁

其中：

- **轻量会话**：偏网页端风格，主要做快速问答、联网搜索和轻分析
- **Agent 会话**：直接复用当前助手会话逻辑，绑定当前事务文档库和当前对象上下文
- **轻量 provider 选择**：轻量会话下显示轻能力 provider，第一版先提供 `Codex`、`Claude Code` 的轻量会话入口
- **Agent provider 选择**：Agent 会话下显示完整 CLI provider，第一版继续复用 `Codex`、`Claude Code`

## 术语表

- **System**：`CodingNS`
- **事务对话入口**：事务模式左侧新增的“对话”导航项
- **事务对话页**：事务模式中间主区展示的正式聊天页面
- **轻量会话**：只有轻量能力的事务会话，默认不带本地工具和完整 Agent 执行壳
- **Agent 会话**：复用现有 Butler/助手会话逻辑的事务会话，绑定当前工作区和文档库上下文
- **会话模式**：当前对话属于轻量还是 Agent，决定能力边界
- **事务 provider 选择**：当前对话使用哪个 provider，决定底层接哪条链路
- **当前文档库绑定**：`spec016.1` 已定义的工作区文档库绑定
- **当前事务对象**：事务视图里当前选中的文档、标签、文件夹、待办或自动化对象

## 范围说明

### In Scope

- 事务模式左侧新增“对话”入口
- 事务模式中间主区的正式对话页面
- 轻量会话与 Agent 会话的类型区分和显示规则
- 轻量模式 LLM provider 与助手模式 CLI provider 的分组展示规则
- Agent 会话复用当前助手会话逻辑的方案
- Agent 会话与当前文档库/当前对象的默认绑定规则
- 事务对话列表、空态、切换和默认进入规则
- 事务模式右侧助手面板和事务对话页之间的职责收口

### Out of Scope

- 轻量会话底层 provider 的完整实现细节
- 新增代码模式 provider 或改代码模式会话入口
- 轻量会话支持本地文件、Shell、MCP、浏览器自动化等完整工具体系
- 待办、自动化各自独立对话模型的细分设计
- 全量重做现有 `ConversationPage` 通用组件

## 需求

### 需求 1：系统必须在事务模式左侧提供正式对话入口

**用户故事：** 作为使用者，我希望在事务模式左侧能直接看到“对话”入口，这样我不用切回代码模式才能进入正式聊天页。

#### 验收标准

1. WHEN 用户进入事务模式 THEN System SHALL 在左侧菜单中提供“对话”入口，并固定在文档库入口下方。
2. WHEN 用户点击“对话”入口 THEN System SHALL 让事务模式中间主区切换到正式对话页，而不是只展开右侧助手面板。
3. WHEN 用户再次回到文档库、待办或自动化入口 THEN System SHALL 正常切回对应对象主区，不与对话页状态混在一起。

### 需求 2：系统必须让事务对话页与代码模式聊天页保持同一套样式语言

**用户故事：** 作为使用者，我希望事务模式里的聊天页面看起来和代码模式聊天页一致，这样切换时不会像换了一个应用。

#### 验收标准

1. WHEN 事务模式中间主区展示对话页 THEN System SHALL 复用代码模式聊天页的主要结构、消息样式和输入区语言。
2. WHEN 用户在代码模式聊天页和事务模式对话页之间切换 THEN System SHALL 保持统一的标题栏、消息列表、输入区和状态提示风格。
3. WHEN 事务模式需要补充自己的上下文提示 THEN System SHALL 在不破坏现有聊天页主结构的前提下做事务语境扩展，而不是另起一套页面骨架。

### 需求 3：系统必须把事务模式对话正式分成轻量会话和 Agent 会话两种模式

**用户故事：** 作为使用者，我希望事务模式里的快速问答和重 Agent 执行被明确分开，这样我知道自己现在开的到底是哪种会话。

#### 验收标准

1. WHEN 用户在事务模式里创建或切换对话 THEN System SHALL 明确区分轻量会话和 Agent 会话两类。
2. WHEN 用户查看事务模式对话列表或当前对话头部信息 THEN System SHALL 明确显示当前会话类型，而不是只靠默认推断。
3. WHEN 事务模式进入对话页 THEN System SHALL 能根据当前会话类型加载对应能力边界和上下文。

### 需求 4：系统必须把轻量会话限制在事务模式内部，不得污染代码模式 provider 入口

**用户故事：** 作为维护者，我希望轻量会话只服务事务模式，而不是又跑到代码模式的新建会话入口里占一个 provider 位置。

#### 验收标准

1. WHEN 用户在代码模式创建会话 THEN System SHALL 不显示事务轻量会话作为新的 CLI provider。
2. WHEN 用户在事务模式使用轻量会话 THEN System SHALL 把它当作事务模式内部会话类型，而不是工作区全局 provider 新增项。
3. WHEN 后续扩展轻量会话能力 THEN System SHALL 继续保持它只在事务模式可见，除非另有明确 Spec 修改。

### 需求 4.1：系统必须让事务模式对话把“会话模式”和“provider 选择”拆开

**用户故事：** 作为使用者，我希望能先看明白当前是轻量还是 Agent，再看明白当前选的是哪一个 provider，而不是把两件事混成一个标签。

#### 验收标准

1. WHEN 用户在事务模式创建对话 THEN System SHALL 用统一新建弹窗分别让用户确认会话模式和 provider 选择。
2. WHEN 用户查看事务对话列表或会话头部 THEN System SHALL 同时展示会话模式与 provider 信息。
3. WHEN 系统存储事务对话元数据 THEN System SHALL 把会话模式字段和 provider 字段分开保存，而不是用一个混合枚举硬编码。

### 需求 5：系统必须让 Agent 会话复用当前助手会话逻辑

**用户故事：** 作为使用者，我希望事务模式里的 Agent 会话能直接继承现在已经可用的助手能力，而不是重造一套不稳定的新链路。

#### 验收标准

1. WHEN 用户在事务模式打开 Agent 会话 THEN System SHALL 复用当前助手/Butler 已接通的会话逻辑。
2. WHEN Agent 会话进入正式对话页 THEN System SHALL 允许它继续使用当前助手链路已有的消息、运行态和权限请求能力。
3. WHEN 右侧助手面板和 Agent 会话主页面都存在 THEN System SHALL 明确两者是同一条 Agent 会话链路的不同展示方式，而不是两套平行状态。
4. WHEN 用户在 Agent 会话里选择 `Codex` 或 `Claude Code` THEN System SHALL 继续走当前完整助手链路，包括现有 AGENTS.md 特别注入和完整工具能力边界。

### 需求 6：系统必须让 Agent 会话默认绑定当前文档库和当前事务对象

**用户故事：** 作为使用者，我希望在事务模式里开的 Agent 会话天然围绕当前文档库和当前对象工作，而不是还要重新选工作区。

#### 验收标准

1. WHEN 用户在事务模式打开 Agent 会话 THEN System SHALL 默认把会话工作区绑定到当前事务文档库所属工作区。
2. WHEN 当前已经选中文档、标签、文件夹、待办或自动化对象 THEN System SHALL 把这些对象上下文带进 Agent 会话初始化语境。
3. WHEN 当前没有选中事务对象 THEN System SHALL 至少带入当前文档库绑定和事务模式语境，而不是退回代码模式语境。
4. WHEN 用户位于事务模式对话页 THEN System SHALL 不提供代码模式那套多工作区切换语义。

### 需求 7：系统必须给轻量会话明确的轻能力边界

**用户故事：** 作为使用者，我希望轻量会话就是快速、轻的聊天，而不是名字轻，实际还是完整 Agent 壳。

#### 验收标准

1. WHEN 用户进入轻量会话 THEN System SHALL 把它定义为快速问答、联网搜索、轻分析优先的会话类型。
2. WHEN 轻量会话运行时 THEN System SHALL 默认不暴露本地工具、工作区写入、完整 Agent 权限流这些重能力。
3. WHEN 轻量会话无法满足当前任务复杂度 THEN System SHALL 提供清楚的切换或升级到 Agent 会话的路径。
4. WHEN 用户在轻量会话里选择轻量 provider THEN System SHALL 只切换轻量底层 provider，不得顺手打开完整助手链路和 AGENTS.md 注入。

### 需求 7.1：系统必须把轻量模式和助手模式的 provider 分组显示清楚

**用户故事：** 作为使用者，我希望一眼就看明白轻量模式和助手模式各自能选什么 provider，而不是打开创建入口后看到一堆混在一起的按钮。

#### 验收标准

1. WHEN 用户点击事务模式里的新建对话按钮 THEN System SHALL 打开统一创建弹窗，而不是在页面里平铺多个组合按钮。
2. WHEN 用户查看轻量模式分组 THEN System SHALL 只显示轻量 LLM provider。
3. WHEN 用户查看助手模式分组 THEN System SHALL 只显示完整 CLI provider。
4. WHEN 当前 provider 不可用或被禁用 THEN System SHALL 在事务模式里复用正式 provider 可见性规则，而不是显示一个点了也不能用的假入口。

### 需求 8：系统必须定义事务模式右侧助手面板与事务对话页的职责分工

**用户故事：** 作为使用者，我希望右侧助手面板和中间对话页各干各的，不要两个地方都能聊，但谁是主舞台说不清。

#### 验收标准

1. WHEN 用户只是围绕当前对象做几步辅助查看或快速补充 THEN System SHALL 允许继续使用右侧助手面板。
2. WHEN 用户需要进行完整连续对话 THEN System SHALL 提供事务对话页作为正式主舞台。
3. WHEN 当前展示的是 Agent 会话 THEN System SHALL 明确右侧助手面板与中间 Agent 对话页之间的状态关系，避免消息或运行态不同步。

### 需求 9：系统必须提供事务对话页的默认进入和空态规则

**用户故事：** 作为使用者，我希望第一次进入事务对话页时，系统能告诉我应该先开什么会话，而不是给我一块空白。

#### 验收标准

1. WHEN 用户第一次点击事务模式“对话”入口且还没有任何事务对话 THEN System SHALL 提供会话类型选择或默认建议入口。
2. WHEN 用户第一次进入事务对话页 THEN System SHALL 先让用户通过统一创建入口选清楚“轻量 / Agent”和对应 provider。
3. WHEN 当前工作区已经绑定文档库且存在明确事务对象 THEN System SHALL 优先提示围绕当前对象开启 Agent 会话。
4. WHEN 用户只是想快速问答或联网搜索 THEN System SHALL 提供轻量会话入口，并明确它是轻模式。
5. WHEN 当前既没有文档库绑定也没有事务对象 THEN System SHALL 给出清楚空态说明，而不是直接落到代码模式会话语境。

## 非功能需求

### 非功能需求 1：兼容性

1. WHEN 本 Spec 落地 THEN System SHALL 不破坏代码模式现有会话页和 provider picker 主链路。
2. WHEN 事务模式继续复用当前助手会话逻辑 THEN System SHALL 不破坏现有右侧助手面板已接通的能力。
3. WHEN 事务模式增加轻量 `Codex` / 轻量 `Claude Code` THEN System SHALL 不把它们注册成代码模式的新 provider 项。

### 非功能需求 2：可维护性

1. WHEN 后续继续细化轻量会话底层实现 THEN System SHALL 能在不重写事务模式对话页 UI 的前提下替换底层运行时。
2. WHEN 后续继续扩事务对象类型 THEN System SHALL 继续复用“当前文档库 + 当前对象 -> Agent 会话初始化上下文”这套模型。

### 非功能需求 3：体验一致性

1. WHEN 用户在代码模式聊天页和事务模式对话页之间切换 THEN System SHALL 保持同一套消息、输入区和状态反馈语言。
2. WHEN 用户从事务对象页切到事务对话页再切回来 THEN System SHALL 在可接受时间内恢复各自局部状态，不造成明显闪烁或上下文丢失。

## 成功定义

- 事务模式左侧正式出现“对话”入口，位置固定在文档库下方
- 点击对话后，中间主区能进入正式聊天页，而不是只靠右侧助手面板
- 事务模式对话明确把“轻量 / Agent”和“provider 选择”拆成两条轴
- 轻量模式和助手模式的 provider 分组显示清楚，不再把所有 provider 混在一起
- 轻量会话不出现在代码模式新建会话 provider 入口里
- Agent 会话复用当前助手会话逻辑，并默认绑定当前文档库和当前事务对象
