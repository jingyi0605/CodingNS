# spec010.3-KimiCLI兼容接入

## 当前定位

这个 Spec 负责把 `Kimi CLI` 接进现有 provider 体系，而且尽量按官方公开协议接，不走野路子。

它解决的不是“给前端再多一个 Kimi 选项”，而是：

- `Kimi CLI` 官方已经公开了哪些程序化能力、哪些本地数据结构
- Kimi 该走 `wire mode`、命令模式还是本地会话目录
- Kimi 的原生会话、历史、实时事件、运行中引导和模型配置怎么映射到现有系统
- 当前仓库里哪些硬编码和能力边界会挡住 Kimi 接入

## 计划覆盖

- Kimi 的会话发现、历史读取、实时运行和中断接入方式
- `wire mode`、命令模式、本地会话目录三条链路的主次关系
- Kimi 会话绑定、消息归一化、能力声明和运行中引导策略
- 当前仓库里阻碍新增 provider 的硬编码拆除范围
- Kimi 真实样本、fixture、回归和验收策略

## 依赖关系

- 前置依赖：`spec002`、`spec003`、`spec003.1`、`spec010`
- 强关联依赖：`spec010.1`
- 后续依赖：Kimi provider 实际实现、前端能力补齐、fixture 回归

## 本阶段明确不做

- 不在这个 Spec 里直接交付完整代码实现
- 不为了 Kimi 单独重做会话页面
- 不把 Kimi 所有高级能力一次性 UI 化
- 不把本地会话文件和运行时事件混成一套模糊真相
