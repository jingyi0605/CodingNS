# npm 服务包发布说明

这份文档只解决一件事：怎么把当前仓库里的统一服务包发布成真正可安装的 npm 包。

这次发布的正式包名是 `@jingyi0605/codingns`。

注意两件事：

- npm 安装名是 `@jingyi0605/codingns`
- 安装后的命令还是 `codingns`

## 1. 先认清发布对象

不要在仓库根目录执行 `npm publish`。

根目录只是 workspace 壳子，`private: true`，根本不是发布物。

真正要发布的是：

- `packages/codingns/package.json`

它会把下面两类产物打进同一个包：

- 前端 `apps/user-app` 的生产构建结果
- 后端 `apps/host` 的生产构建结果

## 2. 发布前准备

发布前至少确认下面几件事：

1. 已经登录 npm
2. `packages/codingns/package.json` 里的版本号已经改好
3. 当前 tag 计划和版本号一致
4. 本地依赖能正常安装

登录 npm：

```bash
npm login
```

检查包名和版本：

```bash
node -p "require('./packages/codingns/package.json').name"
node -p "require('./packages/codingns/package.json').version"
```

## 3. 本地手工发布

### 3.1 先做预演

仓库根目录执行：

```bash
pnpm publish:npm:dry-run
```

这一步会做三件事：

1. 执行 `build:standalone`
2. 执行 `npm pack --dry-run`
3. 执行 `npm publish --dry-run`

如果这一步都过不了，就别碰正式发布。

### 3.2 正式发布

仓库根目录执行：

```bash
pnpm publish:npm
```

脚本位置：

- `scripts/publish-npm-package.sh`

默认规则很直接：

- 正式版本，例如 `0.1.0`，自动发到 `latest`
- 预发布版本，例如 `0.1.0-beta.1`，自动发到 `beta`

如果你要手工指定 dist-tag，也可以直接跑：

```bash
bash scripts/publish-npm-package.sh --tag beta
```

## 4. 发布后的验证

最少做下面两步：

```bash
npx @jingyi0605/codingns start --port 3002
```

或者：

```bash
npm install -g @jingyi0605/codingns
codingns start --port 3002
```

确认：

1. 页面能打开
2. `/api/public/bootstrap-status` 能返回 JSON
3. 设置页里展示的服务包名是 `@jingyi0605/codingns`

## 5. GitHub Actions 自动发布

仓库里已经补了一条自动发布工作流：

- `.github/workflows/npm-publish.yml`

触发条件：

- 推送形如 `v0.1.0` 的 git tag

工作流会做这些事：

1. 安装依赖
2. 校验 tag 和 `packages/codingns/package.json` 的版本号一致
3. 构建统一服务包
4. 发布到 npm

### 5.1 需要配置的仓库 Secret

必须配置：

- `NPM_TOKEN`

这个 token 需要有发布 `@jingyi0605/codingns` 的权限。

### 5.2 推荐发布动作

先改版本号，再打 tag：

```bash
git tag v0.1.0
git push origin v0.1.0
```

如果版本号是 `0.1.0-beta.1`，就推：

```bash
git tag v0.1.0-beta.1
git push origin v0.1.0-beta.1
```

## 6. 最容易犯的错

### 6.1 把安装名和命令名混了

错的：

```bash
npm install -g codingns
```

对的：

```bash
npm install -g @jingyi0605/codingns
codingns start
```

### 6.2 版本没改就重复发布

npm 不允许同一个版本重复发布。版本不变，发布必炸。

### 6.3 tag 和包版本不一致

自动发布流程会直接拦下这种错误，不会替你猜。
