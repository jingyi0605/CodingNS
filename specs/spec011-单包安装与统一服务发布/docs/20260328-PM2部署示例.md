# PM2 部署示例

这份文档只解决一件事：怎么把第一版 `@jingyi0605/codingns` 服务包交给 `pm2` 托管。

不讲 Docker，不讲 systemd，不讲花里胡哨的运维平台。先把最基础、最常用的守护启动做明白。

## 1. 先准备什么

机器上至少要有：

- Node.js 22 或更高版本
- npm
- PM2

安装 PM2：

```bash
npm install -g pm2
```

## 2. 安装服务包

如果已经发布到 npm：

```bash
npm install -g @jingyi0605/codingns
```

如果当前只是本地验证 tarball：

```bash
npm install -g ./jingyi0605-codingns-0.1.0.tgz
```

## 3. 直接启动一遍确认没问题

先别急着上 PM2，先手工确认服务能跑：

```bash
codingns start --host 0.0.0.0 --port 3002 --data-dir ~/.codingns
```

确认下面两件事：

- 浏览器访问 `http://127.0.0.1:3002/` 能打开页面
- `http://127.0.0.1:3002/api/public/bootstrap-status` 能返回 JSON

## 4. 用 PM2 托管

最直接的方式：

```bash
pm2 start "$(which codingns)" --name codingns -- start --host 0.0.0.0 --port 3002 --data-dir ~/.codingns
```

这条命令的意思很简单：

- `$(which codingns)`：找到全局安装后的命令路径
- `--name codingns`：给进程起固定名字
- `--` 之后的内容：原样传给 `codingns`

## 5. 常用 PM2 命令

查看状态：

```bash
pm2 status
```

看日志：

```bash
pm2 logs codingns
```

重启：

```bash
pm2 restart codingns
```

停止：

```bash
pm2 stop codingns
```

删除：

```bash
pm2 delete codingns
```

## 6. 开机自启

保存当前 PM2 进程列表：

```bash
pm2 save
```

生成开机启动命令：

```bash
pm2 startup
```

PM2 会输出一条需要你复制执行的系统命令。把那条命令执行完，再跑一次：

```bash
pm2 save
```

这样机器重启后，`codingns` 会自动拉起来。

## 7. 推荐目录

第一版建议把数据目录单独放出来，不要写进安装目录。

例如：

```bash
codingns start --data-dir /var/lib/codingns
```

或者：

```bash
codingns start --data-dir ~/.codingns
```

数据目录里会放这些东西：

- `host.sqlite`
- `releases/`
- 运行时生成的其他本地数据

## 8. 常见问题

### 8.1 页面能打开，但接口报错

先检查是不是同一个服务地址。

第一版正确姿势是：

- 页面和 API 走同一个端口
- 不再单独跑 Vite 开发服务器

### 8.2 PM2 里进程不断重启

先看日志：

```bash
pm2 logs codingns
```

重点查三类问题：

- 端口被占用
- 数据目录没写权限
- Node.js 版本过低

### 8.3 命令存在，但浏览器打不开页面

先确认监听端口：

```bash
pm2 logs codingns
```

如果启动参数用了 `--host 127.0.0.1`，那它只监听本机回环地址。要给局域网或反向代理访问，应该用：

```bash
--host 0.0.0.0
```

## 9. 最小可用命令

如果只想照抄一个最小版本，就用这条：

```bash
npm install -g @jingyi0605/codingns && pm2 start "$(which codingns)" --name codingns -- start --host 0.0.0.0 --port 3002 --data-dir ~/.codingns
```
