# spec001.2.1-读写刷新与后台任务统一规则

## 当前定位

这是 `spec001.2` 下的新子 Spec。

它只解决一件事：

- 把整个仓库里“读、写、刷新、订阅、watcher、后台任务”这些容易互相拖累的动作，收成一套统一规则，避免现在这轮卡顿刚治完，后面新服务又把同样的坑长回来。

一句人话：
不是继续头痛医头、脚痛医脚，而是把“什么动作可以顺手做、什么动作绝对不能顺手做”写成标准。

## 计划覆盖

- 统一定义纯读、缓存读、请求内写、后台刷新、重扫描五类操作
- 统一约束 `get/list/read/snapshot` 这类读接口的副作用边界
- 统一约束 `refresh/schedule/ensure/invalidate` 这类刷新接口的命名和行为
- 统一约束 `TaskManager`、私有 `inflight`、私有 `timer`、私有 watcher 的使用边界
- 统一约束 Host 主线程、`host_background`、`helper_process`、`external_process` 的适用范围
- 统一约束文件树、Git、工作台、Butler、Provider、终端等链路的缓存、刷新和广播模式
- 给以后新增服务提供接入检查清单和验收口径

## 本阶段明确不做

- 不把所有现有模块一次性推倒重写
- 不引入新的常驻守护进程或分布式任务系统
- 不把所有局部 `Promise` 去重都强行塞进 `TaskManager`
- 不为了“绝对纯函数”牺牲必要的请求内小范围读写能力
- 不改现有接口返回结构，只约束实现方式和后续扩展方式
